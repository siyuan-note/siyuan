# 主题和图标同步

[English](APPEARANCE-SYNC.md)

对应需求：https://github.com/siyuan-note/siyuan/issues/18883

## 功能范围

第三方主题和图标以完整包为单位参与数据同步、快照、安装、更新和卸载。桌面主窗口、独立窗口和移动前端共用内核实现及资源 URL。旧客户端可以继续同步笔记，并将内部外观归档作为普通文件运输；外观包的安装、合并和还原由支持此功能的客户端完成。

明亮主题、暗黑主题、图标、模式及跟随系统等选择保存在各设备的 `conf/conf.json` 中，不随包安装而自动切换。内置 `daylight`、`midnight` 和 `litheness` 使用应用随附资源，不进入第三方包同步目录，同名数据目录不能覆盖内置资源。

`theme.json` 和 `icon.json` 不增加同步开关。主题仍遵守 `frontends`，缺省或空值不支持移动前端，`all` 表示所有前端；运行时同时检查 `minAppVersion`。普通文档和其他数据继续使用原有文件级同步规则。

## 用户交互

安装、更新或卸载包后，同步将完整版本或删除记录传播到其他设备。其他设备收到包不会改变其本机外观选择；当前使用的包被删除或与本机不兼容时，界面回退到内置外观。

用户可以在本机编辑包内 CSS、脚本、图片等文件。建立快照前扫描这些修改并更新完整性记录，正常运行及导出不自动重写摘要。未完成安装、同步恢复或旧版延期资源涉及的包暂不可用时，界面显示内置外观并保留本机原选择，恢复完成后刷新。

同版本号的内容更新也会刷新当前资源。主题脚本继续执行卸载生命周期；无法安全卸载时重新加载界面。忽略规则可以排除完整包，但不能通过只排除部分文件或单独排除安装状态来生成不完整包。

## 数据与存储

### 目录与安装状态

| 路径 | 用途 | 同步范围 |
|---|---|---|
| `data/themes/<name>/` | 本机第三方主题目录 | 从整包事件还原，不直接进入普通文件同步 |
| `data/icons/<name>/` | 本机第三方图标目录 | 从整包事件还原，不直接进入普通文件同步 |
| `data/storage/bazaar/themes/<name>.json` | 每个主题的安装状态 | 随整包事件还原，不单独同步 |
| `data/storage/bazaar/icons/<name>.json` | 每个图标包的安装状态 | 随整包事件还原，不单独同步 |
| `data/storage/appearance-v1/` | 不可变整包事件及格式标记 | 通过原有文件同步和快照保存 |
| `conf/conf.json` | 本机外观选择 | 不参与包同步 |

主题和图标不再更新单文件 `storage/bazaar.json`；旧文件只作为迁移安装时间及来源信息的后备，其他类型集市包仍使用原有机制。每个包的状态属于内核内部格式，不是集市作者清单：

```json
{
  "version": 1,
  "deleted": false,
  "migration": false,
  "installTime": 0,
  "updateTime": 0,
  "repoURL": "https://github.com/owner/package",
  "repoRef": "main",
  "files": {
    "theme.css": "64-character-lowercase-sha256"
  }
}
```

`files` 使用包内相对 POSIX 路径和明文文件的 SHA-256。文件集合遵守既有过滤约定，排除普通隐藏目录、点前缀文件和 `.tmp`，保留允许的 `.siyuan` 目录。未知版本、非法路径、大小写或 Unicode 等价名称冲突、缺文件和摘要不符必须返回错误并保留原数据。

删除状态保留安装来源信息，设置 `deleted: true` 和空 `files`。已同步的包文件被移除；残留空目录或保留的本机忽略文件不视为重新安装，也不阻断后续快照及同步。迁移生成 `migration: true`；明确安装、更新和本地手工修改形成正常状态。快照前先恢复未完成操作，再扫描本地修改，索引还须验证实际保存的分块，拒绝扫描期间变化产生的不一致包。

### 不可变整包事件

DejaVu 将完整包内容和状态保存到 `data/storage/appearance-v1/<kind>/<name>/<sha256>.sypkg`，其中 `<kind>` 为 `themes` 或 `icons`。归档使用 ZIP Store，包含 `appearance.json`、`state.json` 和 `files/`，条目顺序、时间及权限固定，文件名摘要覆盖全部归档字节。更新和删除均创建新事件，不覆盖既有路径；删除事件只包含元数据和删除状态，不包含包资源。

`appearance.json` 记录版本、包类型、包名及前驱事件：

```json
{
  "version": 1,
  "kind": "themes",
  "name": "example",
  "parents": []
}
```

`parents` 是排序且不重复的前驱摘要列表。前驱必须存在，事件图不能包含循环。`data/storage/appearance-v1/format.json` 的固定内容是 `{"version":1,"type":"siyuan-appearance-events"}` 加一个换行符，用于区分支持此功能的空快照与尚无此功能的旧快照。格式标记须单独认证，不能仅凭本地缓存中相同的旧文件标识认定权威来源的内容仍受支持。

归档沿用原有 `File.ID` 算法。不同内容具有不同路径，因此外观更新不依赖文件修改时间区分。原有路径和秒级修改时间可能使不同内容具有相同文件标识；云端锁只串行化同步过程，不能区分同步前已经生成的相同标识。不可变归档解决外观事件的标识问题，不改变普通文件、分块、传输、加密或快照认证格式。

## 实现与接口

### 合并规则

新客户端合并所有参与共享的已知事件，先按因果关系选择事件头，后代覆盖祖先。并发事件按下表选择完整版本，并创建以所有并发头为前驱的新事件，将选择结果持久化。

| 情况 | 处理 |
|---|---|
| 仅一端更改完整包 | 使用该端整包 |
| 两端同时更新 | 使用云端整包，保留另一端完整包的冲突历史；没有云端事件头可区分候选时按稳定摘要顺序选择 |
| 更新与删除并发 | 删除优先，保留被舍弃的完整包历史 |
| 晚迁移遇到已有云端删除记录 | 保留删除，不恢复旧安装 |
| 在已知删除状态上明确重装 | 建立新的本地安装事件并同步 |
| 旧快照没有本功能格式标记 | 保留现有外观，不将缺少记录视为卸载 |
| 新快照还原到早期包版本 | 建立新的恢复事件，保留当前已知事件和恢复材料 |
| 参与共享的归档、状态或内容校验失败 | 停止应用，保留源数据，不发布部分目录 |

应用前验证归档文件名摘要、包身份、前驱关系、路径、状态格式和全部内容摘要。主题和图标的图片、字体等资源必须与代码同时下载，即使普通资源使用按需下载也不延期。同步、仅上传和仅下载入口使用同一整包边界。

DejaVu 的 `EnableAppearanceSync` 选项启用整包处理，`AppearanceIgnoreLines` 提供移除合法受管隔离块后的用户规则，`BeforeAppearanceApply` 在普通文件还原后、外观目录发布前确保持久隔离规则存在。回调执行时不得持有外观锁。这些属于内部集成接口，不增加公开 HTTP 端点，也不改变公开配置字段。

### 运行时加载与导出

资源 URL 保持 `/appearance/themes/...` 和 `/appearance/icons/...`，由内核解析到内置资源或对应本机包目录。正常加载和导出检查状态格式及删除记录，不因用户手工编辑而重写完整性摘要。未完成事务和已经认证的恢复状态由专用检查处理，不得绕过认证加载不完整包。

导出复制整套主题和图标资源，包括脚本引用的附属文件。同步及快照恢复完成后，内核刷新本机可用列表、重新绑定主题文件监听器，并发送内部 `refreshAppearance` 通知。前端按变更包更新缓存修订号，保留公开的主题和图标版本字段；主窗口、独立窗口及移动前端采用相同协议。

### 缓存与并发

历史归档使用有界内存缓存，仅复用已经完整校验且源身份未变的事件元数据，完整内容按事件头载入。缓存键区分仓库源、文件内容、分块序列和加密密钥。Windows 使用文件身份、时间及文件 USN；支持的其他系统要求完整身份和已稳定的高精度变化时间。无法取得可靠变化信息时仍完整读取，格式标记始终单独认证，不使用该缓存。

缓存不得使保留修改时间的闭合文件改写、密文损坏或错误密钥绕过源验证。归档解码按声明长度分配资源缓冲区，并完成大小及 CRC 校验。多个包复用同一字体等内容时，单块读写互斥，避免并行发布与读取冲突。

快照变更预检查保持只读，不下载资源、修复引用或写入分块。

资源请求和包的安装、扫描、提交通过共享外观锁协调，避免读取替换过程中的半个包。Windows 目录替换可能短暂不可用；同步隔离规则回调在普通文件恢复后、外观目录发布前执行，此时不得持有外观锁。

## 兼容与恢复

### 已有数据与客户端

旧客户端继续按原协议同步笔记，并运输内部归档；不要求全部客户端升级。旧客户端不采用新的资源目录，也不执行整包安装、合并及还原。已有快照、按需下载状态和第一版恢复日志保持可读，旧状态中延期的外观资源在包应用前补齐。

笔记本加密、密钥、备份及历史数据的认证规则不变，不改变密钥信封、主盐、AAD 或密钥派生。不得通过重新生成主盐、丢弃密钥或明文回退处理未知版本、损坏或认证失败。失败必须保留源数据及恢复材料；暂存和派生缓存不能取代已认证的原始内容。

### 迁移与忽略规则

迁移先复制并校验旧外观目录中的第三方包，保留原目录；已有目标目录和已有状态优先。无可同步文件的未安装目录保持原样并跳过，不阻断其他包。完成标记 `conf/appearance-migration.json` 只存在本机，重复启动不再次导入已卸载的包。

开发包使用符号链接时，迁移保留到原包的链接关系；无同步状态的包根链接仅在本机使用，普通同步不跟随链接到外部目录。已有同步状态的包改成链接时，必须明确排除整个包，避免误判删除或重新安装。

首次生成本机外观目录前，在 `.siyuan/syncignore` 末尾持久化带显式版本的受管注释块：

```text
# siyuan-appearance-isolation:v1:begin
/themes/
/icons/
/storage/bazaar/themes/
/storage/bazaar/icons/
# siyuan-appearance-isolation:v1:end
```

旧引擎遵守这些规则，新客户端另以路径过滤器保护本机目录。必须保留用户原规则及字节；未知或损坏的受管块保留原件并报错。同步或快照恢复改回早期规则后，在下一次索引及外观还原前重新确保隔离规则存在。

本机 `.siyuan/.appearance-syncignore-clock-v1` 记录已预留的规则修改秒数，不参与快照和云同步。更新隔离规则前先持久预留，避免还原旧规则或时钟回退时复用本机已分配的文件标识；未知或损坏记录保留原件并报错。

判断用户忽略意图时仅去除完整合法的受管块，用户原有规则继续生效。`/themes/example/` 可排除整个包，`/themes/`、`/icons/` 或对应内部归档目录可排除更大范围。排除 `/storage/` 或 `/storage/appearance-v1/` 会停用内部外观协议。只排除部分文件或单独排除状态记录必须报错，不生成不完整包；整包替换仍须保留原有忽略文件并检查应用期间的本地变化。

被整体忽略的包不进入上传或本机应用。忽略范围内损坏、未知或缺失的归档负载不通过云端或局域网下载，也不解码，不因此阻断笔记同步；路径身份及格式标记的安全检查仍有效。云端恢复引用已经保留的公开事件和删除记录继续保留，尚未分享的私有忽略事件不得混入云端恢复引用。

### 中断恢复与快照还原

下载先完成校验及暂存，再在同一文件系统中备份旧目录、替换整个目录并发布状态。同步应用复用原有资源恢复日志；本机安装使用隐藏的 `data/.siyuan-appearance-ops` 日志，旧目录保留在 `data/.siyuan-appearance-backups` 中。同步替换的旧目录保留在历史目录，跨文件系统不能重命名时保留同卷备份。

启动、下一次操作及快照前可以继续未完成事务。日志记录源状态；恢复期间发现新的本地修改时，必须保留原文件、暂存及恢复材料并返回错误。暂不可用的包恢复完成后再刷新前端，不得通过直接删除状态文件绕过完整性校验。

还原支持本功能的快照时，以目标版本创建新的因果事件，而不是删除当前已知历史。还原无格式标记的旧快照时，缺少外观记录不能解释为卸载。还原前必须取得完整快照及所需内容，云端快照缺项不得静默丢弃包或普通工作区数据。单文件云端还原不得单独还原包内文件、安装状态或内部归档命名空间中的文件；这些内容必须通过完整快照及整包恢复流程应用。

### 恢复引用与限制

内部恢复标签 `.siyuan-appearance-v1` 引用包含事件集合的完整工作区快照，沿用云端普通标签机制保留恢复材料。必须先上传完整对象和快照，再发布恢复引用，最后发布最新引用。新客户端遇到旧客户端还原早期快照时，从恢复引用补回事件，防止丢失删除记录。

恢复引用不得指向只含外观的快照，避免旧客户端还原它时误删笔记。同名既有用户标签必须保留并报冲突，不能直接覆盖。新客户端仅对经过认证且具有本协议格式标记的内部标签隐藏显示、禁止手工覆盖或删除，并从用户备份数量中扣除；同名普通用户标签仍可见、可操作。

云端恢复引用合并目标工作区快照及此前已经公开的云端事件，不得从本机恢复引用复制尚未分享的私有事件。如果最新快照只缺少被排除的事件，且没有新事件需要发布，则保留原云端恢复引用并继续同步笔记。

旧客户端可能显示该标签，并按原规则占用一个备份名额；笔记同步不受此限制。内部恢复引用的更新不使用用户手动备份数量配额。内部事件保留已经分享的完整版本，存储占用随包更新次数增长；云端可复用未变化的分块，本机归档仍保存完整包，当前没有自动压缩事件历史的策略。普通历史清理不会删除恢复引用仍使用的事件。主动删除内部恢复标签及全部相关历史会丢失恢复材料，不能再保证恢复已删除事件。

恢复引用先于最新引用发布的保证以既有云锁正常串行为前提。现有锁采用先读后写，仍存在极端同时抢锁或失锁的风险；该功能不扩展服务端锁协议，不保证任意失锁及随后清理仍保留所有引用。

## 验证范围

### 回归覆盖

回归范围包含安装、迁移、手工修改、显式重装、未知版本保留、同秒并发更新及删除、完整冲突历史、整包与部分忽略、忽略范围内损坏负载和私有事件保护、完整与按需下载、单向同步、局域网认证及流量计数、中断恢复、快照回退、单文件还原限制、符号链接、同版本资源重载及默认回退。

内核检查 `bazaar`、`util`、`model`、`server` 的相关回归，DejaVu 检查外观、资源、快照、备份、认证、云锁及 `lansync` 测试。缓存回归覆盖保留修改时间的闭合文件改写、密文损坏、错误密钥、有界缓存及共享分块并发读写。前端在 `app/` 中运行相关单元测试及 `pnpm run lint`。

在 DejaVu 根目录运行历史基准：

```text
go test . -run ^$ -bench ^BenchmarkAppearanceHistory$ -benchtime=1x -count=1
```

基准使用十个 20 MiB 历史版本，测量无变化检查及快照的耗时和累计内存分配。常规测试不生成该大容量夹具，首次读取仍须完整认证，结果需结合文件系统及缓存状态解释。

端到端用例位于 `siyuan-testing`，需要运行包含此功能的新内核。静态检查和本地云适配器测试不能替代官方云、S3/WebDAV 及桌面和移动端的实机验收；升级、冷启动、运行时脚本卸载和跨端刷新需要在真实环境验证。开发验证不得通过构建前端产物、编译或重启正在使用的内核执行。

### 混版验证

在 DejaVu 根目录运行 `python scripts/test-appearance-compat.py`，覆盖完整下载／按需下载与双向同步／手动上传下载四种组合。独立旧版驱动固定已发布的 `v0.0.0-20260914113714-464364dd8fad`，禁止本地替换并通过 `go mod verify` 校验依赖；当前源码冻结到临时目录，报告保存版本、源码摘要、请求和响应。

每组包含旧端继续编辑笔记、接收安装和卸载事件、还原到无外观事件的早期快照、继续同步、清理本地及云端历史，再由全新客户端恢复删除记录并保留最新笔记。按需模式下普通资源仍可延期，外观归档必须完整下载。

固定旧 `cloud.Local` 在包含标签目录时，云端清理会将目录当成对象读取并失败。测试保留原始失败证据，清理兼容段仅通过测试适配器递归枚举全部 `refs/` 文件，补齐后端列举契约，不修改旧版同步、清理或认证源码。此测试验证旧引擎能沿普通标签保留恢复材料，不等同于真实云服务的端到端验收。

### 依赖发布

内核依赖 DejaVu 的整包事件、恢复状态及同步接口。发布时必须先发布包含相关实现的 DejaVu 版本，再更新 `kernel/go.mod`；只更新主仓库而继续使用旧依赖会缺少整包保护。本地开发可以临时 `replace` 指向 DejaVu 检出，但该替换不得提交。主仓库、依赖、主题和图标示例文档及端到端用例需要协调发布。
