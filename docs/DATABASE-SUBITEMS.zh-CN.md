# 数据库父子条目

[English](DATABASE-SUBITEMS.md)

关联问题：[#21038](https://github.com/siyuan-note/siyuan/issues/21038)、[#15706](https://github.com/siyuan-note/siyuan/issues/15706)

## 功能范围

本文说明 `v3.8.10` 分支数据库父子条目的行为、数据约束、接口兼容及验证范围。

父子条目用于在同一个数据库中组织多层结构。每个节点都是独立的数据库条目，拥有自己的字段值，支持绑定块和未绑定条目混合使用。一个条目最多有一个直接父项，可以有多个直接子项；没有父项的条目称为顶层条目。子树包含当前条目及其全部后代。

父子关系由数据库共享，所有视图和镜像使用同一份关系；每个表格或列表视图可以独立选择树形或平铺显示。数据库层级不改变文档目录、块树和列表块的原有结构。

| 视图 | 首版行为 |
|---|---|
| 表格 | 支持树形和平铺；树形支持展开、折叠及父子关系调整 |
| 列表 | 支持与表格相同的层级能力，使用列表布局 |
| 卡片 | 保持平铺，可通过条目属性查看和修改父子关系 |
| 看板 | 保持平铺，条目按自身字段值分组，可通过属性修改父子关系 |
| 日历 | 保持平铺，条目按自身日期显示，可通过属性修改父子关系 |

功能覆盖桌面端、浏览器端和移动端。移动端提供菜单操作，不以拖拽作为唯一入口。支持多层嵌套；深层结构通过迭代遍历、按需加载和响应大小控制处理。

任务依赖表示任务之间的先后或阻塞关系，不属于本次范围。本次也不增加自动排期、父子状态联动、日期继承或跨数据库父子关系。实现复用现有技术栈和本地数据机制，不新增外部服务、数据上传或付费依赖。

## 用户交互

### 启用与显示

在「数据库设置 - 父子条目」中启用功能，自动创建「父项」和「子项」两个自关联字段；也可以选择已有的自关联字段。已有字段必须先通过单父项、关联目标、循环和双向一致性校验。校验失败时显示问题条目并保留原数据，不自动挑选父项或删除关系。

自动创建的两个字段默认不占据表格列，可在属性设置中显示，并在条目属性面板中查看和修改。字段身份使用 ID，重命名不改变其用途。功能启用期间，不允许删除指定字段、改变字段类型或将其关联目标改为其他数据库；更换指定字段必须整体校验后提交。

从表格或列表启用功能时，当前视图切换为树形，其他视图保持原来的显示方式。新建视图默认平铺，复制视图保留原显示方式。「视图设置 - 树形显示」只控制当前视图，不修改父子关系。

停用数据库的父子功能时，所有视图恢复平铺，关联字段及其值继续保留。再次启用必须重新校验现有关系；停用不等于删除字段或降低数据格式版本。

### 创建与移动

表格和列表在主字段前显示缩进和展开按钮。条目菜单提供「新增子项」「更改父项」「提升一级」。父项选择器排除当前条目及其后代，并支持清空父项以移到顶层。

| 操作 | 结果 |
|---|---|
| 新增子项 | 新建普通条目并设置当前条目为父项 |
| 更改父项 | 整棵子树跟随移动，内部父子关系保持不变 |
| 提升一级 | 当前条目成为原父项的同级；原父项为顶层时，当前条目成为顶层 |
| 拖到条目内部 | 成为目标条目的子项，拖拽提示明确显示目标父项 |
| 拖到同级条目之间 | 调整同级顺序，插入线明确表示目标位置 |
| 清空父项 | 当前条目成为顶层，后代继续保留在其下面 |

新增子项的普通字段沿用现有模板、筛选和分组默认值，明确选择的父项优先于默认值。改父项、提升一级和移动子树不自动改写状态、日期等普通字段。新增或移动后不符合当前筛选时，提示条目已保存但不在当前结果中，不为保持可见而改写字段。

自动排序开启时，同级顺序由排序规则决定，禁止用拖拽调整手动顺序；仍可更改父项，并按目标同级的规则确定位置。操作不得仅凭屏幕行号推断目标父项。

选择父项不会隐式选中后代。移动和复制按子树操作，批量选择中已经被选中祖先覆盖的后代只处理一次；删除只处理明确选中的条目。

树形视图的多行粘贴按当前页可见条目的顺序写入，包括作为上下文显示的祖先。超出当前可见范围的行沿用新增顶层条目的行为，不覆盖折叠条目或其他页的条目。

### 筛选与搜索

树形视图先判断每个条目是否符合筛选，再补齐命中条目的祖先路径。仅作为路径补齐的祖先使用弱化样式及上下文标记，不能让用户误认为这些条目也符合筛选。

| 情况 | 展示结果 |
|---|---|
| 子项命中、父项不命中 | 显示子项及完整祖先路径 |
| 同级其他子项不命中 | 隐藏这些子项 |
| 父项命中、子项不命中 | 显示父项，不额外带出未命中的子项 |
| 没有条目命中 | 显示空结果，不保留无命中后代的上下文条目 |

搜索采用相同的路径补齐规则，并临时展开命中路径。清空搜索后恢复原展开状态。筛选变化不改写父子关系，也不把被筛除的子项移到顶层。上下文条目的编辑继续遵守原有权限；补齐路径、返回计数和定位均不得扩大数据可见范围。

### 分组与排序

树形视图中，整棵树跟随顶层父项的分组值。子项保留自己的字段值，不因显示在父项所在分组而被修改。例如父项状态为「进行中」、子项状态为「已完成」时，子项显示在父项下面，但其状态仍为「已完成」。平铺视图继续按每个条目自身的字段值分组。

多选或关联字段使顶层父项出现在多个分组时，各组可以显示同一棵树；这些展示实例对应同一份条目数据。选择和批量操作按条目 ID 去重。分组内计数按条目去重，数据库总数不能通过相加各组数量得出。

跨组移动顶层条目时，沿用现有分组字段修改规则，整棵树跟随新的分组位置，子项字段不变。子项不得仅通过拖到另一分组的空白区域获得不明确的父项；需要明确选择目标父项，或先提升到顶层再调整分组。只读计算字段的分组继续遵守现有修改限制。

排序只在同一父项的直接子项之间生效，顶层条目作为同一组兄弟排序。排序值相同时保持稳定顺序，不把子项拆离父项。不同视图保留各自的手动顺序。

### 删除、复制与撤销

删除父项后，其未删除的直接子项提升一级；删除顶层父项后，直接子项成为顶层。批量删除多个层级时，未删除的条目接到最近的未删除祖先下面；不存在这样的祖先时成为顶层。保留各子树内部关系和同级相对顺序，提升的条目占据被删除父项原来的位置。

从数据库移除条目不会因此删除其绑定文档或块。绑定源删除后的条目处理继续遵守现有绑定规则；如果该处理实际移除了数据库条目，同样执行子项提升，不能留下指向不存在条目的父项关联。

启用父子功能的数据库默认复制整棵子树，包括折叠或被筛选隐藏的后代。所有副本获得新的条目 ID，内部父子关系映射到新 ID；副本根节点保留原条目的外部父项，并作为原条目的同级副本。普通字段和普通关联继续遵守现有复制规则。

条目复制沿用现有未绑定副本语义：复制绑定条目时，副本为未绑定条目，不复制绑定文档或块的正文。层级专用字段必须单独重建，不得直接复制「子项」字段而把原有子项改挂到副本下面。

新增、移动、更改父项、删除和复制必须支持完整撤销与重做，包括父子关系、反向关联、视图顺序及受影响的配置。撤销不得覆盖操作后发生的无关编辑；发生冲突时保留现状并返回可识别的错误。

### 统计、分页与定位

筛选统计只计算实际命中的条目，不计算为路径补齐的祖先。父项和子项都是独立条目，不自动将子项数值累加到父项。展开与折叠不改变统计结果；分组统计使用树形视图的归组规则。

树形分页以顶层条目为单位，分组视图在各组内分页。界面区分顶层条目数量和匹配条目数量，不沿用平铺的行数来解释树形页数。展开节点时加载其直接子项，子项较多时提供前后翻页控件，在有界窗口内显示当前页。定位可以直接跳到目标子项所在页，不要求累计返回之前的所有子项；不能因响应大小限制使后续子项无法访问。

定位深层条目时，找到对应分组和顶层分页，展开祖先并加载目标所在的子项分页。目标不符合当前筛选时返回明确状态，不静默修改筛选；目标作为命中后代的祖先已经出现在结果中时，可以正常定位。多分组中的目标优先使用明确指定的分组，否则采用稳定的视图顺序。

## 数据与存储

### 关系模型

父子关系复用 `Relation` 和关联值中的条目 ID，不新增独立的父项值副本。父项字段最多保存一个条目 ID，子项字段作为同步维护的反向关联。条目 ID 与绑定块 ID 必须区分：同一个块的绑定行为不能决定其在数据库中的父子身份。

| 配置或数据 | 归属与规则 |
|---|---|
| 父子功能配置 | 数据库级，记录启用状态及父项、子项字段 ID；一个数据库使用一套层级定义 |
| 父项关联值 | 条目级，作为层级判断依据；空值表示顶层 |
| 子项关联值 | 父项关联的反向表示，与父项变更一并维护 |
| 树形显示方式 | 视图级，只对表格和列表生效；缺省为平铺 |
| 同级手动顺序 | 未分组时复用视图条目顺序；分组分别保留树形手动顺序和平铺成员顺序，在同一父项范围内解释 |
| 层级索引 | 从已认证源派生的父项、子项及祖先索引，可重建，不作为另一份权威源 |

普通自关联字段不增加单父项或无环约束。只有启用并指定为层级的字段接受这些约束。通过「子项」字段添加或移除关联也必须转换为对应的父项变更；将已有子项加入另一父项时，同时清理旧父项的反向关联。

### 持久化与本地状态

层级配置、关联值和视图显示方式保存在现有属性视图数据中，随数据库同步。普通数据库继续使用 `data/storage/av/<avID>.json`；加密数据库使用所属笔记本内现有的认证加密存储，不把配置或关系复制到普通数据库存储或全局明文索引。

普通数据库的展开状态是按数据库、视图、分组展示实例及条目 ID 组织的本地映射，存入 `data/storage/local.json`，通过 `window.siyuan.storage` 和 `setStorageVal` 维护，不使用浏览器 `localStorage`。搜索临时展开状态独立保存，不能覆盖用户的常规展开状态。加密数据库的展开状态保留在当前解锁会话内，锁定或关闭笔记本时清除，不将其父子结构写入普通本地状态。

关系改变后，各视图重新解释自己的条目顺序；用户指定的插入位置作用于操作所在视图及分组，其他视图和分组维持稳定顺序。分组的树形手动顺序单独保存，避免子项自身的分组值清理其在父项所在分组中的位置；该顺序不改变父子关系或平铺分组成员。旧数据未保存树形分组顺序时，按已有分组及视图顺序解释。修改层级不能重置无关分组顺序、字段值或视图设置。

## 实现与接口

### 模块职责

| 模块 | 实现范围 |
|---|---|
| `kernel/av` | 父子配置、格式版本、关系校验、层级索引和渲染数据结构 |
| `kernel/model/attribute_view.go` 及相关事务模块 | 关联写入、子树复制、删除提升、反向关系维护和撤销重做 |
| `kernel/model/attribute_view_render.go` 及排序、分组、定位模块 | 树形筛选、分组、同级排序、统计、分页及目标定位 |
| `kernel/apicontract` 与对应 API 处理器 | 类型契约、输入兼容、授权及响应语义 |
| `app/src/protyle/render/av` 与移动端相关入口 | 表格和列表渲染、菜单、拖拽、属性编辑、选择、焦点和刷新 |

现有平铺渲染按筛选、排序、统计和分页处理条目；树形显示需要独立的层级处理路径，不能仅在前端为平铺行增加缩进。继续复用现有表格、列表、关联、菜单和属性面板组件。

### 校验与事务

所有写入入口共用内核校验，包括关联单元格、属性面板、拖拽、批量粘贴、模板、API 和自动化。校验当前数据库内的条目存在性、单父项、自关联、循环及反向一致性，并以整个批次的最终结构为准，不能因合法批次的中间状态拒绝操作。

提交使用最新源状态重新验证，复用现有事务和快照恢复机制。一次结构变更同时维护父项值、子项反向值、受影响的视图顺序和缓存；失败不能作为完整成功返回，也不能留下半完成的父子关系。包含其他数据库的普通双向关联仍遵守原有事务和加密边界。

复制先确定去重后的源子树并分配全部新 ID，再复制普通字段和重建内部关系。响应不明时先核对已经生成的条目，不能自动重复复制。撤销和重做由内核记录足够的源状态，不接受客户端伪造的恢复快照。

层级专用字段不绕过已有自动化写入约束，也不新增父子完成状态或日期传播规则。操作后统一刷新相关视图，避免反向关联更新造成重复的结构操作。

### 渲染与缓存

树形读取按以下顺序处理：

1. 验证数据库访问范围、只读状态及加密读取租约，读取对应版本的源数据
2. 根据完整的条目身份和父项关联建立层级索引，再计算筛选与搜索的命中集合
3. 在授权范围内补齐祖先，区分实际命中和上下文条目
4. 按顶层父项归组，在各级兄弟之间应用排序规则，计算匹配数量和统计值
5. 按顶层条目及展开节点的直接子项分页，只生成本次需要返回的行内容
6. 返回层级元数据和定位信息，前端复用现有单元格渲染及条件颜色机制

层级遍历采用迭代和访问标记，避免深层结构导致栈溢出，或循环导致无限展开。结构索引构建应随条目数线性增长，不能对每一行重复扫描全库寻找后代。字段筛选仍可读取必要的数据，但不得先渲染整棵树的所有行内容再截取页面。

前端沿用表格和列表的虚拟滚动窗口，展开后的可见行数与根分页大小分别处理。根和直接子项分页限制每一级的读取宽度；完整展开深层路径或大量子树时，响应及服务端内存仍随实际返回条目数增长。虚拟滚动限制的是挂载行数，不能据此假定服务端开销固定。现有分组布局保留各组标题及每个非空展开组的首行，因此挂载总量也受分组数量影响，不能将行窗口预算解释为所有分组的固定 DOM 上限。分组展示复用一次批量生成的条目内容，重复展示的条目不重复求值模板。

缓存必须包含源版本和影响层级结果的配置，关系、筛选、排序、分组和字段变化都触发正确失效。展开响应到达时校验视图及请求版本，丢弃已经过期的结果。普通实时数据库、加密数据库、历史和快照不得混用源缓存；笔记本锁定后不能继续利用缓存返回受保护数据。

### 接口与声明

树形读取显式声明所需的层级能力，返回父项身份、深度、子项数量、上下文标记及分页信息。旧调用未声明层级能力时保留平铺返回和原有数量语义，不因视图被切换成树形而改变旧调用的结果形状。新的树形计数与旧的行数含义分开定义。

新增或扩展契约覆盖启用配置、批量调整父项、子树复制、子项读取及路径定位，保持数据库、条目、视图和操作上下文的身份明确。旧单条复制调用继续保持单条语义；启用父子功能后的界面复制使用明确的子树操作。写入和读取均保留现有鉴权、可写检查和加密笔记本租约。

契约以 `kernel/apicontract/` 为来源，使用 `contractHandler` 绑定并生成前端声明、模式及 Petal 声明，不手改生成文件。接口默认值、边界及兼容语义写在契约和对应维护声明中。具体维护和生成规则见 [内核接口类型契约](API-CONTRACTS.zh-CN.md)。

### 实施顺序

1. 完成数据模型、统一校验、关系事务、删除提升、子树复制及相应内核回归测试
2. 完成树形渲染、分组排序、统计分页、定位和缓存，维护契约及兼容性测试
3. 完成表格、列表及移动端入口，覆盖拖拽、选择、焦点、属性面板和刷新交互
4. 完成旧数据、加密、历史恢复、导入导出及规模验证，同步全部界面语言和四种语言的用户指南

每一步的测试和夹具随实现同步维护。数据、交互和兼容性验收共同构成首版交付条件，不能以缩进显示或静态检查通过代替完整功能验收。

## 兼容与恢复

### 格式与停用

父子功能使用数据库格式版本 `Spec 14`。只有实际启用该功能的数据库升级格式，未启用的数据库不因打开或读取而升级。不支持新格式的旧内核必须拒绝改写，避免丢失层级配置或绕过约束。

启用前保存可恢复的原始状态，校验完成后再提交配置及格式变化。中断、写入失败或不支持的源格式必须保留原数据，不能以清空关联完成升级。关闭树形显示或停用功能不自动降级格式；恢复到旧版本使用匹配的备份或历史源，不依赖旧内核忽略新增字段。

读取到循环、多个父项或缺失目标时返回可识别的结构错误，不静默挑选父项、删除关系或覆盖源。修复需要基于已认证的源明确处理，派生索引只能在源有效后重建。

### 复制、导入与导出

数据库整体复制和原生导入必须重映射数据库、字段和条目 ID，同时维护父子配置及反向关系。模板中可静态确定的字段 ID 引用随映射更新；动态计算或调用上下文不确定的表达式保留原文，不对普通文字进行全局替换。原生导出、备份和同步完整保留层级。平面导出沿用现有字段导出语义，不能仅凭显示缩进承诺可以恢复层级。

首版不新增跨数据库树迁移能力。既有跨库条目操作仍需检查目标数据库的字段语义，不能把来源父项 ID 写成目标库的父子关联，不能自动启用目标数据库的父子功能。涉及结构无法保留时，在提交前明确说明或返回错误，不能静默改变来源关系。

### 历史、加密与失败恢复

历史和快照使用对应版本的配置、条目及关系，不从当前数据库补齐过去的父子结构。回滚同时恢复数据和层级配置，并使相关派生索引失效。

已有加密数据是兼容基线，升级必须保留支持格式的认证读取和恢复能力。父子功能不修改密钥、加密封装、AAD 或密钥派生，不重新生成 MasterSalt，不要求删除或重建笔记本。普通与加密笔记本、不同加密笔记本之间继续遵守原有隔离边界。

迁移必须先认证源数据，保留历史、备份和必要恢复材料，并在失败或中断后可恢复。未知格式、损坏及认证失败必须保留原始数据并返回错误，不回退到明文读取。加密层级、祖先信息、计数和错误内容均不得通过明文缓存、全局索引或未授权响应泄露。兼容政策见 [加密笔记本](ENCRYPTED-NOTEBOOK.zh-CN.md)。

## 验证范围

| 场景 | 验收要求 |
|---|---|
| 数据约束 | 覆盖顶层、多层、单父项、自引用、循环、缺失目标、已有字段转换及停用后重新启用 |
| 写入入口 | 关联单元格、子项反向编辑、属性面板、拖拽、批量粘贴、模板、API 和自动化遵守相同约束 |
| 显示与筛选 | 表格和列表行为一致；覆盖祖先补齐、不匹配兄弟隐藏、空结果、搜索展开恢复及其他视图平铺 |
| 分组与排序 | 覆盖整树归组、多分组展示去重、计算字段限制、同级排序、手动顺序和跨组操作 |
| 统计与分页 | 折叠不改变统计；上下文不计入匹配数；根分页、子项分页及深层定位无重复或遗漏 |
| 结构操作 | 覆盖混合绑定、删除中间节点、批量删除、隐藏后代复制、选择重叠去重及完整撤销重做 |
| 并发与失败 | 覆盖过期视图、并发改父项、复制响应不明、写入失败、撤销冲突及事务恢复 |
| 接口兼容 | 覆盖旧请求缺省值、旧平铺响应、单条复制语义、新契约、鉴权、只读及租约检查 |
| 持久化与恢复 | 覆盖重启、镜像刷新、同步、整体复制、原生导入导出、历史和备份恢复 |
| 加密边界 | 使用支持的历史格式夹具验证认证读取、解锁和锁定、缓存清理、导出及恢复，错误时原始密文保持不变 |
| 平台与界面 | 覆盖桌面、浏览器和移动端的菜单、展开、编辑、选择、焦点、窄屏、主题及大字体 |
| 规模 | 使用万级条目、宽子树和深层链检查响应大小、加载耗时、内存、计数及遍历完整性，记录环境后比较性能 |

内核测试覆盖 `kernel/av`、相关 `kernel/model` 事务与渲染，以及 API 实际响应、输入兼容和路由覆盖；契约执行 `go test ./apicontract/...`。需要数据库及加密能力的测试使用维护指南要求的 `fts5 sqlcipher` 构建标签和隔离工作区，不替换产品二进制或重启运行中的内核。

前端实现后执行 `pnpm run lint`，审查自动修正的差异，并运行相关行为测试。该功能涉及共享渲染、关系、排序及交互模块，交付前还需运行 `pnpm test` 的完整测试范围。测试入口以目标分支的 `app/scripts/test.mjs` 为准，不能假定其他分支的测试筛选脚本已经存在。浏览器交互验证使用 `/stage/build/desktop/`。

契约变化后按维护指南执行生成与检查，并先核对 Petal 仓库的路径、分支和已有修改。界面文案同步所有语言并执行 `python scripts/check-lang-keys.py`；用户指南同步英文、简体中文、繁体中文和日文。新增测试必须被现有测试发现机制覆盖，测试与实现共同维护。
