# 文档标题与寻址

[English](DOCUMENT-ADDRESSING.md)

关联问题：[Improve hPath by separating display text from document addressing](https://github.com/siyuan-note/siyuan/issues/19938)

本文为实施设计草案，规定文档标题、层级定位、可读路径、接口及迁移的目标行为。下文新增的字段、接口和版本机制均为拟实现契约，不表示当前版本已经支持。当前重命名与路径索引的更新机制见 [文档重命名与路径索引](DOCUMENT-HPATH.md)。

## 目标与范围

文档使用 ID 确定身份和所属层级，标题用于表达内容，可读路径用于展示。创建、移动和引用不得依赖从展示文本反向解析文档身份。完成相关入口迁移与兼容验证后，文档标题可以包含半角斜杠 `/`，并与原有全角斜杠 `／` 保持区别。

未来文档标题支持行级元素是本方案必须保留的扩展能力。寻址、标题显示、纯文本提取和存储表示必须分离，不能将标题永久限定为一个供所有模块直接解释的纯文本字符串。本次不定义完整的富文本标题格式、编辑器交互或元素支持清单。

方案覆盖桌面端、浏览器端、移动端、内核接口和插件可见数据，并遵守普通笔记本与加密笔记本各自的访问边界。笔记本名称作为独立显示字段参与路径展示；笔记本名称的字符限制与富文本支持需要单独评估配置格式和旧客户端兼容，不能由文档标题规则自动推导。

### 方案决策

| 项目 | 采用的方案 |
| --- | --- |
| 文档定位 | 笔记本 ID 与文档 ID；创建使用独立的父文档身份与标题 |
| 新旧模式 | 按笔记本显式启用结构化标题模式；已有笔记本默认保持兼容模式 |
| 插件兼容 | 接受依赖旧 `hPath` 规则的插件适配；先交付替代接口及迁移说明，再启用新字符 |
| 旧字符串寻址 | 兼容模式保留原有行为；结构化标题模式明确拒绝旧字符串定位与创建入口 |
| 可读路径 | 保留标题原文并按层级拼接展示；不编码 `/`，不把 `／` 或 `%2F` 解码 |
| 索引 | 保留现有 `hpath` 列，新增文档级内部元数据；不为每个内容块保存完整标题段数组 |
| 标题源 | 首版继续使用普通标题；预留带版本的行级内容及单向纯文本派生 |
| 发布顺序 | 兼容保护和结构化能力先发布，完成迁移验证后开放 `/`，富文本标题单独实现 |

兼容边界按笔记本划定，避免根据某次请求猜测调用者的标题意图。例如 `/A/B` 可以指两级文档，也可能是单个标题的展示结果，旧请求没有足够信息区分两者。结构化标题模式启用后，该笔记本内即使某篇文档仍使用普通标题，旧字符串寻址入口也会返回明确错误；按 ID 操作和普通文字展示继续可用。这是插件需要适配的明确范围，不承诺所有旧插件零修改运行。

基础解耦不需要新增第三方服务、网络传输或依赖。实现继续遵守仓库及现有依赖的授权要求；若后续选择新依赖，应另行核查其许可。主要成本是调用方迁移、索引重建和跨版本验证。标题及祖先链的缓存、日志和错误响应继续受加密笔记本边界约束，不能因增加结构化字段扩大数据可见范围。

## 标题、身份与路径

### 当前数据来源

当前文档标题保存在文档根节点的 IAL `title` 中，`.sy` 文件及目录使用 ID 命名。`tree.HPath`、`blocks.hpath` 和 `blocktrees.hpath` 由文档及其祖先标题派生。标题写入仍经过 `normalizeDocTitle`，其中会移除半角斜杠；只修改界面输入限制不足以支持该字符。

当前部分逻辑将 `hPath` 用于按名称定位、创建文档、计算层级或提取标题。这些用途需要逐项迁移，不能仅将 `hPath` 改名为显示字段。可逆编码可以解决特定字符串协议中的分隔符歧义，但仍需要格式版本与兼容规则；本方案通过分离职责减少内部对该协议的依赖。

### 目标模型

下表中的名称表示概念，不直接规定新增接口字段或存储字段的名称。

| 概念 | 内容与用途 | 约束 |
| --- | --- | --- |
| 文档身份 | 笔记本 ID 与文档 ID | 按实际归属校验访问范围；不能用标题替代 |
| 父文档身份 | 目标笔记本及父文档 ID，或显式笔记本根位置 | 创建和移动时校验父文档仍存在且属于目标笔记本 |
| ID 数据路径 | ID 组成的目录路径与 `.sy` 文件名 | 用于存储及子树查询；移动后可能变化，不能作为永久身份 |
| 标题源内容 | 当前为 IAL `title`，未来可扩展为带版本的行级内容 | 每种格式必须有明确的权威来源及读取规则 |
| 纯文本标题 | 从标题源内容提取的普通文本 | 用于文本搜索、排序及兼容输出，不含 HTML 或搜索高亮标记 |
| 结构化祖先链 | 按层级排列的文档 ID 及对应标题信息 | 保留段边界，笔记本名称单独保存，不从展示字符串恢复 |
| 标题段数组 | 从明确位置开始逐级匹配或创建文档的输入 | 只消除分隔符歧义，不保证名称唯一 |
| 可读路径 | 面包屑、提示或复制路径所需的展示内容 | 可以使用不同展示形式，不承担文档寻址或源数据恢复 |
| 旧路径协议 | 现有接口及插件使用的 `hPath`、`hpath` 等字段 | 兼容模式维持原有行为；结构化标题模式采用后文明确的显示及拒绝规则 |
| 导出相对路径 | 导出任务为文档分配的文件位置 | 由导出映射确定，与标题及界面可读路径分开 |

当前前端搜索配置的 `idPath` 是多个搜索范围字符串组成的数组，其中每项可以包含笔记本 ID 和文档 ID 路径；它不是单条路径的逐级 ID 数组。迁移时必须保持现有配置的解释方式。块树中的 `parent_id` 表示块节点的父节点，也不能直接当作文档的父文档 ID 使用。

下面两种结构可以显示为相同的 `/A/B`，但必须保留不同的文档身份和祖先链：

| 标题段 | 文档结构 |
| --- | --- |
| `["A/B"]` | 根目录下一个标题为 `A/B` 的文档 |
| `["A", "B"]` | 标题为 `A` 的文档及其标题为 `B` 的子文档 |

面包屑应使用结构化层级呈现边界。复制出的纯文本路径只用于阅读；用于定位的链接和引用必须携带 ID。同一父文档下的同名文档允许存在，不能因为标题段相同而合并身份。

### 标题读取与文档元数据

内核建立统一的标题读取边界，输出 `format`、`text`、`empty` 和源内容版本。首版只支持 `format: "plain"`，从 IAL `title` 及既有 `custom-sy-title-empty` 属性读取；该属性与标题中的实际文字必须分别保留。旧文档的占位标题不批量重写，空标题的界面提示不作为新的名称匹配依据。未来富文本来源通过同一边界提供纯文本，不要求修改寻址调用方。

在普通 `blocktree.db` 及各加密笔记本对应的块树数据库中新增内部表 `document_metadata`，每篇文档一行。现有 `blocktrees` 列顺序保持不变，避免改变已有扫描和插件查询的列布局。

| 字段 | 含义 |
| --- | --- |
| `box_id`、`id` | 联合主键，分别为笔记本 ID 和文档 ID |
| `parent_id` | 父文档 ID；逻辑根位置为 SQL `NULL`，区别于块树节点的 `parent_id` |
| `title_text`、`title_empty` | 由源标题提取的文字及空标题标志 |
| `title_format`、`source_spec` | 标题表示及源文档版本 |
| `revision` | 身份、位置、标题源内容和空标题状态的版本摘要 |

建立 `(box_id, parent_id, title_text, id)` 索引，用于当前父文档下的精确名称查询。名称匹配使用原始 Unicode 文本的区分大小写比较，不做宽窄字符、百分号编码或 Unicode 归一化转换；搜索可继续采用自己的分词和大小写规则。空标题不能作为未知父文档的自动匹配条件，必须指定父 ID。

`document_metadata` 是可重建的内部索引，不新增公开 SQL 表承诺。定位使用块树数据库中的当前元数据，插件可通过结构化读取接口取得父 ID、标题和深度。现有内容库文档行的 `content` 继续保存标题的纯文本表示，`hpath` 继续作为可读路径副本。

文档元数据与块树文档行在同一数据库事务中更新。新增、重命名、移动、删除、复制、导入和同步重建都必须更新或清理对应行。标题缓存以笔记本及文档身份为键，并使用版本摘要校验；不得跨笔记本借用同名文档的数据。

### 结构化路径输出

`DocumentPath` 包含 `notebook`、`id`、`parentID`、`path`、`title`、`segments`、`depth`、`displayPath`、`revision` 和 `addressingVersion`。`title` 为 `{format, text, empty}`，`segments` 按从根到当前文档的顺序包含 `{id, text, empty}`。`displayPath` 以 `/` 开头并用 `/` 连接各段，空段数组显示为 `/`，仅作展示；笔记本名称单独返回或由调用方取得，不混入段数组。这里的 `title` 是标题摘要，不能作为未来富文本源内容的完整副本回写。

普通根文档的 `depth` 为 `1`，`parentID` 为 `null`。启用笔记本文档功能时，笔记本文档本身的 `depth` 为 `0`、`segments` 为空，普通根文档仍为第一级；它不额外增加物理目录。创建时传入笔记本文档 ID 与显式根位置等价，沿用现有逻辑根映射。根位置的子文档名称查询排除笔记本文档自身，避免把它误当成普通根文档。

路径版本摘要使用有明确字段边界的版本化序列化，覆盖祖先 ID、标题版本及当前位置，不能只使用秒级更新时间。直接按父 ID 创建可以跟随父文档的最新位置；需要保持预览结果时提交 `expectedParentRevision`，祖先改名或位置变化会使该值失效。摘要只用于一致性检查，不作为跨权限边界的访问凭证。

## 行级标题的扩展约束

标题读取应提供明确的源内容、纯文本提取和展示边界。当前实现可以继续保存普通字符串，但寻址、层级计算、创建目标解析和文件名分配不得绑定到 IAL 字符串的具体存储形式，也不得把标题交给文件路径清理函数处理。

将来支持粗体、斜体、行内代码等元素时，应复用已有行级内容模型及解析、渲染能力，并为文档标题定义明确的格式标识或版本。旧标题中的 `**文本**`、反引号和链接语法仍是原有字面内容，不能仅因升级而被自动解释为富文本。具体采用行级 Markdown、节点结构或其他表示，由独立的富文本标题设计确定。

新格式必须指定唯一的标题源内容。为兼容保留的纯文本标题只能是其派生值，源内容与派生值必须一致保存和恢复，不能成为互相覆盖的两个可写来源。旧接口不能将富文本标题的纯文本回写并静默丢弃格式；不支持相应格式的写入必须拒绝，正文编辑也必须保留标题源内容或明确拒绝保存。

富文本标题的纯文本提取需要定义空白、换行、行内公式、链接文本、空标题和长度限制的规则。仅样式不同的两个标题可以得到相同纯文本，身份与引用仍由 ID 区分。搜索、排序和导出文件名不能将 Markdown 标记或渲染 HTML 当作标题文字；导出正文中的标题可以按目标格式保留行级内容。

普通标题按文本渲染，使用现有转义或文本节点机制，不能因支持新字符而直接拼接为 HTML。富文本标题复用经过校验的节点及渲染模型；`DocumentPath` 的纯文本摘要与可编辑源内容使用不同读取边界，写入按格式区分，防止展示数据覆盖源格式。

块引用、动态锚文本、链接、标签和资源需要进一步定义依赖更新、点击行为、引用及资源归属、循环引用处理、复制与导入时的 ID 重映射，以及加密边界。本方案保留这些能力的表示空间，不表示所有行级元素都会同时开放。后续富文本标题实现还必须覆盖输入法、选区、撤销、移动端交互、历史、同步和导出。

本次解耦的验收必须确认：增加一种标题表示时，寻址和层级规则无须改变；现有普通标题的字面内容保持不变；消费者通过约定的标题读取边界获取内容，不能各自猜测标题语法。

## 创建与路径模板

### 按身份创建

已知父文档时，创建请求表达目标笔记本、父文档 ID 或根位置、独立标题及正文。内核在实际写入前按当前身份解析 ID 数据路径，并重新校验归属、可写状态、父文档有效性和加密笔记本操作租约。跨笔记本移动可能改变归属，过期的笔记本参数必须报错，不能退回其他笔记本或同名文档查找。

直接创建不附带预览版本时，父文档改名或在同一笔记本内移动后仍按该 ID 的当前位置创建。带有 `expectedParentRevision` 的请求、创建预览及模板文档树计划则必须校验相关标题和位置版本，变化时返回 `planChanged`，由调用方重新预览。两种行为由请求明确区分，不能仅因文档 ID 未变就认定预览仍有效。

父身份解析、最终校验和源文档提交必须处于与重命名、移动、删除共用的变更协调范围内，避免校验后父位置变化。沿用现有事务队列和锁顺序，不在持有队列执行所需锁时等待队列完成。请求取消、关闭笔记本或锁定不能留下可继续使用的过期租约。

当前 `createDocWithMd` 的 `parentID` 仍可能因 `hPath` 不匹配而回退到名称解析，且已有回归测试要求保留这一行为。新协议另设严格按父 ID 创建的入口，不通过修改旧参数含义实现。迁移后的内部调用直接传递结构化目标，禁止先拼回 `hPath` 再调用旧解析器。

普通新建、日记复用和往既有文档追加内容是不同操作。调用方必须表达是否允许复用目标，不能通过一次按标题搜索隐式决定写入对象。迁移应保留原有模板应用、属性写入、排序、消息推送和同步落盘要求；例如成功后清理源数据的速记流程，必须先确认目标写入成功。

### 新协议的标题校验

新创建接口要求显式传入 `title: {format: "plain", text: string}`。省略 `title`、传入 `null` 或未知 `format` 均为错误；`text: ""` 表示空标题，沿用 `custom-sy-title-empty` 和既有存储占位机制。读取时同时返回实际纯文本与 `empty`，编辑器根据标志恢复空输入，不把本地化占位文字当作用户标题。

首版保留 512 个 Unicode 码点的长度上限及现有不可见字符、私用区字符限制，保留组合 Emoji 所需的 ZWJ。新接口对超长、禁止字符和首尾空白返回 `invalidTitle`，不截断、修剪或替换后悄悄保存；界面若主动整理输入，应在提交前显示最终标题。兼容模式下新接口拒绝 `/` 及独立的 `.`、`..`；结构化标题模式允许它们作为普通文字。既有旧接口在兼容模式下的规范化行为保持不变。

结构化标题模式不执行文件路径清理、宽窄转换、百分号解码或 Unicode 归一化。`/`、`／`、`%2F`、连续斜杠以及 `A/../B` 均保留原文，层级只由父身份决定。普通新建允许同父同名，返回新 ID，不隐式覆盖或复用已有文档。

### 按标题段解析

需要按名称逐级创建时，输入包含明确的起点和标题段数组。已知祖先 ID 时直接使用该身份；未知祖先逐级在当前父文档下匹配。无匹配时按操作规则创建，有多个匹配时返回歧义及授权范围内的候选身份，不得任取第一项。通用解析器不跨同名父文档搜索后代来猜测用户意图。

结构化标题段中的 `/` 不拆分层级，`.`、`..` 不执行导航。向上一级、从笔记本根开始和以当前文档为起点需要独立表达。空段数组表示起点自身，空字符串不能用来自动匹配空标题父文档；最终创建的空标题仍可显式提交。是否允许创建缺失祖先，由调用方的 `onMissingParent` 策略决定。

### 提交、部分失败与重试

首版不新增通用的跨文件原子创建接口。内核业务使用创建计划，插件通过解析接口及单文档创建接口组合操作。计划在写入前校验所有可预知的标题、深度、歧义、模板及权限错误，并为待创建的每篇文档分配固定 ID；已匹配祖先记录身份和版本。执行时重新检查匹配和版本，并发出现同名候选时要求重新规划，不能悄悄改用另一篇文档。

每个创建步骤独立提交。成功响应要求源文档及本次必需的正文、属性修改已同步持久化，文档元数据已可读取；搜索全文索引可按现有机制异步更新。模板、脚注、数学内容、剪藏来源、标签、排序及刷新通知按原业务语义执行，不能因拆分定位逻辑而丢失。

写入途中失败时保留已落盘文档。错误数据区分 `commitState: "none"`、`"committed"`、`"unknown"`，并返回可确认的文档 ID、失败阶段及已完成步骤；`committed` 仅表示源文档已提交，不表示所有后续动作成功。落盘状态无法确认时必须返回 `unknown`，不得声称未写入。多级业务同时保留原计划及已完成 ID，向用户提供继续处理的位置。

调用方在发送前保存所分配的 ID。响应丢失或结果未知时，先完成必要的索引恢复，再按原 ID 核对源文档和目标，不重新分配 ID。重复提交已有 ID 返回 `documentIDConflict`，不覆盖文档，也不把“ID 已存在”直接认定为同一次成功请求。首版不承诺自动幂等重放；模板或追加正文等有副作用的步骤不得未经核对再次执行。

恢复只处理未完成步骤，不自动删除已经成功创建的父文档。源数据清理等不可重复的后续操作，仅在业务所需步骤全部成功后进行；部分成功和单纯收到文档 ID 都不足以触发速记源数据删除。

### 模板版本

旧字符串保存路径继续使用原有解释规则，包括绝对与相对路径、`..`、末尾 `/`、空模板、跨笔记本上下文，以及显式名称替换末段的行为。新建语法必须有可识别的版本，不能自动将已有配置按新规则重解释。

旧模板由兼容编译器按原语法求值，再输出结构化创建计划；另行传入的新标题保持独立，不重新拼入路径字符串。相对起点和向上导航使用当前文档 ID 及父关系，不能先把当前文档的显示路径拆成旧模板段。该内部适配不调用被新模式禁用的公开字符串寻址接口，因此已有日记等配置仍可工作。旧模板内变量产生 `/` 时继续按旧语法分层，只有显式改用新模板后才保留为单段。兼容编译保留语法，不保留任意选取同名父文档的做法；未知祖先仍执行歧义检查。

新配置分别使用 `docCreateTarget`、`refCreateTarget`、`dailyNoteTarget`，与原保存路径字符串字段并存。首版仅在已启用模式 `2` 的笔记本配置中开放这三个对象，全局配置继续保留旧字符串模板及现有继承规则，避免未经笔记本启用便引入旧客户端无法识别的配置。对象必须带 `version: 2`，指定目标笔记本、起点、向上层数、祖先段、最终标题和缺失祖先策略；各段继续复用现有保存路径模板求值器。示例中的 `{{now | date ...}}` 是保存路径模板语法，不能与正文模板语法混淆。

```json
{
  "version": 2,
  "notebook": "20210808180117-6v0mkxr",
  "anchor": {"kind": "notebookRoot"},
  "up": 0,
  "parents": ["Daily notes", "{{now | date \"2006-01\"}}"],
  "title": "{{now | date \"2006-01-02\"}}",
  "onMissingParent": "create"
}
```

`anchor` 另支持 `{kind: "context"}` 与 `{kind: "document", id: string}`。`context` 必须能解析为目标笔记本内的当前文档，不能在跨笔记本时猜测起点；缺少上下文返回错误。`up` 为非负整数，越过逻辑根时失败。`parents` 可为空，`onMissingParent` 必须为 `create` 或 `error`；调用方显式提供标题时直接替代 `title` 的求值结果。最终文档的复用政策由日记等业务决定，不放入通用路径模板。

新模板在渲染前确定段边界，各标题段独立求值。变量值为 `A/B` 时仍是一个标题段；先渲染成单个字符串再 `split("/")` 不符合协议。一次创建的各段使用同一份上下文和时间快照，日记按指定日历日期提供 `now`，避免跨日期或上下文变化。

新对象存在时，它是相应创建目标的唯一权威配置；旧字符串仅保留为原配置记录。修改旧字段为不同值时必须返回明确的配置冲突，不能静默覆盖新对象；原样回传旧字段仍可接受。显式移除新对象后可重新使用旧模板，但不会将笔记本降回兼容模式。未配置新对象时沿用现有笔记本及全局配置选择顺序。跨笔记本的目标仍按目标笔记本模式校验标题，不能因为来源已启用模式 `2` 而绕过目标限制。

### 业务入口迁移

| 入口 | 保持的业务行为与迁移重点 |
| --- | --- |
| 普通新建及块引用新建 | 已知父 ID 直接创建；新标题独立传递，生成的引用保存文档 ID |
| 日记 | 先按日记日期属性复用；多个匹配时保留现有模板目标优先、否则按 ID 排序的规则，已有日记不重新应用正文模板 |
| 速记 | 明确追加目标或新建目标；目标持久化成功后才清理来源 |
| 数据库新建条目 | 保留属性值、绑定关系和排序；创建计划保存最终文档 ID |
| 模板文档树 | 保留预览、ID 重映射和插入顺序，提交校验预览版本并展示部分完成结果 |
| 桌面、浏览器和移动端 | 分别检查菜单、快捷键、对话框及事件处理；共享工具函数迁移不能代替各端验证 |

日记的既有复用策略是明确的业务规则，不因通用解析器拒绝歧义而改成所有同日期情况均报错；模板目标优先匹配改为结构化身份链比较。

## 搜索与派生索引

结构化祖先链提供统一数据来源，界面展示、旧协议输出、纯文本检索和导出分别使用适合各自用途的转换规则。统一的是标题与层级的来源，不要求所有消费者共用同一个字符串序列化结果。

文档深度、父子关系和子树范围根据 ID 数据路径或明确的文档关系计算。不得通过 `hPath` 中斜杠的数量、`path.Base(hPath)`、`path.Clean(hPath)` 或按深度截取展示字符串推导结构。索引中的文档标题从标题源内容提取；恢复读取也必须使用相同的数据边界。

搜索范围过滤与路径文字匹配分开。前者使用文档身份或 ID 数据路径，后者匹配标题的纯文本表示及祖先文字，不进行 `/` 与 `／` 之间的替换。返回内容中的搜索高亮标记和 HTML 是展示结果，不能回写成标题源内容，也不能在补充文档标题时覆盖已有匹配高亮。

首版保留 `blocks.hpath`、`blocktrees.hpath` 及现有批量更新机制，新增前述文档级元数据作为结构化查询来源。完整祖先链按文档组装，可使用有界缓存，不为每个内容块复制完整标题段数组。插件仍能读取字符串列，但新模式下只能把它们当作显示和文字检索数据。

`RefreshDocHPaths` 通过 ID 子树和元数据重建祖先标题，不再按深度切割旧 `hPath`。`updateRootContent` 从统一标题读取结果取得文档标题，不使用 `path.Base`。稳态下重命名父文档不为取得标题而读取每篇后代的完整 `.sy`；缺失或失效元数据进入恢复流程，不能以旧显示路径补齐。

重命名仍会使展示路径、祖先文字检索和相关缓存失效。源文档保存、文档元数据更新、后台批次校验与中断恢复必须保持有序，排队中的旧树不能写回过期标题或路径。按 ID 寻址消除了标题对身份的影响，不等于可以删除所有重命名更新任务。

## 导入与导出

导出先为每个文档身份分配唯一的相对文件路径，再用同一份映射写文件及生成文档间链接。映射必须处理标题中的斜杠、非法文件名字符、同名文档、大小写不敏感冲突、长度限制和跨笔记本同名；文件覆盖检查与链接生成不能各自临时决定文件名。

分配器先按 ID 关系确定导出目录，再独立转换每个文件名。兼容已有无冲突文件名；遇到保留名称、空名称、`.`、`..`、尾部空格或点等情况时使用安全名称，冲突时附加稳定的文档 ID，必要时再加笔记本 ID。按目标文件系统规则比较大小写和名称，截断时保留唯一后缀及扩展名。所有名称分配完成后再次校验相对路径唯一性及目标目录边界，随后写文件和链接。标题中的 `/` 只影响单个文件名转换，不产生新目录。

标题中的 `.`、`..` 和路径分隔符只能参与文件名转换，不能越出导出目录。纯文本标题和目标格式支持的富文本标题用于文档内容；导出的文件名可以经过必要转换，但不能反过来作为标题的唯一恢复来源。要求无损重导入的格式必须保存原始标题及对应身份的元数据；普通 Markdown 文件名不能单独承担这一保证。

首版原生导出和备份继续以源文档保存标题及版本，不为了 Markdown 导出新增一种通用源格式。普通 Markdown 导出可以在正文保留标题，但不因此承诺无损恢复全部标题元数据；若后续提供带清单的往返格式，需单独定义其版本及导入规则。

导入以源文件路径和来源标识建立到新文档 ID 的映射，链接解析使用该映射，不使用 `hPath` 作为唯一键。同名来源、相对链接、标题锚点和无法唯一定位的链接沿用明确的冲突处理。Obsidian 等已有导入流程中的源路径映射应继续使用，迁移其标题及可读路径生成部分即可。

## 结构化接口契约

以下路径和字段为本方案拟定的新增契约，均使用 `POST` 和 JSON 请求。首版新增读取接口要求工作空间管理员权限，写入接口另要求可写状态；不自动向发布访问者开放祖先枚举能力。现有发布页面继续遵守已有逐文档可见性检查，增加结构化展示数据时也必须经过同等过滤。加密笔记本从解析、查询到响应写出均保持有效操作租约。

### 按 ID 批量读取

`/api/filetree/getDocPaths` 接收 `notebook` 和 `ids`，其中 `ids` 为 1 至 128 个文档 ID；超限失败，不静默截断。按首次出现顺序去重，返回 `{documents: DocumentPath[], missingIDs: string[]}`。不存在、不属于目标笔记本或不能作为文档读取的 ID 放入 `missingIDs`，不跨笔记本补查；无权访问整个笔记本时直接失败。

每个 `DocumentPath` 的标题和祖先链来自同一可验证版本。响应顺序与去重后的输入顺序一致，缺失项单独列出。索引未就绪、源格式不支持及认证失败属于错误，不伪装成文档不存在。批量读取不承诺不同文档之间的全局快照，调用方保存各项 `revision`，提交预览时重新验证。

### 按标题段解析

`/api/filetree/resolveDocPath` 接收 `notebook`、`start` 与 `segments`。`start` 为 `{kind: "root"}` 或 `{kind: "document", id: string}`，`segments` 为独立标题字符串数组。接口只解析，不创建。空数组返回起点；非空数组按精确名称逐级查找，不解析字符串中的导航字符。

结果包含 `status`、`start`、`resolved`、`nextIndex`、`candidates` 和 `candidatesTruncated`。`start` 返回起点身份及版本，`resolved` 和 `candidates` 使用 `DocumentPath`；`nextIndex` 是下一待处理段的零基索引。`status: "resolved"` 表示全部命中，`"missing"` 表示从该段开始没有文档，`"ambiguous"` 表示该段存在多个候选。候选按 ID 排序，最多返回 128 个，并用 `candidatesTruncated` 表示仍有更多结果；达到上限仍必须报告歧义，调用方改用明确父 ID，不能从截断结果中默认选择第一项。

解析最多接受 128 段，每段遵守标题长度限制，实际创建仍执行用户的文档深度限制。空字符串段失败，名称为空的已有父文档需按 ID 选定。笔记本根作为解析结果时使用明确的根位置，不伪造文档 ID；根版本覆盖笔记本身份及相关配置，不因无关子文档变化而失效。作为根位置别名的笔记本文档 ID 也使用根版本校验。错误和候选不得泄露其他笔记本的标题。

### 按父 ID 创建

`/api/filetree/createDocByParent` 的最小请求如下。示例要求目标笔记本已启用结构化标题模式。

```json
{
  "notebook": "20210808180117-6v0mkxr",
  "parentID": "20261015090000-abcdefg",
  "id": "20261015100000-hijklmn",
  "title": {"format": "plain", "text": "卷01·第一章/第二节"},
  "markdown": ""
}
```

| 字段 | 约束 |
| --- | --- |
| `notebook` | 必填，目标笔记本 ID |
| `parentID` | 必填；文档 ID 或表示笔记本根位置的 `null`，不接受空串作为根位置 |
| `id` | 必填，由调用方预先生成并保存的有效新文档 ID；已存在时不覆盖 |
| `title` | 必填，首版仅接受普通标题对象；空字符串与缺省值不同 |
| `markdown` | 必填，允许空字符串 |
| `expectedParentRevision` | 可选，提交预览时用于校验父路径版本；根位置使用解析接口返回的根版本 |
| `tags`、`withMath`、`clippingHref` | 可选，复用现有 Markdown 创建流程对应的处理规则 |
| `sorts`、`sortTargetID`、`sortPosition` | 可选，保持排序校验；相对排序目标必须仍是同一父级下的文档，冲突排序方式报错 |
| `docCreateTemplatePath`、`listDocTree` | 可选，沿用现有正文模板与文档树刷新语义 |

接口拒绝额外提交的 `path`、`hPath` 等目标字段，避免两个位置来源互相覆盖。父文档不匹配时直接失败，不能退回名称寻址。成功返回 `{id, document: DocumentPath}`；客户端直接使用返回 ID 打开、引用或追加内容。

业务错误使用 `code: -1`，`data.reason` 提供稳定原因；`msg` 用于人类阅读，不作为插件分支条件。契约声明保留错误数据，以传递提交状态和恢复信息。认证、角色、锁定及通用请求校验错误继续使用相应中间件契约，不强行改写所有既有错误格式。

| 原因 | 含义及调用方处理 |
| --- | --- |
| `invalidTitle` | 标题格式、字符或长度无效，修改输入后提交 |
| `parentUnavailable` | 父文档不存在或不属于目标笔记本，不跨笔记本查找 |
| `planChanged` | 位置、标题版本或预览依赖变化，重新解析并确认目标 |
| `documentIDConflict` | ID 已存在，核对原请求结果，不覆盖或直接换 ID 重试 |
| `legacyPathUnsupported` | 目标笔记本禁用旧字符串寻址，改用新接口 |
| `indexUnavailable` | 结构化元数据未就绪，等待恢复，不回退到显示路径 |
| `unsupportedTitleFormat` | 客户端或接口不能处理标题格式，升级或改用对应格式接口 |
| `writeFailed` | 写入或后续处理失败，依据 `commitState` 及阶段恢复 |

### 读取有效创建目标

`/api/filetree/getDocCreateTarget` 接收当前 `notebook` 与 `purpose: "document" | "reference" | "dailyNote"`，复用各业务现有的配置优先级，返回生效的 `target`、`docCreateTemplatePath` 和配置 `revision`。`target` 为带 `version` 的联合类型：旧模板返回 `{version: 1, notebook, path}`，新模板返回上文完整的版本 `2` 对象。接口只读取配置，不执行模板、不猜测当前文档或当前日期；调用方随后提供上下文生成计划。

旧 `/api/filetree/getDocCreateSavePath` 在生效配置仍为旧模板时保持原响应；新对象生效时返回 `code: -1`、`data: {reason: "structuredTemplateRequired"}`，不返回已经失效的旧路径。该错误变体在旧契约中明确声明。新增读取入口同时服务内置调用方和插件，避免各自重复实现配置继承规则。

### 能力探测与启用

在 `/api/notebook/getNotebookConf` 的 `data` 中增加可选只读对象 `documentCapabilities`，保留现有 `box`、`name`、`conf` 和权限过滤。对象包含 `addressingVersion`、`structuredPaths`、`literalSlash`、`titleFormats`、`indexState`、`minimumReaderVersion` 和 `revision`。`structuredPaths` 表示服务端实现了新协议，`indexState` 表示该笔记本是否可用；两者不能混为一谈。首版 `titleFormats` 为 `["plain"]`，`literalSlash` 仅在模式 `2` 且索引就绪时为 `true`。

`revision` 是启用流程相关的配置版本；它不等同于某篇文档的路径版本。能力声明不授予访问权限，关闭或锁定笔记本时仍执行原有访问限制；状态读取不得暴露标题或受保护的模板内容。旧服务端没有该对象时，插件只能使用旧能力。鉴权、锁定或网络请求失败不能被当作“服务端不支持”，更不能据此回退后继续写入。

`/api/notebook/enableStructuredTitles` 接收 `notebook` 与 `expectedRevision`，核查当前配置版本、索引状态和客户端本地兼容能力后持久化模式 `2`，返回最新 `documentCapabilities`。已经启用且版本匹配时可直接返回当前状态。此接口不能证明所有离线同步客户端都已升级；启用界面需要说明最低版本和插件适配要求，由用户明确启用。通用配置更新不能绕过此流程切换模式，省略新字段的旧请求也不能将模式重置为 `1`。

### 契约及声明维护

实现遵循 [内核接口类型契约](API-CONTRACTS.zh-CN.md)：在 `kernel/apicontract/` 定义声明，使用 `contractHandler` 绑定，生成类型并同步 Petal 维护声明及变更记录。新增接口的详细规则放在对应契约注释中。已有接口行为受影响时检查并同步中、英、日 API 文档中的既有条目，不自动把新接口追加到 API 参考文档，也不向契约维护指南添加本特性的接口说明。

## 接口与插件兼容

模式 `1` 为兼容模式；模式 `2` 为显式启用的结构化标题模式。没有模式字段的旧笔记本按 `1` 读取。模式决定旧协议是否可用，不根据某一次请求是否恰好包含 `/` 猜测。

| 使用场景 | 兼容模式 `1` | 结构化标题模式 `2` | 插件迁移方式 |
| --- | --- | --- | --- |
| 按 ID 读取、移动及删除 | 保持现有契约 | 保持身份、权限及返回变体 | 继续使用 ID，移动后重新读取当前位置 |
| 按 ID 重命名及 ID 数据路径创建 | 保持现有标题规则 | 普通标题可保留 `/`，仍验证模式和标题格式 | 标题与位置分开传递；未知富文本格式不能用纯文本覆盖 |
| `getIDsByHPath` | 保留原名称路径语法 | 整个笔记本拒绝，返回 `legacyPathUnsupported` | 已知 ID 直接使用；未知位置调用 `resolveDocPath` |
| `createDocWithMd` | 保留旧语法及 `parentID` 回退行为 | 整个笔记本拒绝，即使传入 `parentID` | 改用 `createDocByParent`，不提交字符串路径 |
| `getHPathByID`、`getHPathByPath` | 保留现有输出 | 按祖先标题原文拼接，只可显示 | 获取结构时改用 `getDocPaths` |
| `getFullHPathByID` | 保留含笔记本名称的输出及空值规则 | 仍显示笔记本名称，不能反向定位 | 笔记本名称与文档段分别展示 |
| `blocks.hpath`、`blocktrees.hpath` | 保留列类型及原行为 | 仍是字符串，可能包含无法区分的标题斜杠 | 子树查询使用 ID `path`，标题读取文档行 `content`，父级及深度通过结构化接口取得 |
| `Criterion.hPath`、`SearchPath`、搜索结果 | 保留既有配置和高亮语义 | 显示文字仍可检索，范围与层级使用 ID | 不把高亮文本或路径显示值重新提交为位置 |
| 旧保存路径模板 | 原语法运行 | 通过内部兼容编译器生成结构化计划 | 需要变量中的 `/` 保持单段时显式使用版本 `2` 模板 |
| `getDocCreateSavePath` | 保留旧配置结果 | 旧模板仍返回原结果，新模板返回 `structuredTemplateRequired` | 通过 `getDocCreateTarget` 读取生效的带版本配置 |

不改变旧字段的数据类型，不删除旧 API，也不把模式 `2` 的显示路径编码后伪装成可兼容地址。新模式下两个不同结构可以显示为相同字符串；SQL 的等值 `hpath` 查询也可能返回两种结构。继续按分隔符计数、取末段或做前缀子树查询的插件必须适配，这是启用能力的兼容成本。

旧字符串接口在模式 `2` 下新增明确的错误变体：`code: -1`、`data: {reason: "legacyPathUnsupported"}`。该变体需在原接口契约中声明并保留错误数据；模式 `1` 下既有成功、空值及错误返回保持不变。不能只改错误文案却让插件通过匹配本地化文字判断能力。

现有标题中的 `／`、`%2F` 等均按字面数据处理，不推测历史编码意图。若特定对外通道需要可逆编码，必须使用独立版本和适配边界，不能把该编码引入内部身份或标题源内容。

插件迁移顺序为能力探测、按 ID 读取目标、按结构化规则解析未知祖先、按父 ID 创建、使用返回 ID 操作。发布替代接口时同时提供上述迁移矩阵和最小示例；开放模式 `2` 前完成内置调用方迁移。服务端无法识别所有插件 SQL 及其后续用途，不能宣称会自动阻止全部插件误用显示字符串。

## 版本、加密与恢复

### 混合版本访问

笔记本配置新增 `documentAddressingVersion`，缺省或 `1` 为兼容模式，`2` 为结构化标题模式。该字段与加密信封版本独立，不能复用 `BoxCrypt.Spec`。新旧模式不批量改写已有文档标题或 ID；开启能力只改变后续操作准入和新内容的表示规则。

即使 `.sy` 仍保存字符串标题，旧客户端也可能移除 `/`，或把标题文字当作层级。发布分两步：先发布理解笔记本能力标记、能够安全拒绝未知模式的保护版本，再发布允许启用模式 `2` 的功能版本。保护版本在挂载、索引、修复、编辑及同步应用入口拒绝处理不支持的模式，不能先修改数据再提示升级。

真正使用新标题能力的文档采用新的 `DocumentTitleSpec`；具体数值在实现时按当时已使用的 `.sy` 版本分配，不在草案中预占某个数字。未使用新能力的文档不因笔记本启用而全部改写。未来富文本表示还需对应的明确格式版本，未知内容不得被容错解析后覆盖。

版本保护必须覆盖完整读取、仅属性读取、只读路径恢复、导入、历史、备份及同步。当前 `readDocIAL` 的非严格分支不会执行与严格分支相同的 `CheckSpecJSON` 检查，不能仅在普通编辑加载处添加检查就认为完整受保护。源文档版本要求模式 `2` 而配置仍为 `1` 时，先报告模式冲突；导入只能在明确选择启用后继续，不能偷偷清理标题以适配旧模式。

最低兼容版本由真实发布版本的读写及拒绝测试确定。保护版本之前忽略能力标记的客户端无法由新字段自动约束，不在安全混用承诺内。启用前要求所有同步设备升级；系统无法证明离线设备状态，应明确说明这一限制。如果已支持版本仍存在会改写数据的路径，保持新能力关闭，不能以文档提示代替必要保护。

模式 `2` 启用后不提供直接改回 `1` 的开关。即使当前标题已不含 `/`，历史和备份仍可能包含新格式。回退客户端只能使用经验证的兼容导出副本，或恢复启用前的完整备份到独立工作空间；不能将旧配置覆盖回原工作空间并继续同步。若未来提供降级转换，应另行设计转换清单、冲突处理和恢复机制，保留原数据。

### 索引与任务恢复

`document_metadata` 使用独立的派生索引版本及笔记本状态 `missing`、`building`、`ready`、`error`。新建表后从源文档和 ID 位置构建，不从旧 `hPath` 推测段边界。构建期间记录增量变更并在切换前追平；只有全量扫描和增量校验完成，才将对应代次标记为 `ready`。

兼容模式下旧功能在重建期间保持既有行为，新结构化接口在需要的数据未就绪时返回 `indexUnavailable`。模式 `2` 下不能因索引损坏回退到旧名称定位；按现有源读取路径恢复，结构化写入等待必需元数据就绪。不存在的父源文件不能自动补建，损坏源文件不能靠索引中的旧标题覆盖。

更新顺序为源文档持久化、同一块树数据库事务内更新文档元数据和对应文档行、提交后续 `hpath` 批次。源文件与数据库、块树库与内容库之间不宣称原子事务。任一步骤中断都保留恢复标记；重新启动或解锁后先验证源版本及当前 ID 位置，再继续派生更新。快照版本、移动或删除检测使排队中的旧树失效，不能恢复旧标题。

现有 `temp/queue/hpath-refresh.queue` 只保存笔记本 ID、文档 ID 和 ID 数据路径。迁移不得将标题段、富文本标题或正文写入这个全局明文队列。并发重命名、移动、删除、同步及普通索引重建仍需校验任务是否过期，不能误清理尚未完成的加密笔记本恢复任务。

为防止源文件已写入而恢复任务尚未登记时崩溃，变更前先持久化仅含身份的待核对标记，或使用已有能覆盖该窗口的持久事务记录；相关实现必须用故障注入证明可恢复。任务完成后再清理标记，重复恢复应得到同一派生结果。加密笔记本未解锁时保留任务，不能为了清空队列而跳过认证。

### 加密兼容

已有加密数据是兼容基线，遵循 [加密笔记本](ENCRYPTED-NOTEBOOK.zh-CN.md) 的认证读取、隔离及恢复要求。标题源内容、纯文本标题和祖先链都属于受保护的文档内容；读取、缓存和响应必须处于对应笔记本的授权范围及操作租约内，锁定后按现有生命周期清理。

重建派生索引之前必须认证源密文并验证文档格式。未知格式、损坏和认证失败必须保留原始数据并返回错误，不能回退到明文、跨笔记本查询或未认证的旧索引。普通索引重建不代表加密源数据已经通过认证。

本方案的内部解耦不要求更改加密信封、AAD 或密钥派生。后续若涉及这些格式，必须另有显式版本、认证迁移和中断恢复设计，并保留匹配的密钥与备份材料。不得重新生成 `MasterSalt`、丢弃密钥或要求用户重建已有加密笔记本来规避兼容问题。文档、历史、备份和同步快照中的受支持格式必须持续可恢复。

## 实施拆分与开放条件

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| A：兼容保护 | 笔记本能力标记、未知模式及源版本保护、旧行为回归样本 | 已发布保护版本；未知模式在所有写入与修复入口安全拒绝 |
| B：内部解耦 | 统一标题读取、文档元数据、ID 层级计算、路径刷新及恢复 | 普通标题行为不变；结构不再从显示字符串推导，加密索引可认证重建 |
| C：接口与调用方 | 新读取、解析、创建接口，版本 `2` 模板，内置业务及各端迁移 | 新旧契约通过验证，部分失败可恢复，日记等业务行为保持 |
| D：开放新字符 | 模式启用入口、旧接口拒绝规则、插件迁移说明、导入导出和跨版本验证 | 全部开放条件满足后才允许用户显式启用 `/` |
| E：行级标题 | 独立的源格式、编辑及渲染设计 | 保持本方案身份接口，完成格式及旧写入保护后另行交付 |

阶段 B、C 可以在保留旧标题限制时先行交付；新字符的开放必须等待 A 至 D 所需条件全部成立。阶段 E 不作为基础解耦的前置依赖，也不能在 A 至 D 中重新引入只接受永久纯文本来源的假设。

开放条件包括：所有内置消费者已迁移；替代接口和插件适配文档已发布；已验证最低客户端版本及混合版本拒绝；普通与加密索引迁移可中断恢复；导入导出不会因显示路径冲突覆盖文件；桌面、浏览器和移动端行为一致；四种语言的用户指南说明启用方式、插件影响和同步设备要求。

实施时还需登记实际发布版本号、分配未冲突的 `.sy` 版本号，并附上性能测量与兼容测试结果。这些是发布证据，不是重新悬置身份、模板、插件边界或失败语义的决策。本文中的接口和字段需落实为可验证契约，不能以完成文档或一次索引重建代替功能验收。

### 关键回归用例

保留 `TestCreateDocsByHPathUsesParentIDForDuplicateHPath` 和 `TestCreateDocsByHPathKeepsHPathFallbackForDifferentParent`，证明旧兼容入口没有被新规则悄悄替换。另为新入口覆盖父标题变化后仍使用原 ID、父跨笔记本移动后拒绝、同名父文档不会被误选，以及带版本提交返回 `planChanged`。

同时建立根文档 `A/B`、根文档 `A` 及其子文档 `B`、根文档 `A／B`、根文档 `A%2FB`。前两者允许相同显示路径，但 ID、`segments`、`depth`、子树范围和导出链接必须各自正确；后两者不得被转换成前两者。增加重复斜杠、点段、空标题、大小写差异和相同纯文本不同标题格式的样本。

实际 HTTP 回归检查严格请求类型、必填与 `null` 区别、返回顺序、候选截断、错误数据、管理员与可写保护、加密响应租约及发布访问拒绝。旧接口的兼容回归与新接口回归分开断言，避免用新预期覆盖旧行为。前端验证旧模板配置往返、新模板逐段求值、同一时间快照、部分成功提示以及移动端入口。

故障注入至少覆盖源文档落盘前后、元数据事务前后、内容索引批次中断、成功响应丢失及锁定发生在响应输出期间。使用受支持历史格式的真实样本验证读取、导出、历史、备份及恢复，同时验证保护版本安全拒绝新格式；仅测试当前版本生成的文件不能证明向后兼容。

### 性能与资源

同一环境比较基线和实现，使用 1,000 与 10,000 篇文档、宽子树及深度 7 的层级，并额外覆盖用户开启更深层级的情况；分别测试普通与已解锁加密笔记本。记录批量路径读取、父文档重命名、移动、首次重建和增量恢复的前台延迟、后台耗时、内存、数据库大小及 `.sy` 读取次数，报告中位数和高分位结果。

前台创建和读取不得因新增元数据而扫描整个笔记本；已就绪的父重命名不得逐篇读取后代正文。索引构建允许按文档数量扫描源数据，但须有进度和恢复点。缓存有明确上限，锁定时清除相应标题；不把每个内容块的整条祖先链常驻内存。既有 `hpath` 对内容块的后台更新成本单独记录，不把含调度等待的总耗时当作数据库耗时，也不宣称解耦会消除全部子树更新。

性能报告必须说明相对基线的变化及原因；具体耗时取决于设备、正文大小和加密开销，本草案不填写未测量的收益或固定毫秒承诺。明显回归先分析查询次数、事务批次及重复源读取，再决定缓存优化，不以改变标题语义换取性能。

### 实现阶段的检查

行为测试进入现有前端及内核测试发现范围；新 Go 契约用例名称保留 `Contract`。实施 API 改动后，在 `app/` 执行 `pnpm run api:generate --petal ../../petal`、`pnpm run api:check --petal ../../petal`、`pnpm run lint` 及相关前端测试；在 `kernel/` 执行 `go test ./apicontract/...` 和覆盖受影响 API、模型、文件系统、块树及 SQL 的回归测试。发布前由现有完整测试入口覆盖 `pnpm test` 与 `go test -tags "fts5 sqlcipher" ./... -count=1`。

只有既有发现机制不能覆盖新用例时才调整持续集成筛选或维护指南。以上是实施验收要求，并非本设计文档已执行的功能测试；文档修改本身检查双语一致性、示例、链接及差异格式。
