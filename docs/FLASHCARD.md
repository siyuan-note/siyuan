## 1. 设计范围

### 1.1 核心方案

闪卡采用相互分离的卡片模式、卡源、卡片、复习状态、复习事件、卡包和排期预设。一份卡源可以生成多张独立排期的卡片；同一卡片进入多个卡包时共享一份排期。快速制卡与高级制卡使用同一领域模型，只在交互复杂度上有所不同。

`.sy` 保存正文，`data/storage/riff/v2/` 保存版本化实体与不可变事件，`temp/flashcards.db` 提供本地事务、查询和统计。SQLite 不参与同步，可以从权威记录与当前文档重建。排期统一使用 FSRS，内容编辑、卡包调整和临时排序不自动重置排期。

旧结构把块、卡片、物理卡包和排期绑定在一起，难以表达一源多卡、稳定挖空、共享排期和完整历史。新结构以稳定的卡片身份承担复习，以可组合的查询和成员关系组织卡包，同时保留 SiYuan 的块编辑、上下文和插件扩展能力。

### 1.2 当前能力与已知缺口

下表区分已具备的能力和仍需完成的部分。设计规则描述预期行为，不表示所有交互目标或发布验收都已完成；具体待办见[待完成工作](#11-待完成工作)。

| 范围 | 已具备的能力 | 已知缺口或限制 |
|---|---|---|
| 领域与迁移 | 卡源、卡片、排期和卡包分离；稳定身份；自动幂等迁移；旧接口适配；保留旧数据 | 多设备真实迁移、同步与恢复仍需完整验收 |
| 制卡与渲染 | 块闪卡、正反向、分组挖空、有序多空、输入答案、选择题、图片遮挡、媒体与 TTS；高级内置卡源可原地编辑 | 公式内部挖空与修复、通用模板管理、步骤编辑、部分预览和配置入口尚待补齐 |
| 管理 | 卡源分组与卡片列表、结构化筛选、标签、七色旗标、暂停、埋藏、优先级和预设分配 | 标签来源与后代筛选、部分批量操作尚待补齐 |
| 学习范围 | 按卡包、文档、笔记本、当前筛选或本页选中卡片学习；选中卡片可临时排序 | 全查询结果沿用现有优先级与到期排序，不提供临时自定义排序 |
| 复习 | 正常复习、同会话短期重学、共享每日额度、强化复习、撤销、原文定位与复习大纲；结束后可主动再练薄弱卡片 | 自动评分配置仍待补齐；薄弱范围只保留在当前会话，不形成持久化最终演练队列 |
| 历史与统计 | 卡源配置历史、完整单卡历史、未来到期、保留率、耗时与 FSRS 分布 | 部分统计细项和单卡统计入口尚待补齐 |
| 数据恢复 | 不可变分段、快照、投影重建和实体冲突处理 | 大数据量性能及真实同步链路仍需验收；物理清理依赖独立安全压缩协议 |
| 渐进式阅读 | 可复用编辑器、块引用、摘录组织、制卡和原文定位 | 独立阅读进度、回访调度与位置恢复暂缓实现 |

子集学习、临时排序和当轮薄弱练习复用现有查询、有序候选卡片与强化会话，不需要新增内核接口、权威格式或插件公开参数。

### 1.3 范围约束

- 加密笔记本不支持闪卡，也不建立专用闪卡存储；所有入口执行相同的准入检查
- 支持 Anki `.apkg` 导入及安全降级，不支持 `.apkg` 导出或 RemNote 专用导入
- 排期只使用 FSRS，不内置 SM-2 或插件排期算法；“考试”优先级不包含自动备考计划
- 模板采用声明式定义和作用域 CSS，不执行任意 JavaScript；AI 制卡通过 API 和插件扩展，不内置专门界面
- v2 激活后停止旧格式写入，保留迁移备份；历史默认保留，不提供尚无安全同步协议的物理清理
- 完整渐进阅读、持久化最终演练、自动负荷分摊、全库严格优先级和引用网络扩散列为后续范围

## 2. 用户流程与交互

用户从文档或块创建卡片，在管理界面组织和筛选内容，选择范围开始学习，在复习中查看上下文或编辑原文，最后结束或主动继续薄弱练习。各入口沿用现有对话框、表单、菜单和主题样式；临时操作只影响本轮，涉及长期排期的操作明确表达其含义。

### 2.1 创建与编辑卡片

现有入口包括块菜单、文档菜单和制卡对话框。设计目标还包括编辑器工具栏、卡片预览面板及可配置文本快捷输入；这些入口与保存前预览的缺口集中在第 11.1 节。桌面端和移动端应能完成方向、模板、分组、顺序与预览操作。

快速制卡为所选块创建正式的块闪卡，并使用默认内置模式和模板，保持当前操作效率。复习时动态检查块内是否存在标记、列表、标题、超级块、引述区块或备注等答案结构：存在时先隐藏答案并显示答案按钮，不存在时直接显示完整内容和评分按钮。高级制卡打开完整配置面板，但最终调用同一创建 API。

快速制卡统一跳过纯空白段落，单选和多选采用相同规则。空格和换行不构成制卡内容，图片、公式、块引用等具有独立语义的内容仍可制卡；列表项、标题和引述块不受该规则影响。已有快速卡的内容被清空后仍保留排期和历史，并允许取消制卡。该过滤仅作用于快速卡的新建候选，不改变多块问答或高级卡源中的块顺序和角色。

原生输入答案模式把所选第一个块作为问题，其余块作为同一张卡的多个可接受答案；答案检查默认折叠空白、忽略大小写并给出轻度模糊匹配建议，但不替代用户最终评分。

新增或修改快捷键时同步维护对应快捷键说明。

### 2.2 管理与卡包

管理界面默认按 `CardSource` 分组，可展开查看正向卡、反向卡、挖空组和其他变体；同时支持切换为扁平卡片列表。分组模式必须先按卡源分页，再返回当前页卡源的全部匹配卡片，不能先按单卡分页后在前端临时分组，也不能把同一卡源拆到不同页。

筛选条件至少包括内容文本、文档范围、卡片模式、模板、卡源标签、单卡标签、旗标、生成状态、暂停、埋藏、学习优先级、排期预设、到期范围、复习次数、遗忘次数、稳定度、难度和可提取性。

所有单卡操作以 `CardID` 为目标，卡源操作明确提示会影响多少张兄弟卡。

闪卡标签选择器支持在指定父标签下创建标签，并可重命名或移动既有标签；移动时不能选择自身或后代作为父标签，内核仍负责父引用、同级重名和环检测。

卡包界面显示查询条件、静态成员、排除项、预计卡片数量、今日到期量和复习方式。新建卡包默认不启用动态筛选且成员为空；用户可以显式启用动态筛选，从管理界面的当前筛选保存卡包时自动启用。启动时可以选择正常复习或不影响排期的强化复习。

删除卡包只删除组织关系，不能显示为删除卡片操作，也不改变卡片的排期预设。

### 2.3 选择学习范围

管理工具栏提供“开始学习”。有勾选时默认使用本页选中卡片，没有勾选时默认使用当前筛选范围；用户可以在对话框中切换范围。页内全选只选择当前页，当前筛选范围则覆盖全部分页。卡包内发起学习时继续保留该卡包的成员边界。

学习对话框使用现有表单、下拉框和主题样式，仅提供学习范围、复习模式及适用时的排序选项。复习模式默认正常复习，并显示到期资格与每日限额说明；选择强化复习时提示不改变正常排期。只有选择具体卡片时显示临时排序，默认保留列表顺序，也可以选择随机、先到期的优先、难度高的优先或遗忘次数多的优先；数值相同的卡片保留原列表顺序。

临时排序和模式的额度规则见第 5.6 节。界面不要求用户先保存卡包，也不把管理页的分页误当成整个筛选范围。

### 2.4 复习与原文定位

复习界面支持上下文、提示、逐步揭示、输入答案、选择题、媒体、TTS、直接编辑和插件渲染。答案检查给出建议，评分由用户决定；可选自动评分的配置仍列为待完成工作。

会话菜单明确区分跳过、埋藏、暂停当前卡、暂停同源卡、编辑、重置、设置到期时间、旗标和标签。

弹窗、页签和独立窗口使用相同的会话与卡片渲染流程，保留定位当前文档入口。关闭承载界面结束当前会话；恢复保存的页签布局时按保存范围重新创建会话，不复用过时进度。旧布局兼容规则见第 8.3 节。

### 2.5 复习大纲

弹窗、页签和独立窗口共用会话内侧栏，使用工具栏按钮或现有大纲快捷键切换。大纲读取来源文档的标题结构，只显示当前卡面已可见且未遮挡的标题文字，其余使用序号占位。点击可见标题在卡内滚动，其他标题打开原文；滚动同步高亮，换卡、撤销和结束时更新范围，过期异步结果不写入新卡片。带修饰键的组合快捷键不参与评分。

### 2.6 结束与继续练习

结束页保留撤销入口，并提供明确的结束按钮。存在当轮薄弱卡片时显示“再练薄弱卡片”及数量，提示该操作属于不改变正常排期的强化练习。继续练习由用户主动选择，不自动开始下一轮，也不要求清空薄弱范围。

弹窗在旧会话完成清理并从全局弹窗列表移除后打开下一轮，避免关闭动画干扰新会话。页签和独立窗口复用当前挂载区域，移除上一轮的关闭监听与渲染资源，不关闭承载页签；最终退出时清理当前会话。结束页按钮在窄窗口自动换行，沿用现有主题颜色、字号和间距。

## 3. 领域模型

以下类型描述逻辑职责与核心字段；精确的请求、响应及可选字段由内核契约和维护中的类型声明定义。字段、引用、卡片身份和排期不得因界面名称或显示顺序改变。

### 3.1 术语

| 术语 | 标识符 | 定义 |
|---|---|---|
| 卡片模式 | `CardSchema` | 定义一类卡源包含的字段、允许的模板和验证规则，对应 Anki 的 Note Type |
| 卡片模板 | `CardTemplate` | 定义正面、背面、生成条件、答案方式、上下文和样式，对应 Anki 的 Card Type |
| 卡源 | `CardSource` | 一份可生成卡片的逻辑知识实体，对应 Anki 的 Note，也可以由一个或多个 SiYuan 块组成 |
| 卡源引用 | `CardSourceRef` | 卡源对块、属性视图条目、资源或其他实体的有序引用，并标明问题、答案、提示等角色 |
| 卡片 | `Card` | 真正参与排期和评分的最小单位，由卡源、模板和稳定变体共同确定 |
| 复习状态 | `ReviewState` | 一张卡当前的 FSRS 状态、到期时间、暂停和埋藏状态 |
| 复习事件 | `ReviewEvent` | 一次评分、重置、手动设置到期时间等排期行为的不可变事实记录 |
| 卡包 | `ReviewSet` | 保存卡片查询、手动成员、排除项、排序、限制和复习方式的命名集合 |
| 卡包成员关系 | `ReviewSetMembership` | 独立记录卡包对单张卡片的手动加入或排除，不把大量卡片 ID 内嵌到卡包实体中 |
| 排期预设 | `SchedulerPreset` | 保存 FSRS 参数、新卡与复习卡限制、兄弟卡埋藏和疑难卡规则 |
| 学习优先级 | `StudyPriority` | 只影响复习队列顺序和是否进入全局队列，不直接修改 FSRS 到期时间 |
| 复习会话 | `StudySession` | 一次连续复习过程，记录卡包、复习方式、开始结束时间和已处理卡片 |

产品界面和本文统一使用“卡包”。内部 Go 类型和 API 字段继续使用 `ReviewSet` 与 `ReviewSetID`，它们是稳定的数据模型标识，不需要随界面术语迁移。

“快速制卡”和“高级制卡”只表示不同的创建界面。两者必须生成相同的 `CardSource`、`CardTemplate` 和 `Card`，不能再维护不同存储路径。

### 3.2 领域关系

```text
CardSchema 1:N CardTemplate
CardSchema 1:N CardSource
CardSource 1:N CardSourceRef
CardSource 1:N Card
CardTemplate 1:N Card
Card 1:1 ReviewState
Card 1:N ReviewEvent
ReviewSet 1:N ReviewSetMembership
Card 1:N ReviewSetMembership
SchedulerPreset 1:N CardSource
SchedulerPreset 1:N Card override
```

`CardSource` 与 `Card` 必须分离。修改卡源内容时，所有兄弟卡重新渲染，但各自的复习状态不变。一个块可以参与多个卡源，一个卡源也可以引用多个块。

### 3.3 `CardSchema`

核心字段：

| 字段 | 含义 |
|---|---|
| `ID` | 稳定模式 ID |
| `Name` | 显示名称 |
| `Fields` | 字段定义、类型、必填规则和默认值 |
| `BuiltinType` | 普通问答、挖空、图片遮挡等内置类型；自定义模式为空 |
| `TemplateIDs` | 关联模板 ID |
| `RevisionID` | 当前版本化实体修订 ID |
| `CreatedAt`、`UpdatedAt` | 创建和更新时间 |

内置模式至少包括普通问答、挖空、多行卡、选择题和图片遮挡。Concept、Descriptor 等 RemNote 风格能力作为内置预设表达，不增加仅服务于某一产品术语的底层实体。

### 3.4 `CardTemplate`

核心字段：

| 字段 | 含义 |
|---|---|
| `ID` | 稳定模板 ID |
| `SchemaID` | 所属 `CardSchema` |
| `Name` | 模板名称，例如正向、反向 |
| `GenerationRule` | 根据字段、挖空组或遮挡组生成卡片的规则 |
| `FrontSpec`、`BackSpec` | 声明式正反面渲染定义 |
| `AnswerMode` | 揭示、输入答案、单选、多选、逐步揭示等 |
| `ContextPolicy` | 文档标题、面包屑、最多五层祖先块、前后各最多五个相邻块或无上下文；渲染前移除当前卡源与答案引用并执行文本泄漏检查 |
| `Style` | 通过 CSSOM 解析后绑定到当前卡片根元素的作用域 CSS；丢弃 `@import`、全局字体、关键帧、外链、脚本协议和固定定位，不允许任意 JavaScript |
| `Enabled` | 模板是否参与生成 |
| `RevisionID` | 当前修订 ID |

模板关闭后，关联卡片进入 `DisabledByTemplate`，不删除 `CardID`、排期或历史。重新启用后恢复原卡片。

### 3.5 `CardSource`

核心字段：

| 字段 | 含义 |
|---|---|
| `ID` | 稳定卡源 ID |
| `SchemaID` | 所用卡片模式 |
| `SourceType` | `block`、`multi-block`、`cloze`、`image-occlusion`、`av-row` 或插件类型 |
| `PrimaryRefID` | 确定卡源主要位置、文档范围策略和默认上下文的引用 |
| `DefaultPresetID` | 默认排期预设 |
| `Priority` | 卡源级学习优先级覆盖，可为空 |
| `GenerationConfig` | 经过类型校验的方向、挖空组、顺序和答案配置 |
| `Status` | `Active`、`Orphaned` 或 `Deleted` |
| `PluginData` | 仅供插件类型使用的版本化扩展数据 |
| `RevisionID` | 当前修订 ID |

核心字段不能塞入无约束的 `map[string]string`。插件扩展数据必须包含类型命名空间和数据版本，并提供缺少插件时的文本回退。

### 3.6 `CardSourceRef`

核心字段：

| 字段 | 含义 |
|---|---|
| `ID` | 稳定引用 ID |
| `SourceID` | 所属卡源 |
| `FieldID` | 所属 `CardSchema` 字段；上下文等非字段引用可为空 |
| `EntityType` | `block`、`av-item`、`asset-region` 等 |
| `EntityID` | 被引用实体 ID |
| `Role` | `question`、`answer`、`hint`、`extra`、`context` 等 |
| `Sort` | 同角色内的显示顺序 |
| `Required` | 引用缺失时是否使整个卡源进入 `Orphaned` |

卡源只保存引用，不复制 `.sy` 块正文。一个模式字段可以对应多个有序引用，一个引用只能归属一个字段；`Role` 用于进一步区分答案、提示和上下文等渲染语义，不能代替稳定 `FieldID`。复习时从当前块内容渲染，源内容编辑后所有兄弟卡立即更新。

### 3.7 `Card`

核心字段：

| 字段 | 含义 |
|---|---|
| `ID` | 稳定卡片 ID，也是复习日志的主关联键 |
| `SourceID` | 所属卡源 |
| `TemplateID` | 所用模板 |
| `VariantKey` | 同一卡源和模板下的稳定变体键 |
| `VariantData` | 经过类型校验的分组、步骤或遮挡参数 |
| `GenerationStatus` | `Active`、`DisabledByTemplate`、`Orphaned` 或 `Deleted` |
| `Flag` | 无旗标或七种固定颜色之一 |
| `PresetOverrideID` | 单卡排期预设覆盖，可为空 |
| `PriorityOverride` | 单卡学习优先级覆盖，可为空 |
| `CreatedAt`、`UpdatedAt` | 创建和更新时间 |

必须建立唯一约束 `UNIQUE(SourceID, TemplateID, VariantKey)`。`VariantKey` 使用稳定 ID，不使用当前显示编号或数组下标。

### 3.8 标签与旗标

闪卡标签和内容标签使用完全独立的命名空间。标签采用规范化关系表，不使用逗号或空格分隔字符串。

| 表 | 关键字段 |
|---|---|
| `tags` | `id`、`parent_id`、`name`、`normalized_name`、`revision_id` |
| `tag_assignments` | `tag_id`、`target_type`、`target_id` |

`target_type` 支持 `source` 和 `card`。查询一张卡的有效标签时，返回卡源标签与单卡标签的并集。标签模型支持父子层级；层级筛选与批量移动的交互缺口见第 11.1 节。

旗标属于单张 `Card`，每张卡最多一个。提供七种固定颜色，用户可以修改每种颜色的显示名称。每个非零旗标使用稳定的 `FlagDefinition` 版本化实体保存工作区显示名称，实体 ID 只由固定旗标编号确定；删除该实体即恢复编号显示，不改变卡片上的旗标值。旗标不影响排期和队列优先级。

### 3.9 `ReviewState`

`ReviewState` 只保存当前可变状态，历史事实由 `ReviewEvent` 保存。核心字段包括 `CardID`、`State`、`Due`、`LastReview`、`Stability`、`Difficulty`、`ElapsedDays`、`ScheduledDays`、`Reps`、`Lapses`、`Suspended`、`BuriedUntil`、`BuriedReason` 和 `StateRevisionID`。

`Suspended` 表示单卡无限期暂停；`BuriedUntil` 表示手动或兄弟卡规则造成的临时埋藏；当前会话跳过不写入 `ReviewState`，只写入 `StudySession` 的会话排除集合。

### 3.10 `ReviewEvent`

每次真实评分和手动排期操作都必须形成不可变事件。核心字段：

| 字段 | 含义 |
|---|---|
| `ID` | 全局唯一事件 ID，同时作为幂等键 |
| `CardID`、`SourceID` | 当前卡片和卡源 |
| `OriginCardID` | 迁移或导入前的原卡片 ID，可为空 |
| `Kind` | `Review`、`Reset`、`SetDue`、`Reschedule` 等 |
| `Rating` | 重来、困难、良好、简单；非评分事件为空 |
| `ReviewedAt` | 用户完成操作的时间 |
| `DurationMS` | 问题与答案阶段总耗时；旧日志缺失时为空 |
| `BeforeState`、`AfterState` | 精确排期状态快照 |
| `SchedulerVersion` | 产生结果的 FSRS 实现版本 |
| `PresetRevisionID` | 当时使用的排期预设修订 |
| `SessionID`、`ReviewSetID` | 所属会话和卡包，可为空 |
| `ReviewMode` | 正常复习或不影响排期的强化复习 |
| `DeviceID`、`WriterID`、`Sequence` | 设备归属、唯一写入者和因果排序信息 |

旧日志中不存在的字段必须保存为空或未知，不能伪造为零。

### 3.11 `ReviewSet`

“卡包”代替物理卡包。核心字段包括 `ID`、`Name`、`QueryAST`、`Order`、`NewLimit`、`ReviewLimit`、`DefaultReviewMode` 和 `RevisionID`。`Order` 使用受版本约束的结构化规范，支持按学习优先级后到期时间、纯到期时间、加入时间或会话种子稳定随机排序，不能保存任意 SQL。

手动加入和手动排除分别保存为独立的 `ReviewSetMembership` 实体，至少包含 `ReviewSetID`、`CardID`、`Mode`、`RevisionID` 和墓碑。这样可以增量同步和合并单个成员关系，避免每次变更都重写一个不断增长的卡片 ID 数组。用户选择恢复自动成员关系时删除手动覆盖并写入墓碑，使卡片重新由动态查询决定，同时阻止旧设备复活已清除的关系。卡包可以由动态查询、手动加入和手动排除共同组成；排除优先于动态命中和手动加入。同一卡片可以属于多个卡包，但始终共享同一份 `ReviewState`。删除卡包只删除查询和成员关系，不删除卡片、排期或历史。

卡包启动时可以选择：

- 正常复习：评分更新正常 FSRS 排期。
- 强化复习：记录练习事件和耗时，但不改变正常 FSRS 排期。

## 4. 卡片生成与渲染

### 4.1 统一生成与协调

卡片生成器根据 `CardSource`、启用的 `CardTemplate` 和源类型数据枚举变体。生成结果以 `(SourceID, TemplateID, VariantKey)` 与现有卡片进行协调：

- 仍存在的变体沿用原 `CardID` 和 `ReviewState`。
- 新变体创建新的 `CardID` 和新卡状态。
- 暂时关闭的变体进入 `DisabledByTemplate`。
- 引用暂时缺失的变体进入 `Orphaned`。
- 明确删除的卡源或卡片写入墓碑并停止出卡，历史继续保留。

生成和协调必须在一个 SQLite 事务中完成，并由一个持久化变更记录描述，不能先删除再重建所有卡片。

高级内置卡源原地编辑后，稳定变体继续使用原 `CardID`、复习状态和历史；新生成变体继承卡源创建时的卡包归属，不继承之后的手动成员关系。

### 4.2 正向、反向与双向卡

普通问答卡源至少包含问题、答案和可选补充信息。正向和反向是两个独立模板或模板变体，各自生成一张 `Card`，拥有独立排期和历史。

反向卡不能简单交换最终渲染后的正反面。每个方向必须分别定义问题、答案、提示和补充信息，避免例句、解释或上下文出现在错误的一侧。

关闭某个方向只改变生成状态，不删除卡片。双向卡的两张卡属于兄弟卡，默认按排期预设埋藏到下一个复习日。

### 4.3 分组挖空

每个挖空拥有使用 Lute Node ID 格式生成的稳定 `OcclusionID`，可以属于一个或多个稳定的 `GroupID`。用户看到的 1、2、3 只是当前显示顺序，移动、插入、删除或重新排序其他分组不能改变已有卡片身份。

编辑时允许暂时保留空分组，以免移动最后一个挖空后分组被静默删除并触发重新编号。空分组不生成可复习卡片；重新分配挖空后沿用原 `GroupID` 和已有卡片排期。

必须支持：

- 同组多空：一个组中的多个位置在同一张卡中一起遮挡和揭示。
- 各组独立：每个组生成独立卡片，各自排期。
- 多组组合：一个卡片变体可以遮挡指定的多个组。
- 反转遮挡：只显示指定组并遮挡其他组。
- 一个挖空属于多个组：用于重叠记忆、表格和复杂映射。
- 当前卡源遮挡：上下文中的其他块不因当前卡片的挖空规则被遮挡。

普通编辑状态使用统一标记样式；进入制卡编辑或预览时显示分组编号和区分颜色。

分组身份不能依赖文本偏移。文本挖空的稳定身份由 Lute 保存，扩展节点能力时先修改 `88250/lute` 并重新生成前端产物；不得手工修改 `app/stage/protyle/js/lute/lute.min.js`。

用户一次选择跨越多个相邻行级节点时必须生成一个 `OcclusionID`，不能因为粗体、斜体、行级代码或其他样式边界拆成多张卡。数学公式内部挖空需要保存稳定的公式子范围和原始公式校验信息；公式被编辑后优先通过结构锚点重新定位，无法唯一定位时将该挖空标记为待修复，不能悄悄遮挡错误内容。Markdown、`.sy` 和编辑器 DOM 往返后必须保持同一挖空身份。

当前分组界面处理文本标记和块范围；编辑既有行级分组时，只有显式选择纳入新增标记才扩充目标，保留原组选择和顺序。公式内部的结构锚点、子范围选择与失败修复尚未实现，整块公式遮挡不代表已经支持公式内部挖空。

### 4.4 有序多空

有序多空同时支持两种模型：

- 单卡逐步揭示：一个 `CardID`，包含多个稳定 `StepID`；逐步回答并在全部步骤完成后统一评分。
- 递进式多卡：每个步骤生成独立 `CardID`，前面步骤可以作为后续步骤上下文，各自排期。

`StepID` 是身份，`DisplayOrder` 是顺序。重新排序步骤不改变卡片身份。每一步可以包含多个挖空、独立提示、输入答案规则和揭示方式。

单卡逐步揭示可以记录每一步的正误和耗时用于分析，但只产生一次最终 FSRS 评分。递进式多卡应用兄弟卡埋藏规则。

当前已支持两种出卡模型，独立的步骤重排界面仍待补齐；已有分组排序不能代替步骤编辑。

### 4.5 图片遮挡

图片遮挡至少支持矩形、椭圆和多边形区域，并允许多个形状组成一个稳定遮挡组。必须提供：

- 全部遮挡、回答一个：正面遮挡全部区域，当前目标在答案阶段揭示。
- 只遮挡当前区域：正面只遮挡当前目标，其他区域可见。

图片资源保持普通资源引用，遮挡几何数据保存在卡源结构中。图片尺寸、裁剪或显示缩放不能改变遮挡区域的逻辑身份。

### 4.6 输入答案

模板可以配置大小写、前后空白、内部空白、标点、音调符号和模糊匹配规则，并支持多个可接受答案。插件可以注册特殊答案检查器。

答案检查只给出正确性、差异和建议评分，最终仍由用户选择重来、困难、良好或简单。可以配置答对后自动采用默认评分，但必须允许用户撤销。

当前已支持多个答案、标准化与模糊匹配；完整配置入口和可选自动评分尚未完成。

### 4.7 选择题

选择题支持单选、多选、固定选项、选项随机排序、固定干扰项、从指定查询范围动态抽取干扰项和答案解析。动态干扰项的实际选项必须记录到当前会话，保证翻面、撤销和复习日志一致。

当前动态干扰项可设置开关和数量，新建时范围默认匹配全部，编辑时保留原查询；查询范围的编辑入口仍待补齐。

### 4.8 多行卡、媒体与 TTS

多行卡可以一次显示全部答案或逐项揭示。卡片字段支持图片、音频、录音和其他现有富媒体引用。模板可以分别配置正面和背面的 TTS 语言、语速、字段范围和自动播放行为。

TTS 与媒体播放已经可用，正反面分别配置等模板设置交互仍待补齐。

### 4.9 声明式模板

内置和用户模板使用声明式字段引用、条件判断、循环和受控组件，不执行任意 JavaScript。样式使用作用域 CSS，必须经过解析和限制，不能影响应用外层 DOM。

模板渲染输入由卡源字段、当前卡片变体、上下文和复习会话组成。渲染结果是缓存，不是权威数据。

### 4.10 上下文与答案保护

模板可以选择不显示上下文，或显示文档标题、面包屑、祖先块、相邻块和显式 `context` 引用。上下文渲染必须执行答案泄露检查，例如隐藏包含当前答案的祖先背面、其他挖空目标或显式标记为敏感的字段。

上下文只负责提示，不改变卡片身份和排期。

### 4.11 复习中编辑

复习界面允许直接编辑关联块。保存后当前卡片和所有兄弟卡重新渲染，排期不自动重置。用户可以显式重置单卡或整个卡源的排期。

当必需引用暂时找不到时，卡源进入 `Orphaned` 并停止出卡。块通过同步、撤销或历史恢复重新出现后，卡源自动恢复原 `CardID`、排期和历史。不能使用缓存内容继续复习缺失卡源。

### 4.12 卡源配置历史与文档历史

接口请求、返回值和重试约束见 [卡源配置历史接口](FLASHCARD-HISTORY-API.md)。

闪卡管理的单卡菜单分别提供「复习历史」「卡源配置历史」和「文件历史」。按卡源分组时，卡源行也提供配置历史入口。配置历史分页列出保留的卡源修订，并将所选版本的生成配置、方向和有序块引用与当前版本并排展示；各引用可打开对应文档的文件历史，引用已经缺失时可进入全局历史查找文档。这里显示的文档位置属于当前可访问的文档，不是历史正文预览。

恢复配置在同一权威批次中写入新的卡源修订、引用变更及生成卡片变更，不改写旧修订。稳定变体沿用原卡片身份、旗标、单卡预设和复习状态；当前卡源的排期预设、学习优先级及删除／失效状态保持不变，恢复配置不会自动恢复已软删除的卡源。文档正文、图片文件、共享模板、标签和卡包成员关系不参与回退，题面和答案应从文档历史恢复。

历史引用沿卡源修订的父链及操作批次重建，不使用设备时间猜测引用版本；无法唯一还原引用时返回错误。恢复必须提供当前预期修订，拒绝过期请求、未解决的相关实体冲突、跨卡源修订、插件数据和不兼容的卡源模式。恢复前检查块引用、加密笔记本边界、行级挖空标记和图片所属块；正文或标记已经缺失时先恢复文档。现有权威数据格式保持不变，配置历史可随投影重建恢复。

若插件或底层实体接口曾绕过卡源操作单独修改引用，旧数据没有记录引用与卡源版本之间的因果边界，此时拒绝推断配置版本的完整引用，仍可使用单卡菜单中的文件历史入口。此入口不承诺还原任意时刻完整的卡片正反面，也不改变文档历史的生成频率和保留期限。

## 5. 复习会话、排期与统计

### 5.1 状态与管理操作

以下状态必须严格区分：

| 操作或状态 | 持久化范围 | 对排期的影响 |
|---|---|---|
| 跳过 | 当前 `StudySession` | 本轮不再出现，不修改正常排期 |
| 埋藏 | `ReviewState.BuriedUntil` | 在指定时间前不出卡，不改变 FSRS 状态 |
| 暂停 | `ReviewState.Suspended` | 无限期不进入正常队列，手动恢复后沿用原状态 |
| 范围暂停 | 文档范围学习策略 | 自动排除当前及以后新增的后代卡片，可被显式覆盖 |
| 模板关闭 | `Card.GenerationStatus` | 不出卡，重新启用后恢复原卡片 |
| 卡源缺失 | `CardSource.Status=Orphaned` | 不出卡，引用恢复后自动恢复 |
| 删除 | 墓碑 | 不出卡，保留历史；物理清理依赖后续安全压缩协议 |

删除卡片、卡源或卡包不得默认删除 `ReviewEvent`。全局统计继续包含带墓碑卡片的历史，按当前卡片查询时默认排除已删除内容。当前不提供物理清除历史。未来清理必须先具备清除墓碑、安全传播和压缩协议，不能仅从本地索引删除事件。

### 5.2 排期预设与每日额度

排期只使用 FSRS。排期预设至少保存 FSRS 参数、目标保留率、最大间隔、每日新卡与复习卡限制、兄弟新卡埋藏、兄弟复习卡埋藏、疑难卡阈值和疑难卡处理方式。

卡源保存默认排期预设，单卡可以覆盖。创建后不会因为移动文档、切换卡包或从不同入口复习而自动改变排期预设。用户可以通过管理界面或查询结果批量重新分配。

文档和笔记本的 `StudyPolicy.DefaultPresetID` 保存制卡默认值。新卡源按显式预设、最近的非空文档范围默认值、笔记本默认值、工作区初始预设依次选择，并将结果固化到 `CardSource.DefaultPresetID`。清空某级默认值表示继承上级。快速制卡、普通问答、高级卡和旧制卡兼容入口使用同一规则；迁移和 Anki 导入保留各自原有映射，不根据当前位置重新分配。卡源默认值可单独修改，已有单卡覆盖继续优先，新生成的兄弟卡沿用卡源默认值。省略新字段的旧策略更新请求保留已配置的默认预设。

范围优先级允许空值表示继承，显式 `unset` 仍表示覆盖为未设置；默认预设和优先级分别寻找最近的非空规则。配置制卡默认值不会隐式取消祖先文档或笔记本的暂停策略。

预设的每日新卡与复习卡上限在同一工作区内跨卡包、文档入口和会话共享，零表示不引入该类卡。按当天每张卡第一次有效正常评分的原状态及事件对应的预设计算用量，同卡当日后续复习不重复占用额度，强化复习不占用正常额度，撤销评分后重新计算。卡包和会话上限继续约束本轮队列。启动会话和正式评分接受本地日历的 `reviewDayStart`、`reviewDayEnd` 毫秒边界，兼容夏令时的 23／25 小时日；未提供时使用内核所在时区。队列读取和评分写入均复核额度，避免预先打开多个会话绕过上限。

范围默认预设和会话日界均为可选权威字段，保留缺少这些字段的已有 v2 记录读取。投影升级通过已验证的权威批次和快照重建，不修改或删除旧权威记录及迁移备份。

### 5.3 学习优先级

学习优先级固定为：

1. 考试
2. 正在学习
3. 保持记忆
4. 暂停
5. 未设置

学习优先级只影响队列选择和顺序，不改写 FSRS 到期时间。“考试”不包含自动备考计划，底层可以预留可空的目标日期字段。

优先级解析顺序为单卡显式覆盖、卡源显式覆盖、主引用所在最近文档范围规则、未设置。文档范围的“暂停复习”使用同一策略系统实现，可自动作用于以后新增的后代卡片；单卡或卡源显式优先级可以覆盖范围规则。

### 5.4 FSRS 与历史兼容

新版内核通过 `go-fsrs` 计算排期，输入为当前状态、评分、时间和排期预设，输出为新状态及转换信息。SiYuan 负责事务、持久化、查询和同步；`riff` 的当前用途是旧格式与旧接口兼容。跨仓库职责见第 8.6 节。

正常评分启用 FSRS 短期学习，新卡的“重来”“困难”“良好”分别产生 1、5、10 分钟的学习间隔，后续学习和重学间隔由 FSRS 计算。评分预览与实际评分使用同一计算入口。每个事件的 `SchedulerInput.EnableShortTerm` 保存当时使用的参数；历史记录中的 `false` 继续使用按天排期实现，混合版本并发复习按各事件参数逐步重放，不重写原有排期或历史。

### 5.5 队列成员与短期重学

队列首先应用硬排除条件，包括删除、`Orphaned`、`DisabledByTemplate`、单卡暂停、范围暂停和未到期埋藏；随后应用卡包查询和手动成员；最后按学习优先级、到期状态、预设顺序和稳定排序键生成队列。

学习优先级顺序为考试、正在学习、保持记忆、未设置。暂停不参与正常队列，但用户可以在明确包含暂停卡的管理或专项复习入口中查看。

正常复习会话在创建时固定成员及普通卡片顺序。会话中评分产生的学习或重学卡片到期后，在当前卡片作答或跳过完成时优先再次出现，不打断作答；不自动纳入新建卡片、会话开始时未选中的卡片或之后的卡包成员变化。普通卡片耗尽但还有待到期学习卡时，显示倒计时，到期自动继续，并允许主动结束或撤销上次评分。强化复习仍保持每张卡片一次。重复评分分别记录事件、次数和用时，同一卡片当日不重复占用每日卡片额度。

`/api/flashcard/getSessionQueue` 返回可选的 `repeatDue` 毫秒时间，表示本会话已评分卡片的下一次学习时间；持久化 `SessionCard` 保持 `reviewed`，读取队列不改写修订。回队资格要求会话卡片与当前排期来自同一权威操作批次，并复核当前可用性和每日额度。其他会话评分、手动改期、暂停、埋藏、删除和相关冲突不会被刷新队列绕过。`/api/flashcard/reviewCard` 接受 `stateRevisionID`，前端每次提交展示时的排期版本；同会话重复评分必须提供该版本，拒绝提前评分、过期请求和重复点击。跳过已评分的学习卡只结束其本会话回队资格，不修改排期。现有实体与事件格式保持不变，回队资格可以随投影重建恢复。

### 5.6 临时子集与排序

管理界面发起的子集学习复用 `startSession` 的 `reviewSetIDs`、`query` 和 `cardIDs`：卡包成员、当前筛选条件与显式选择取交集，未选择卡片时只省略 `cardIDs`，不丢弃其余范围。空的显式选择不能退化为全局复习。选中卡片的临时排序只生成候选 ID 顺序，不写回卡包排序、全局学习优先级或到期时间；队列资格和同会话重学仍遵循第 5.5、8.3 节。

正常复习继续使用工作区会话限额和共享的每日预设额度。整个筛选范围的强化复习沿用工作区会话限额；显式选中的强化复习通过前端内部 `practiceLimit` 将本次 `newLimit`、`reviewLimit` 设为候选数量，覆盖全部仍符合资格的选择。该参数仅在强化模式生效，不修改每日设置，也不作为新的内核接口字段或插件公开参数。暂停、埋藏、范围暂停、来源失效及访问边界继续由内核检查。

### 5.7 当轮薄弱练习

薄弱卡片范围由当前会话在内存中记录的最后一次成功评分派生：`again` 或 `hard` 纳入，后续 `good` 或 `easy` 移出；撤销恢复上一次判断，撤销首次评分则移除该判断。只从当前队列中状态为已评分且生成状态有效的卡片取候选，跳过和未评分卡不加入。失败请求不改变范围。用户选择再次练习后，先成功结束原会话，再以薄弱卡片 ID 创建独立强化会话，重新检查可访问性和学习资格；新会话记录自己的练习事件和耗时，不改写正常 FSRS 排期。

每轮强化会话仍只处理每张卡一次，结束后可以再次主动选择薄弱范围。关闭会话即释放本轮临时判断，不维护持久化的最终演练队列，也不替代正常复习中的 FSRS 短期学习步骤。

### 5.8 兄弟卡埋藏

同一 `CardSource` 生成的卡片均为兄弟卡。排期预设分别控制兄弟新卡和兄弟复习卡是否埋藏，默认埋藏到下一个复习日。

新卡和复习卡的分类取自被埋藏的兄弟卡自身状态，不取决于刚刚评分的卡片属于哪一类。关闭某一类兄弟埋藏只影响该类卡片，不改变另一类规则。

兄弟埋藏是队列状态，不修改 FSRS 到期时间。用户可以在会话中取消埋藏或通过专项复习显式包含。

### 5.9 疑难卡

排期预设可配置遗忘次数阈值和处理方式，包括添加疑难卡标签、显示提示、暂停或继续复习。默认行为是添加标签并提示，不自动暂停。

自动添加的标签必须使用稳定标签 ID，用户重命名标签后规则继续有效。

### 5.10 多设备并发复习

每个复习事件记录它基于的状态修订、评分时间、完整排期输入、FSRS 实现版本和实际参数。正常因果链直接采用并校验事件中的 `AfterState`；基于同一旧状态产生的并发事件全部保留，并按 `ReviewedAt`、`WriterID`、`Sequence` 和事件 ID 的稳定顺序从共同祖先重新计算当前状态，同时在事件元数据中标记并发。任何事件都不能因最后写入覆盖而从历史中消失。

内核必须保留所有已写入 `SchedulerVersion` 所需的兼容重放实现，不能用当前 FSRS 版本直接重放旧事件。并发消解完成后写入具有确定性 ID 的 `ReviewConflictResolved` 事件，其中保存参与事件 ID、共同祖先、算法版本和最终状态；其他设备计算出相同结果时视为同一事件。缺少兼容实现或参数时应隔离该冲突并保持最后一个已验证状态，不能猜测排期。

### 5.11 统计

统计支持全局、任意卡包、任意结构化查询和单卡范围，并提供今天、最近周期、全部历史和自定义时间范围。

至少包括：

- 历史每日、每周和每月复习次数与独立卡片数。
- 未来到期预测、逾期数量和预计每日负荷。
- 新卡、学习、复习、重学、暂停、埋藏、关闭、孤立和已删除卡片数量。
- 重来、困难、良好和简单分布。
- 正确率、真实保留率和遗忘次数。
- 总复习耗时、单卡平均耗时和时段表现。
- 间隔分布。
- FSRS 稳定度、难度和可提取性分布。
- 疑难卡数量和处理结果。
- 单卡完整复习、重置、手动设置到期时间和排期转换历史。

删除卡片后的事件继续进入全局历史统计；按当前内容或当前卡片查询时默认排除墓碑。旧日志没有耗时等字段时界面显示未知，不按零参与平均值。

强化复习记录练习次数和耗时，不计入正常排期的遗忘量；重学只有实际增加遗忘次数时才进入遗忘统计。界面还需补齐的统计细项见第 11.1 节。

## 6. 存储、同步与恢复

当前数据同步以文件为单位处理变更，无法合并两台设备对同一个 SQLite 文件产生的事务。SQLite 主文件、WAL 和 SHM 也无法通过普通文件同步形成跨文件原子快照。每次复习都修改同一个数据库还会导致高频大文件同步和不可解释的冲突。

因此 SQLite 只承担本机事务、查询和统计；跨设备权威数据使用写入者隔离、带序列号和校验和的操作批次分段。

### 6.1 文件布局与格式声明

```text
data/storage/riff/
├── <deckID>.deck                 旧版卡包元数据
├── <deckID>.cards                旧版卡片和排期
├── logs/                         旧版复习日志
└── v2/
    ├── manifest.json             确定性格式和能力声明
    ├── writers/
    │   └── <writerID>/
    │       └── segments/         活动与已封存操作批次分段
    └── snapshots/
        └── <writerID>/           带高水位和校验和的不可变加速快照

temp/
└── flashcards.db                 可删除、可重建的本地 SQLite 数据库
```

`manifest.json` 至少包含 `formatVersion`、最低兼容客户端版本、编码规范和数据能力标志。它使用规范化 JSON 生成，同一格式版本在所有设备上必须得到完全相同的内容，不保存设备状态、迁移进度、高水位或更新时间，避免多设备重写同一同步文件。迁移状态、切换状态和能力升级分别使用操作批次中的不可变领域事件；不兼容格式使用新的主版本目录。

### 6.2 实体修订与操作批次

版本化实体记录不是同步 SQLite，也不是每次修改都复制整个闪卡库，而是把某个实体的每次有效变更追加为一条带父修订的记录。例如重命名卡包会产生一个新的 `ReviewSet` 修订，旧修订继续保留；加载时沿修订关系计算当前版本，并可在多设备并发时判断两次修改是先后发生还是来自同一个旧版本。卡片当前排期虽然投影在 SQLite 中，但其可恢复依据同样来自持久化修订和不可变复习事件。

每条实体修订至少包含：

```json
{
  "entityType": "cardSource",
  "entityID": "source-id",
  "revisionID": "revision-id",
  "parentRevisionIDs": ["parent-revision-id"],
  "deviceID": "device-id",
  "writerID": "writer-id",
  "sequence": 42,
  "updatedAt": 1786431600000,
  "deleted": false,
  "payload": {}
}
```

`revisionID` 和事件 ID 全局唯一，`parentRevisionIDs` 描述因果关系，`deleted` 是防止旧设备复活已删除实体的墓碑。标签分配、卡包成员和其他集合关系使用独立实体修订，不能把整个集合放入父实体后进行最后写入覆盖；标量字段发生并发修改时使用稳定冲突规则并保留冲突信息，不能静默丢弃整个实体。

实体修订、复习事件、迁移记录和其他领域事件统一封装在 `OperationBatch` 中。一个批次包含 `operationID`、`batchID`、`WriterID`、连续序列号和一组有序记录；同一次用户操作产生的不同记录必须位于同一批次并由一个分段写入原子持久化，不能先写实体目录再写事件目录。SQLite 也以整个批次为事务应用。

### 6.3 写入者与分段

每个内核运行实例创建全局唯一的 `WriterID`，只写自己的活动分段。`WriterID` 由安装设备 ID 和随机写入时期共同组成，不能只使用可能随工作空间或系统镜像被复制的设备 ID。活动分段使用安全写入和完整校验，达到大小或批次数量阈值后封存为不可变文件。同步只在文件级传输，不需要合并两个写入实例修改的同一活动文件。

具体阈值由实现阶段基准测试决定，不属于产品行为。分段文件名包含 `WriterID`、起止序列号和不可复用的分段 ID，分段内容包含记录数、内容校验和和格式版本。活动分段只能由创建它的当前进程修改；进程重启、检测到写入者重复或同步收到同名异内容文件时立即封存或隔离旧分段，并使用新的 `WriterID`，不能继续覆盖。

### 6.4 写事务与幂等

每次创建、编辑、复习或管理操作执行以下顺序：

1. 前端或调用方生成或提交幂等 `operationID`。
2. 内核验证权限、实体修订和加密笔记本边界。
3. 内核将实体修订或事件安全写入当前 `WriterID` 的 v2 活动分段。
4. 内核在 SQLite 事务中应用记录，并把 `operationID` 写入 `applied_changes`。
5. 内核完成缓存和队列更新后返回成功。

如果步骤 3 完成后进程崩溃，重启时会从权威记录补写 SQLite。如果调用方因超时重试，相同 `operationID` 不会重复创建卡片或复习事件。

仅存在于 `temp/flashcards.db` 的 outbox 不能作为未同步操作的唯一副本。

### 6.5 SQLite 投影表

所有具体业务表之前先建立通用摄取层：`operation_batches` 保存物理批次，`entity_revisions` 和 `revision_parents` 保存修订图，`events` 保存不可变领域事件，`applied_changes` 提供操作幂等，`writer_sequences` 和 `writer_high_watermarks` 保存连续重放位置，`entities` 保存通用当前实体，`entity_conflicts` 保存未消解分支。具体业务表是由该通用层派生的查询投影，不能反过来成为唯一权威数据。

| 表 | 责任 |
|---|---|
| `card_schemas` | 卡片模式当前状态 |
| `card_templates` | 模板当前状态 |
| `card_sources` | 卡源当前状态 |
| `card_source_refs` | 卡源实体引用 |
| `cards` | 生成卡当前状态 |
| `review_states` | FSRS 当前状态 |
| `review_events` | 可查询的完整复习历史 |
| `tags` | 闪卡标签树 |
| `tag_assignments` | 卡源和单卡标签关系 |
| `review_sets` | 卡包定义 |
| `review_set_memberships` | 可独立合并的手动加入和排除实体 |
| `scheduler_presets` | FSRS 排期预设 |
| `study_policies` | 文档或笔记本范围的优先级和暂停规则 |
| `block_metadata` | 从块树重建的主引用笔记本、文档和路径缓存，不参与同步 |
| `source_availability` | 从必需块引用重建的卡源当前可用性，不参与同步 |
| `study_sessions` | 复习会话 |
| `session_cards` | 会话内顺序、跳过和动态选项 |
| `applied_changes` | 已应用修订与事件的幂等集合 |
| `entity_conflicts` | 尚未自动消解的实体冲突 |
| `projection_meta` | 模式版本、快照 ID、写入者高水位和旧数据水位 |

### 6.6 索引、派生缓存与查询一致性

至少需要：

```text
UNIQUE cards(source_id, template_id, variant_key)
UNIQUE applied_changes(operation_id)
UNIQUE review_set_memberships(review_set_id, card_id)
INDEX cards(generation_status, source_id)
INDEX review_states(suspended, buried_until, due)
INDEX card_source_refs(entity_type, entity_id)
INDEX tag_assignments(tag_id, target_type, target_id)
INDEX review_events(card_id, reviewed_at)
INDEX review_events(reviewed_at)
INDEX review_events(session_id)
INDEX review_set_memberships(review_set_id, mode, card_id)
INDEX block_metadata(notebook_id, path, block_id)
```

卡片正文以 `.sy` 为权威来源。管理摘要、`block_metadata` 位置数据、`block_search_content` 文本与 FTS 索引、`source_availability` 可用性都是可重建缓存。启用 `fts5` 的发布内核使用 trigram 索引执行内容包含查询；其他构建保持语义相同的回退查询。

查询和实体投影遵循以下规则：

| 场景 | 一致性规则 |
|---|---|
| 位置与可用性 | 查询或恢复会话前刷新主引用位置和可用性；只读查询可派生孤立状态，但不因此写同步日志。可写流程协调卡源与卡片，块恢复后重新激活同一身份和排期 |
| 会话结束 | 仍处于排队或已展示状态的会话卡在同一操作中持久化为跳过，不在已完成会话中遗留待处理卡片 |
| 卡包分页 | 先完整合并动态查询、手动加入和排除，再按稳定卡片 ID 应用 `offset`、`limit`，同时返回未分页总数 |
| 范围策略 | 按 `ScopeType`、`ScopeID` 查找与保存，使用由范围确定的稳定实体 ID，使多端并发创建形成可检测修订冲突 |
| 标签重名 | 本地写入前拒绝同级重名；SQLite 不使用会阻断同步重放的同名唯一约束，离线重名保留双方实体供后续解决 |

### 6.7 快照与完整历史

快照保存当前实体、当前排期状态、统计汇总、每个写入者已包含的最高序列号和数据校验和。`block_metadata`、`block_search_content`、对应 FTS 索引和 `source_availability` 属于设备本地可重建缓存，生成快照时必须清空，恢复后再从当前块树补充，避免把创建快照设备上的旧位置、正文或可用性带到另一设备。快照名称包含创建者 `WriterID` 和内容哈希，写入后不可修改。多个设备生成的快照可以并存；加载器选择覆盖高水位最大且校验通过的快照，并重放其余记录。快照只用于加速，不替代完整复习历史。

快照损坏时应回退到更早快照；没有可用快照时从全部实体修订和事件重建。恢复前必须确认快照中的每个批次及其校验和都已存在于本机权威分段中，快照先于对应分段同步到本机时不能替代尚未到达的历史。初版不自动删除同步目录中的快照、分段、墓碑和迁移记录；以后只有在确认新快照完整、所有已知写入者越过高水位且清除墓碑安全传播后才允许通过单独设计的压缩协议回收。

### 6.8 同步后的加载

当前同步逻辑监听 `/storage/riff/` 变更。同步合并完成后，v2 存储重新校验格式清单、导入新增分段、幂等推进 SQLite 投影，并检查旧格式是否越过迁移激活水位；该流程不再重新加载旧卡包作为正常运行时数据。

旧客户端会忽略 `v2` 子目录，但无法理解新版卡片。不可变激活记录启用 v2 后，参与闪卡复习的所有设备必须升级到最低兼容版本；新版不长期双写旧格式。

### 6.9 投影重建

发现 `flashcards.db` 不存在、损坏或模式不兼容时：

1. 锁定闪卡写操作并创建 `temp/flashcards.rebuild.db`。
2. 创建最新 SQLite 表结构。
3. 读取最近一个校验通过的快照。
4. 根据快照写入者高水位重放后续实体修订和事件。
5. 导入完整复习事件索引；数据量较大时可以先恢复当前排期，再后台补建历史统计索引。
6. 从 `.sy` 和块树解析 `CardSourceRef`，重新协调卡片变体和可重建摘要。
7. 校验外键、唯一约束、写入者序列、事件数量和校验和。
8. 校验成功后替换正式 `flashcards.db` 并恢复写操作。

重建中断后可以继续或安全地从头开始。块暂时未同步到本机时只标记 `Orphaned`，不能删除卡片。

## 7. 旧数据迁移与 Anki 导入

### 7.1 旧格式映射

| 旧数据 | 新结构 |
|---|---|
| `<deckID>.deck` | `ReviewSet` 和必要的显示元数据 |
| `<deckID>.cards` | `CardSource`、`Card` 和 `ReviewState` |
| `logs/<yyyyMM>.msgpack` | `ReviewEvent` |
| `custom-riff-decks` | 卡包静态成员关系 |
| 块 ID、标记、列表和标题结构 | 默认卡源引用、内置块闪卡模板和自动答案配置 |

旧版快速卡自动原位升级为内置块闪卡，保留原 `CardID`、复习状态和历史，不需要用户手工转换。内部继续使用稳定变体键 `legacy-quick` 计算既有卡片身份，该标识只用于数据兼容，不在界面显示，也不代表仍在使用旧版快速卡实现。

### 7.2 自动迁移与旧设备分歧

内核启动时自动执行以下流程。迁移预览与显式激活 API 保留用于诊断、测试和处理 `LegacyDiverged`，不作为正常首次升级必须完成的手工步骤。

1. 等待同步存储空闲并锁定旧版与新版闪卡写操作。
2. 扫描全部 `.deck`、`.cards`、旧日志和相关块属性，生成输入清单与校验和。
3. 在 `temp` 中生成确定性的迁移记录和候选 SQLite 投影。
4. 校验卡片映射、排期、日志、块引用和卡包成员关系。
5. 将验证后的记录安全写入 `data/storage/riff/v2/`，最后写入不可变迁移激活记录。
6. 从 v2 数据重建正式 SQLite，再开放新版接口。

第 5 步的完成状态写入类型为 `MigrationActivated` 的不可变领域事件，不能修改共享 `manifest.json`。迁移投影依次处于 `Preparing`、`Active` 或 `LegacyDiverged`；只有全部输入校验和、实体映射、事件数量和 SQLite 重建均通过后才能由不可变激活记录进入 `Active`。

迁移 ID 必须由固定命名空间、旧格式版本、旧卡包 ID、旧卡片 ID、块 ID 和旧日志 ID 的规范化字节计算，确保两台设备针对同一旧数据迁移时不会生成两套卡源和事件。字段缺失和排序规则也必须写入迁移规范，不能依赖 Go map 遍历、文件读取顺序或本地时区。迁移中断后重新执行必须得到相同 ID 和相同记录内容。

每条旧复习事件的 ID 必须独立于整次迁移 ID，只由旧格式版本、日志文件相对路径、稳定记录位置、旧日志 ID 和旧卡 ID 确定。旧设备在原日志文件末尾追加记录并触发增量迁移时，既有事件保持同一身份并跳过，新追加的事件才写入新批次。

激活记录保存全部旧文件的路径、大小、修改时间和内容校验和。新版不会双写旧格式，但每次同步后都要检查旧文件是否越过激活水位；这通常表示仍有未升级设备执行了制卡或复习。检测到后进入 `LegacyDiverged`，暂停新的闪卡写操作并提供增量迁移预览，确认旧卡片、排期和日志全部映射后写入新的不可变激活记录。仅提示“请升级设备”而继续忽略旧写入会造成数据丢失，不可接受。

首次迁移存在无法映射的旧记录时，继续使用旧格式并报告错误；一旦进入 `Active` 或 `LegacyDiverged`，或已发现不兼容的 v2 清单，运行时不得回退到旧卡包写入。激活后的快速制卡、管理、复习、文档与笔记本范围入口及旧兼容接口都使用 v2。

### 7.3 同块重复卡与历史占位

同一个块可能在多个旧卡包中拥有多张独立排期。迁移时自动合并为同一个卡源和同一张等价卡片：

- 当前排期采用最近复习卡片的 `ReviewState`。
- 若最后复习时间相同，优先采用已有非新卡状态，再采用默认卡包中的卡，最后按旧 `CardID` 稳定排序选取。
- 选中的旧 `CardID` 作为新版主卡 ID，其他旧 `CardID` 写入别名映射。
- 所有旧卡的复习日志都映射到主卡并保留 `OriginCardID`，用于统计和审计，但不重新计算当前排期。
- 主卡加入所有相关旧卡包生成的卡包。
- 所有迁移前状态写入迁移审计记录，出现问题时可以人工恢复。

旧复习日志可能引用已经从当前 `.cards` 文件移除的卡片，而旧日志本身不保存块 ID 或卡包 ID。迁移时必须为每个此类旧 `CardID` 建立确定性的、不可复习的历史占位卡源和卡片，并用只读别名保存旧卡 ID 映射；这些占位实体不进入管理查询、复习队列或卡包，但对应日志仍完整进入全局历史统计。不能把正常的旧卡删除历史计为未映射日志并阻断迁移。

迁移验收不能再要求新旧卡片数量相等，而应要求每个旧 `CardID` 都存在主卡或别名映射、每条旧日志都被导入、每个旧卡包成员关系都被保留。

### 7.4 迁移备份保留

旧版 `.deck`、`.cards`、`logs/` 和相关块属性永不自动删除。初版也不提供会同步删除这些备份的清理入口，避免未升级设备、延迟同步设备或工作空间恢复操作把删除误判为新的旧格式分歧；以后只有在独立清理协议能够确认所有参与设备已经越过迁移水位后才提供显式清理。

新版启用后不再把新操作写回旧格式。旧数据只作为迁移备份，不能继续参与队列和统计。

### 7.5 Anki 类型映射

| Anki | SiYuan v2 |
|---|---|
| Note Type | `CardSchema` |
| Note | `CardSource` |
| Field | 目标笔记本中的字段块及带 `FieldID` 的 `CardSourceRef` |
| Card Type | `CardTemplate` |
| Card | `Card` |
| Tag | 卡源标签 |
| Flag | 单卡旗标 |
| Deck | `ReviewSet` |
| Revlog | `ReviewEvent` |
| Media | SiYuan 资源引用 |

普通卡、正反向卡、可选反向卡、输入答案、挖空和图片遮挡应尽可能转换为对应内置模式。经过过滤的字段引用、条件和 CSS 转为声明式模板；无法安全转换的模板保留原始导入数据，并生成安全文本回退和导入报告。

### 7.6 内容、媒体与重复导入

导入前必须选择一个普通笔记本作为目标。每条 Anki Note 在该笔记本中生成一个稳定的卡源容器，每个字段生成独立的可编辑字段块；数据量较大时按原卡包和固定数量拆分文档。`CardSourceRef.FieldID` 将字段定义映射到这些块，模板只能通过稳定字段 ID 取值，不能依赖字段名称或子块位置。

Anki HTML 经过安全转换后写入 `.sy`，媒体写入目标笔记本可访问的资源目录，原 Note GUID、字段序号和媒体映射写入导入审计数据。卡源容器和字段块同时保存稳定的 Anki 来源与字段序号属性；即使进程在 `.sy` 已写入但 v2 元数据尚未提交时崩溃，重试也要先按这些属性找回并验证容器从属关系，再复用原块。重复导入同一集合时根据集合标识、Note GUID 和 Card ordinal 更新既有卡源与卡片，不能重复创建内容。这样导入内容仍然遵循“`.sy` 是正文权威来源”，可以使用 SiYuan 的搜索、编辑、引用和上下文能力；不能一部分字段只存在于 `flashcards.db` 或同步日志中。

### 7.7 SM-2 到 FSRS 的过渡

SiYuan 不内置 SM-2。导入 SM-2 卡片时默认保留当前到期时间、间隔和完整可解析历史，并生成兼容的初始 FSRS 状态；不在导入时强制改变用户近期复习量。

导入完成后提供“根据历史重新计算 FSRS 排期”的可选批量操作。用户未选择时，卡片在下一次正常复习后自然进入完整 FSRS 状态。

### 7.8 导入边界

不提供 `.apkg` 导出，不承诺兼容 Anki 插件脚本或任意 JavaScript。导入器必须生成逐项报告，区分完整转换、安全降级、未知字段和无法导入的数据。

## 8. API、插件与跨仓库职责

### 8.1 API 约束

- 新 API 以 `CardID`、`SourceID`、`TemplateID` 和 `ReviewSetID` 为主要标识，不再用 `BlockID` 代替卡片身份。
- 所有修改接口接受 `operationID` 和可选的预期 `revisionID`，支持幂等和乐观并发控制。
- 批量操作可以接受明确 ID 集合或结构化查询快照，不能接受任意 SQL。
- 查询、卡包、管理界面和统计共用一套结构化查询 AST。
- 返回结果必须区分卡源字段、单卡字段、继承标签、有效排期预设和有效学习优先级。
- 加密笔记本目标在所有 HTTP API、插件 API、MCP、事务和导入入口中统一返回明确的不支持错误。

### 8.2 能力分组

接口按下列能力组织。具体路由、默认值、字段约束和兼容要求以 `kernel/apicontract/` 中的维护声明为准；本表不代替接口契约。

| 能力 | 操作 |
|---|---|
| 模式与模板 | 创建、读取、更新、删除、预览、复制、启用和关闭 |
| 卡源 | 创建、读取、更新、删除、恢复、协调卡片和解析引用 |
| 卡片 | 查询、批量更新、暂停、恢复、埋藏、取消埋藏、重置和设置到期时间 |
| 复习 | 获取队列、开始会话、跳过、提交评分、撤销评分和结束会话 |
| 标签与旗标 | 树管理、批量分配、重命名、移动和筛选 |
| 卡包 | 创建、查询、批量摘要、手动批量加入、排除、预览成员和启动复习 |
| 排期预设 | 创建、复制、分配、验证参数和批量重新排期 |
| 统计 | 总览、时间序列、未来到期、FSRS 指标、单卡历史和查询范围统计 |
| 导入 | 迁移预览、Anki 导入、进度、报告和取消 |

### 8.3 复习入口与范围参数

插件通过 `openTab` 打开新版复习页签，可以指定有序候选卡片、多个卡包或结构化查询。例如：

```ts
openTab({app, card: {
    type: "all",
    title: "自定义复习",
    cardIDs: ["卡片 C ID", "卡片 A ID", "卡片 B ID"],
    reviewMode: "normal",
}});

openTab({app, card: {
    type: "all",
    reviewSetIDs: ["历史卡包 ID", "语文卡包 ID", "数学卡包 ID"],
    reviewMode: "normal",
}});
```

| 参数 | 规则 |
|---|---|
| `cardIDs` | 使用新版卡片 ID，拒绝空数组和空 ID，重复 ID 按首次出现去重；不存在、已删除或不可访问的候选使请求失败，不扩展为全局复习 |
| `reviewSetIDs` | 非空卡包数组；各卡包先应用自己的动态查询、手动加入和排除，再取成员并集。一个卡包的排除不影响另一个卡包的纳入；无效或已删除卡包返回错误 |
| `card.query` | 接受版本为 1 的结构化查询 AST，与卡包并集、文档或笔记本范围及候选列表取交集 |
| `type / id / title` | 保持已有参数兼容；`type: "doc"` 或 `"notebook"` 时，`id` 指定的范围继续约束查询结果 |
| `reviewMode` | 正常模式选取新卡与到期卡，评分更新正常排期；强化模式允许未到期卡，记录练习但不修改正常排期 |

查询示例：`{version: 1, root: {operator: "predicate", field: "rootID", comparator: "in", value: ["历史文档 ID", "语文文档 ID", "数学文档 ID"]}}`。显式候选与所有范围取交集后，仍检查可用性、暂停、埋藏、学习优先级暂停和额度。筛选与限额后保留候选输入顺序，不追加列表外卡片；到期的同会话重学仍按第 5.5 节优先回队，兄弟埋藏、跳过和撤销沿用内置流程。

多卡包混排不合并各卡包的默认模式、排序和上限，而是使用显式复习模式、工作区队列上限及统一优先级／到期顺序；每张卡保留自己的排期预设和共享每日额度。接口不提供提前正常评分或按评分动态重排后续队列的能力。

内核 `/api/flashcard/startSession` 接受可选 `cardIDs` 和 `reviewSetIDs`；`reviewSetIDs` 与单个 `reviewSetID` 互斥，可以与 `query` 同用。成员在创建时冻结，卡包 ID 去重排序后保存用于审计和幂等校验；候选顺序保存在会话可选字段中，最终顺序保存在 `SessionCard.Sort` 中。重复操作必须携带相同的去重候选顺序，包括未入选卡片，否则返回幂等冲突。缺少这些可选字段的已有请求与会话保留原行为，投影重建保持已保存的顺序。

页签布局保存学习范围、模式与候选列表。恢复时重新检查资格并创建新会话，不复用旧队列与进度；新页签、右侧分屏和独立窗口采用相同转换。旧布局中的 `cardType / id / title` 转为新版参数，丢弃 `cardsData / index`。旧 `cardType: "all"` 配合非空 `id` 表示指定卡包，必须先按 `legacyDeckID` 或实体 ID 找到新版卡包，找不到时停止打开，不能扩大范围。

### 8.4 插件扩展与生命周期

插件扩展的设计范围包括：

- 卡源类型及其版本化数据验证器。
- 创建和编辑界面。
- 声明式或受控 DOM 渲染器。
- 答案检查器。
- 卡源到卡片变体的生成器。
- 管理界面附加列和结构化查询字段。
- 进入和离开复习、当前卡片变化、正反面切换、评分前后、撤销评分和会话结束等只读生命周期事件。

插件不能注册排期算法，所有卡片统一使用 FSRS。插件不能直接写 SQLite 或 v2 文件，只能通过内核 API 修改数据。

生命周期事件提供稳定 `CardID`、`SourceID`、会话、当前面、有效状态和本次操作信息，并遵守加密笔记本与权限过滤。评分前事件只能用于提示或发音等交互，不能阻塞、替换或篡改内核排期事务；需要评分或改期的插件必须调用正式 API。查询昨日逾期卡等需求通过结构化查询 API 实现，不增加只能服务单一插件的专用接口。

插件注册的 `CardSourceType` 数据必须声明插件名称、类型名称、数据版本和文本回退。卸载或缺少插件时保留卡源、卡片、排期、历史及原始版本化数据，显示安全的文本回退、类型名称和安装提示，不能删除或重写未知数据。

实现中的卡源注册入口为 `registerFlashcardType`；公开声明与示例的缺口在第 11.3 节核对。管理附加列、查询字段和其他扩展能力应通过维护声明表达，不能把本节的设计目标视为已经公开的插件接口。

### 8.5 旧接口适配

现有 `/api/riff` 接口在过渡期作为兼容适配层，只操作 v2 中可以明确映射的快速卡。旧 `blockIDs` 用于查找兼容卡片，不代替新版 `CardID`。适配层不再读写旧 `.deck` 和 `.cards`，并应返回废弃提示。无法明确指定单张卡的旧操作必须拒绝或要求调用方改用新 API，不能猜测目标。

### 8.6 跨仓库职责

| 仓库或依赖 | 当前职责 |
|---|---|
| `siyuan-note/siyuan` | 领域模型、v2 文件、SQLite 投影、迁移、同步协调、HTTP API、界面、统计、Anki 导入和插件接入 |
| `go-fsrs` | 新版排期计算；内核保存所用实现版本与输入，并负责历史兼容重放 |
| `siyuan-note/riff` | 旧卡包、卡片、日志和旧接口类型兼容；新版排期不依赖其物理卡包存储，也不以拆分该仓库作为上线前置条件 |
| `88250/lute` | 持久化文本挖空的稳定 `OcclusionID`、多 `GroupID` 和顺序信息，保证 Markdown、`.sy`、编辑器 DOM 与导出保真 |
| `petal` | 插件公开类型、常量、生命周期和 API 行为注释，与对应实现保持一致 |

Lute 的节点扩展先在上游实现并构建，再更新生成产物，不手工修改 `lute.min.js`。本地依赖替换只用于开发验证，不提交 `kernel/go.mod` 中的临时 `replace`。插件声明的使用示例放在 `plugin-sample`，不把 `petal/README.md` 扩展为功能说明。

## 9. 安全与性能

### 9.1 加密笔记本准入

加密笔记本继续不支持闪卡。以下入口必须统一拒绝加密笔记本目标：

- 快速制卡和高级制卡。
- 添加、删除和查询卡片。
- 复习队列和统计。
- Anki 导入目标选择。
- 插件 API、MCP 和事务操作。
- 文档范围学习策略和卡包静态成员。

v2 文件和 `flashcards.db` 中不得出现加密笔记本块 ID、卡片数量、标题、到期时间或其他元数据。迁移发现遗留加密笔记本卡片时不得导入，应隔离并生成明确报告。

创建加密笔记本不能导入闪卡。普通笔记本转换为加密笔记本时，转换流程必须扫描卡源主引用、全部辅助引用、卡包静态成员和范围策略；只要仍有关联闪卡就拒绝转换。物理清理尚未提供，不能引导用户通过本地删索引、软删除卡片或删除历史来绕过检查；未来的清理入口必须先满足第 11.4 节的协议要求。不能在转换后仅靠查询过滤，因为块 ID 和复习事实可能已经存在于全局 v2 记录及其同步历史中。

### 9.2 模板与插件隔离

声明式模板必须过滤 HTML、URL、媒体引用和 CSS，禁止脚本执行、全局样式污染和未授权网络访问。插件渲染继续受现有插件权限和生命周期约束。

### 9.3 文件完整性

所有 v2 分段和快照包含格式版本、长度和校验和。加载器先验证路径、文件名、大小上限和校验和，再反序列化，损坏文件不得部分应用。损坏快照可以回退到可用快照或完整权威分段；不兼容的格式清单或损坏的权威记录使当前存储停止写入并报告错误，原始记录和诊断信息继续保留。快照回退不能绕过权威记录的完整性检查。

### 9.4 性能要求

- 管理和队列查询必须分页，不能把全部块 DOM 或全部卡片一次返回前端。
- 到期查询、标签筛选、卡包查询和统计必须使用 SQLite 索引。
- 块正文按需加载，管理列表只使用可重建摘要。
- 复习事件按时间和卡片建立索引，长期历史按时间分区或等价方式优化。
- 同步后优先增量导入变化分段，只有数据库缺失、损坏或模式不兼容时执行全量重建。
- 快照、事件分段大小、SQLite WAL 参数和统计预聚合策略必须通过真实数据集基准测试确定。
- 至少覆盖十万张卡和百万级复习事件的数据规模测试。

## 10. 验收标准

验收按下列不变量和用户场景执行。单元测试、组件隔离测试、真实内核联调和多设备验收分别提供不同证据，不能相互替代。尚未完成的功能在实现后执行对应验收；发布前仍需运行的场景集中列在第 11.3 节。

### 10.1 领域模型

- 一份卡源生成正向和反向两张卡，两张卡的评分、到期时间和历史互不影响。
- 关闭并重新启用方向后恢复相同 `CardID` 和排期。
- 修改问题、答案、提示和上下文后不重置排期。
- 一个卡源关联多个块，一个块参与多个卡源时查询结果正确。

### 10.2 挖空与高级卡

- 同组多空一起遮挡，不同组生成独立卡。
- 同一挖空属于多个组时，各变体渲染正确。
- 插入、移动和重新编号分组不改变已有卡片身份。
- 一次选择跨越粗体、斜体等多个行级节点时仍只生成一个挖空；Markdown、`.sy` 和 DOM 往返后 ID 不变。
- 数学公式内部挖空可以稳定重定位；无法唯一重定位时进入待修复状态而不是遮挡错误内容。
- 单卡逐步揭示只产生一次评分，递进式多卡分别排期。
- 图片遮挡两种模式、形状分组和资源缩放后坐标正确。
- 输入答案标准化、模糊匹配、多个答案和插件检查器正确。
- 选择题随机化后翻面、撤销和日志使用同一组选项。

### 10.3 状态与队列

- 跳过、埋藏、暂停、范围暂停、模板关闭和孤立状态互不混淆。
- 兄弟新卡和兄弟复习卡分别遵循预设。
- 同源卡混合新卡、学习、复习和重学状态时，分别开启兄弟埋藏选项只影响对应类别。
- 卡源预设、单卡覆盖和文档移动符合持久分配规则。
- 空文档与空笔记本可先配置制卡默认预设，最近范围的默认预设与学习优先级分别继承；只设置预设不解除上级暂停。
- 多个卡包、会话和旧接口共享预设每日额度，撤销返还额度；同卡当日重复学习、强化复习不重复占用正常额度，夏令时和跨午夜仍按客户端日界计算。
- 正常复习更新 FSRS，强化复习不改变正常排期。
- 学习优先级只改变队列顺序，不修改到期时间。
- 临时子集保留卡包成员、文档或笔记本范围与查询条件的交集，跨窗口传递保持范围与模式，空显式选择不能扩展为全局复习。
- 临时排序不修改源列表或排期，数值相同的卡片保留顺序；显式强化选择覆盖合格候选，正常复习及整个筛选范围仍遵守各自限额。
- 薄弱范围只依据成功评分，重复学习后的最后评分及撤销正确更新范围；跳过、失效和未评分卡不加入，下一轮重新检查资格且不改变正常排期。

### 10.4 迁移与导入

- 迁移可中断、重试并得到相同实体和事件 ID。
- 每个旧 `CardID` 都有主卡或别名映射。
- 同块重复卡采用最近复习卡片状态，其他历史完整进入统计。
- 所有旧卡包生成卡包，成员关系完整。
- 旧日志缺失字段保持未知。
- 旧文件迁移后保持不变，除非用户显式清理。
- 激活后收到旧设备写入时进入 `LegacyDiverged`，完成增量迁移前不接受新的闪卡写操作。
- 同一 Anki 集合重复导入时更新原字段块、卡源和卡片，不重复创建内容或历史。

### 10.5 同步与恢复

- 两台设备修改不同实体可以自动合并。
- 同一实体并发修改不会静默丢失。
- 两个安装实例拥有相同设备 ID 时仍使用不同 `WriterID`，不会覆盖彼此的活动分段。
- 多设备生成的 `manifest.json` 字节完全一致，卡包不同成员的并发增删可以独立合并。
- 同一卡片离线并发复习后事件全部保留，当前状态确定一致。
- 不同 `SchedulerVersion` 的历史事件使用对应兼容实现重放，缺少实现时停止并报告而不是使用当前版本猜测。
- 重复同步和重复 API 请求不会生成重复事件。
- 删除 `temp` 后可以从 v2 和 `.sy` 完整恢复卡片、排期、标签、卡包和统计。
- 损坏最新快照时可以回退到旧快照和事件。
- 结构版本 5 的投影及快照可以从未修改的旧权威记录恢复到版本 6，卡源预设、原排期和完整复习事件保持不变。
- 创建卡源后修改预设与到期时间，再重试原创建请求，返回首次创建结果而不回滚当前配置；范围策略重试区分省略预设与显式修改预设。

### 10.6 安全隔离

- 所有闪卡入口拒绝加密笔记本块。
- v2 文件、SQLite、日志和错误信息不包含加密笔记本元数据。
- 恶意模板无法执行脚本、污染全局样式或读取未授权内容。
- 缺少插件时未知卡源数据保持原样。
- 普通笔记本存在关联闪卡时不能直接转换为加密笔记本。

### 10.7 桌面、独立窗口与移动端

- 桌面端和移动端均可创建、预览、分组、排序、复习和管理所有内置卡片类型。
- 管理界面卡源分组与扁平列表操作目标一致。
- 复习中编辑后当前卡和兄弟卡立即刷新。
- 既有行级分组卡源只有显式选择纳入新增标记时才扩充目标；原分组 ID、用户已经修改的组选择和排序保持不变。
- 管理与复习均可直接选择七色旗标或清除，重命名后显示同步刷新。
- 统计快速切换范围时只显示最新请求结果，未知耗时不显示为零，单卡历史可翻页查看全部记录。
- 管理界面的开始学习默认范围与勾选一致，当前筛选覆盖全部分页，切换范围时正确显示或隐藏排序，切换模式时说明同步更新。
- 结束页可再次练习薄弱卡片、撤销或结束；弹窗关闭后再开始下一轮，页签和独立窗口在原区域继续且不残留关闭监听，窄窗口及较长翻译文案无横向溢出。
- 新增快捷键时用户指南同步更新。
- 插件收到顺序稳定且经过权限过滤的复习生命周期事件，但不能从事件回调绕过评分 API 修改排期。
- 复习大纲覆盖长文档、无来源卡片、答案遮挡、快速换卡、请求失败重试及关闭会话；过期异步结果不写入新卡，组合快捷键不误触发评分。

### 11.2 性能与规模验证

- [ ] **建立可重复的大数据量基准**：至少覆盖十万张卡和百万级复习事件，记录管理筛选、卡包预览、开始会话、评分、全量历史统计、迁移和投影重建的耗时、峰值内存及磁盘占用，形成可重复执行的数据集和基准结果。当前回归测试不能替代第 9.4 节的规模验收。
- [ ] **优化队列与范围查询**：核查并优化读取完整候选卡片后在内存中筛选、排序和截断的路径，优先把范围过滤、排序和限制交给 SQLite，保持动态成员、手动纳入、排除项、每日额度和稳定排序语义一致。
- [ ] **优化统计与每日额度计算**：核查当前历史读取、卡片范围筛选和每日有效事件计算的成本，根据基准结果采用索引查询、数据库聚合或可重建预聚合；保留撤销、强化复习、未知旧字段和历史预设归属的准确性。
- [ ] **减少同步后的重复分段读取**：在已实现新增批次幂等摄取的基础上，补充变化分段识别，减少每次刷新重新扫描、读取全部分段及遍历全部批次的成本。保留首次加载、重建及异常情况下的完整校验，不把本地已摄取标记当作文件未被修改的证明。
- [ ] **验证同步加载与快照成本**：度量仅新增少量分段时的校验、导入和投影推进成本，以及冷启动、快照恢复和全量重建成本；根据结果调整现有分段大小、快照阈值、SQLite WAL 和统计缓存策略。优化不得省略权威数据完整性校验。

- [ ] **子集学习与薄弱练习整体验收**：连接运行内核验证跨分页筛选、本页选择、正常与强化模式的额度、同会话重学后的薄弱范围、撤销、连续练习和关闭。组件隔离测试覆盖弹窗、挂载会话和窄窗口交互，仍需真实内核、独立窗口与移动端验收。
- [ ] **多设备迁移、同步与恢复验收**：在独立测试工作空间验证升级迁移、离线并发复习、同一实体冲突、旧设备继续写入后的 `LegacyDiverged`、同步中断重试、笔记本关闭与重开、投影重建和损坏快照回退，记录卡片身份、排期、历史及旧备份保持情况。已有自动化回归需要补充真实同步链路验证。
- [ ] **Anki 导入实包验收**：用包含不同卡片类型、媒体、SM-2 排期和长期历史的实际 `.apkg` 样本验证字段落地、模板降级报告、重复导入、取消和中断恢复，核对导入前后的卡片映射、到期时间及历史数量。
- [ ] **公开声明与示例核对**：核验 `registerFlashcardType` 等卡源扩展与 `petal` 的公开声明，补齐注册、渲染、答案检查、卸载回退及 `plugin-sample` 示例；已有七个 `flashcard-review-*` 生命周期事件继续保持声明一致。
- [ ] **发布文档核对**：实现细节维护在本设计文档及对应契约、类型注释中；用户指南和对外 API 文档按明确的发布范围单独维护。
- [ ] **议题验收核对**：按第 10.8 节逐项核对实际通过的场景和已知限制，功能完成与验收通过分别确认，不根据议题关闭状态直接勾选。

### 11.4 安全清理

以下能力依赖设备确认与安全压缩协议，不作为 v2 切换的前置条件。

- [ ] **跨设备安全压缩协议**：设计设备确认水位、设备退出或长期离线的处理、墓碑传播和失败恢复，再实现旧分段、快照及墓碑回收，防止旧设备或恢复的工作空间重新引入已清除记录。
- [ ] **彻底清除卡片元数据与历史**：在安全压缩协议具备后提供范围预览、明确确认和可恢复的执行流程，覆盖权威分段、快照、SQLite 投影及同步副本；现有软删除继续保留历史。
- [ ] **旧格式迁移备份手动清理**：确认所有参与设备已越过迁移水位后，再提供 `.deck`、`.cards`、旧日志和相关块属性的显式清理入口；此前继续完整保留备份。

### 11.5 渐进学习的后续范围

渐进式阅读区分用于理解的阅读材料与用于检验回忆的问答卡片，并保留阅读位置和来源上下文。当前采用的子集与薄弱练习只补齐会话交互，完整阅读调度及以下能力暂缓实现。

- **完整渐进式阅读**：优先复用文档、块和现有编辑器，以“继续阅读”“稍后再读”“完成阅读”组织交互；独立保存来源、稳定块位置、阅读状态、下次回访和最后访问时间，摘录关联原文，需要记忆的内容再制卡。完成阅读保留原文与卡片。先解决块移动、删除、合并后的定位恢复、同步冲突和既有加密笔记本准入边界，再考虑自动增长阅读间隔；PDF 页码和音视频时间点分别扩展，不能只增加书签就视为完整阅读调度。
- **持久化最终演练**：跨会话或跨日继续练习还需独立集合、进入和退出规则、恢复及统计语义。当前当轮薄弱练习不自动累计此类待办，也不改变现有 FSRS 学习步骤。
- **自动负荷分摊与批量改期**：需要试算预览、原子写入、冲突检测、撤销及多设备一致性，不用多次单卡改期拼接可能部分失败的自动操作。
- **全库严格优先级与今日队列覆盖**：严格全序需要可同步的顺序与并发合并规则，不能直接替换现有语义优先级分组；将未到期卡临时混入正常队列需要独立的日内覆盖及恢复语义，当前临时练习通过强化会话完成。
- **引用网络扩散复习**：现有块引用提供关系基础，自动选择相邻内容仍需扩散边界、去重、访问校验、性能限制和用户可理解的退出条件。
