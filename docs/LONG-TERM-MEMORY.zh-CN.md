# 长期记忆

[English](LONG-TERM-MEMORY.md)

## 功能范围

本文规定思源工作空间级长期记忆的设计目标、存储方式和维护规则。下文规定实现行为，待决事项在对应章节中单独列出，不代表当前已发布版本均提供这些接口或默认配置。

长期记忆保存有来源的用户背景、偏好、项目事实、约定和决定原因，供当前及未来需要上下文理解的 AI 功能共同使用，减少跨任务、跨会话的重复解释。各功能使用同一份记忆，不各自维护用户画像。记忆不替代原笔记、文档搜索、会话历史或人工规则。

首版采用 Markdown 正式记录、系统生成的精简概览和按需文件搜索，不增加 SQLite、向量检索、知识图谱或外部记忆服务，也不把全部记录常驻内存。数百至千条记录仅用于初步规模评估，不作为硬上限或性能承诺。抽取、判断和概览生成仍有模型调用成本，应使用用户配置的 AI 服务并提供可见的调用范围与失败状态。

功能面向桌面端、浏览器端和移动端，由内核提供统一的读写与检索能力。文件搜索不能依赖用户系统安装 `grep`、`find` 或其他命令行工具。新功能接入时显式选择是否使用或维护记忆，不在模型协议适配层向每个请求无条件注入记忆。

保存与采用分开：尽量保留有依据的信息，不以主观的「长期价值」判断或固定条数直接截掉有效内容；来源、主体或含义尚不确定的内容可以保留为候选，但不得按已确认事实使用。上下文预算限制本次读取和注入量，不反向删除正式记录。未确认的自动候选遵循下文明确规定的 30 天清理策略。

## 用户交互

### 记住、纠正与忘记

人工智能设置中的管理按钮仅在长期记忆开启时显示。首次渲染及后续配置变更均按当前已保存的开关状态更新，桌面端、浏览器端与移动端共用。关闭记忆会隐藏该入口，但不删除已有记录；重新开启后可再次管理。这项界面规则不改变正式记录 API。

用户可以明确要求记住、纠正或忘记某项信息。系统检索相关记录并核对主体、适用范围和时间后执行对应操作，说明实际结果；未确认写入成功时不得回复已经记住。存在多个可能目标时，需要消除歧义，不能批量覆盖所有相近记录。

| 操作 | 目标行为 |
|---|---|
| 记住新信息 | 建立正式记录，保留原始依据及适用范围 |
| 再次表达同一信息 | 保留原记录 ID，补充来源及再次确认时间，不重复创建 |
| 补充已有信息 | 更新对应记录，保留原有条件及未被推翻的内容 |
| 纠正或改变要求 | 区分原记录错误与事实随时间变化，保存必要的替代关系和有效时间 |
| 暂停使用 | 保留记录但不参与后续检索结果和概览注入 |
| 忘记 | 停止使用内容，并持久保存防止旧版本重新生效所需的最小撤回信息 |

管理界面将只读概览放在输入框和使用模型整理操作上方，处理中仅显示转圈，报错统一显示在右上角消息区，不显示行内任务状态或完成文案；显示时隐藏文件名及技术性记录引用，不改变保存的原文，不展示逐条记录、内部元数据、搜索、分页、刷新或取消控件。概览统一归纳用户背景、偏好和常用上下文，不是可编辑的事实来源。强类型记录接口仍保留查看、明确纠正、启用、停用和撤回能力，并继续执行来源、修订和授权检查。

记忆已启用、工作空间可写且已配置处理模型时，管理器按当前界面语言显示有效概览，翻译期间显示加载状态，失败时保留原文。翻译使用已配置的记忆模型供应商，仅发送概览，不额外发送记录或来源依据，可能产生费用。内核重新读取有效概览，确认与请求中的原文逐字一致后才发送。显示译文不写回正式记录或概览原文。进程内有界缓存（32 条、每条 16000 字节、30 分钟有效期）和相同请求合并减少重复处理；最多并发两次请求，超时为 60 秒。新概览生成时指定界面语言，并在进程内记录语言以避免同轮重复翻译。进程重启后，已有概览语言可能未知并需要再次调用模型，缓存不跨重启保留。前端不会自动重试失败的付费翻译请求。关闭窗口会停止等待，但不保证撤销已开始的模型请求。

记忆摘要输入框也支持直接明确地请求忘记某条具体记忆。此路径仅限不带来源 ID 的手动文本，自动采集和引用的来源材料不构成撤回授权；忘记请求应单独提交，不与新增内容混合。手动请求复用现有关键词提取调用，同时区分记住、忘记或含糊意图，缺失、不合法或含糊的意图均拒绝执行。提案动作必须与意图一致：忘记请求不能转成新增或否定事实保存，空提案或未匹配目标时报告目标错误，不当作成功。完整可用候选集不超过 100 条时，全部候选参与匹配，避免中文词形或别名导致漏召回；更大集合保留有界关键词检索及扫描不完整检查。候选检索受预算约束（100 条记录、96 KB），仍执行来源、范围和加密内容访问检查。仅忘记提案使用严格的 `targetIDs` 响应，由服务端从已验证快照回填记录正文和元数据，不要求模型复制这些字段；未知字段、格式错误、重复 ID 或快照外目标均被拒绝。模型提出撤回后，使用所选模型结合完整请求和固定候选集，额外批量核验语义，要求识别明确且唯一的目标。明显引用、记录身份或正文不符、未知 ID，以及混合保存与忘记的批次由程序拒绝；含糊、否定、转述、假设或清空全部的请求由语义核验保守拒绝，但不能承诺模型绝不误判。每项获准操作使用修订检查和持久撤回标记，多目标请求不保证整批原子性：后续操作失败不撤销已成功撤回，明确重试复用准备结果，不重复已成功目标。额外核验可能产生模型费用，公开记录接口契约不变。

忘记目标选择和独立核验的候选上下文仅包含记录 ID、类型、主体、范围和完整正文。来源证据、修订及操作元数据保留在服务端已验证快照中，不为匹配重复发送。请求仍受 96 KB 预算约束，不能为满足预算静默截断正文或丢弃候选；来源校验和写入修订检查继续生效。

当前明确指令优先于旧偏好。例如全局偏好为简短回答，某个教程要求详细步骤时，该任务采用具体要求，不因此改写全局偏好。一次任务的临时要求不得自动升级为全局长期规则。

记忆摘要右上角的更多菜单提供红色垃圾桶操作“删除所有记忆并关闭记忆功能”，执行前要求确认。内核先持久保存关闭状态并使旧写入失效，再撤回全部当前记录，删除当前 `MEMORY.md` 和旧版 `USER.md` 概览。原笔记、对话、冲突、历史备份和撤回标记继续保留，不调用模型。清理失败仍保持关闭，返回部分完成结果供明确重试；未知格式和损坏记录会保留，不能静默丢弃。该菜单操作不依赖模型理解输入框中的清空全部请求，后者仍被拒绝。

### 自动整理与来源范围

自动整理处理允许范围内的笔记与使用过程。笔记读取保留 `.sy` 的块身份、类型、层级、引用、行内语义和属性视图的类型化值，避免仅凭扁平文本误判主体或关系。收藏、引用的第三人文章不能自动当作用户的观点；模型生成的内容也不能仅因出现在对话中就视为用户确认。

普通对话或任务告一段落后，可以批量提取候选并与已有记忆核对。整理需要合并连续修改、支持取消和重试，不在每次击键或每句话后重新生成全部文件。某条候选校验失败时保留可诊断的失败状态，不应丢弃同批其他有效记录。

长期记忆初始关闭，总开关统一控制记忆使用和自动整理；自动模型任务还要求有效的记忆模型配置。笔记来源默认包含全部非加密笔记本，包括新建笔记本；加密笔记本即使已解锁也排除。不设置笔记本允许列表，旧配置中的 `memory.sources`、`memory.autoMaintain` 和 `memory.conversations` 值被忽略。启用不触发全库旧笔记扫描；明确记住、纠正和忘记仍可独立使用。仅在普通任务成功提交或来源修改提交后安排整理，合并受影响来源，不处理每次编辑。同一来源版本与配置的自动请求复用已排队或正在运行的任务，不重复创建批次。关闭长期记忆阻止新自动任务入队，并使运行任务在提交前重新校验许可。具体扫描、调用预算可调整，但不能改变这些边界。

会话采集由长期记忆总开关统一控制。开启后只处理后续成功提交轮次中的用户消息，不采集 AI 回复、不扫描历史；来源保留会话与消息身份及原文版本。涉及加密或不可访问引用的消息不进入全局记忆。消息被编辑、删除或长期记忆关闭后，使用前重新校验来源；会话删除不等同于擦除历史快照，明确忘记仍使用撤回机制。

### 自动候选管理

自动候选维护在启动时和此后每小时执行，仅在长期记忆开启且工作空间可写时运行，不额外调用模型。只有未明确确认、来源全部为块或会话的 `candidate` 记录参与。重复候选必须具有相同事实、有效期、替代关系和完整来源依据。连续 30 天没有实质更新的自动候选会被清理；仅以新操作 ID 重复提交相同提案不会重新计时。手动提交、未知来源、明确确认以及生效、待核对、停用、已替代的记录均排除。清理采用不含正文和证据的目标记录撤回标记，阻止旧 ID 恢复及旧操作重放，但允许原来源产生新的候选。标记持久保留，因此清理限制候选正文增长，不承诺元数据零增长。

后续普通模型提案只有在事实未变、原来源在本轮归并前已经有效，且当前证据逐字支持正文时，才能激活已有候选；提交时仍复核修订、来源与权限。仅重复出现、同轮来源改版、修改含义或提出替代关系均不自动激活。完全相同而未指定 ID 的提案复用已有候选，避免新增重复记录。

### 模型与推理强度配置

用户应能按与智能体相同的选择策略，为长期记忆处理选择模型及推理强度，不能写死供应商、模型或强度，也不要求与当前对话使用相同配置。复用现有 AI 供应商与模型配置，提供独立的长期记忆处理选择；切换当前对话模型不应隐式更改后台记忆处理的选择。

该配置用于候选抽取、检索词生成、重复或变化判断以及概览生成等模型调用；文件遍历、文本匹配、元数据校验和持久化仍由程序完成，不因此产生模型请求。界面必须说明模型调用范围及成本。可用模型使用受支持协议时，提供与智能体一致的选项：默认（空字符串）、none、low、medium、high、xhigh、max；不按模型名称猜测能力或据此禁用自定义模型。这些是可选档位，不保证每个供应商接受每个值；共用协议适配器透传或转换所选强度，供应商失败必须明确反馈。

所选模型被删除、停用、不可访问或配置不兼容时，应保留已有记忆并报告受影响任务，不能静默切换供应商或清空记录。无需模型参与的已有记忆读取和明确目标的停用、撤回，不应依赖生成服务恢复。

共享 AI 设置提供统一控制记忆使用、自动整理和后续用户消息采集的总开关、独立模型引用和推理强度。模型初始未选择，模型任务开始前要求用户明确选择；推理强度初始采用供应商和模型默认值，不显式覆盖强度。不能复用会静默选中其他已启用模型的既有配置协调逻辑。校验所选模型引用，拒绝不可用模型。非默认强度必须属于该协议开放的标准枚举，拒绝非法值，不按模型名称猜测能力。任务捕获配置代次，在模型请求前和提交前复核；配置变化使旧任务取消，等待明确重试。首版不自动回退供应商或模型。

### 可选的决策模型预筛选

现有决策模型开关已启用且所选配置完整时，自动整理可在记忆模型生成搜索词之前，先调用已配置的决策服务（`Decision.ActiveOptions` / `EvaluateDecision`）。不新增凭据、模型选择或记忆专用开关。这是发往所选 TypeSafe/OpenAI 兼容决策端点的远程请求，不是本地关键词分类器，也不是免费服务。它可能省去后续记忆模型调用，但会为符合条件的任务增加一次决策请求；实际费用和延迟取决于所配置的服务与工作负载。

首版范围刻意收窄：仅对没有请求文本、且来源全部为块或笔记的自动任务预筛选。手动记住、纠正、忘记操作，所有会话或用户来源，以及已有来源绑定的修复任务均绕过预筛选。当前会话没有可信的显式意图元数据，因此统一绕过会话，无需写死多语言表达的关键词列表。程序完整分页扫描有效、候选和待核对记录的来源绑定；同一文档存在任何绑定，或扫描失败、不完整，均保留原流程。接受跳过结果之前再次检查来源绑定。

决策模型接收完整且受预算约束的原生来源证据，不截断正文，并将其视为不可信数据，跨语言选择 `process`、`skip` 或 `unknown`。只有完全空白或纯社交寒暄，且任何部分均不含事实、指令、请求、纠正、否定、条件或其他潜在有用信息时，才允许判断为 `skip`。实现还要求跳过概率与置信度均不低于 0.99。该阈值是偏保守的启发式规则，不保证语义判断绝对准确；歧义、不支持的输出、低置信度与 `unknown` 均保留原流程。不持久化跳过标记或撤回信息，后续编辑或显式整理仍可再次处理来源。跳过不写记忆记录或概览、不调用记忆模型，也不声称记忆或投影已更新；已有概览待更新状态保持不变。

决策模型未启用、未配置、返回格式错误、服务故障或决策超时，均降级到原有的所选记忆模型流程。当前实现将单次决策限制为两秒，不重试。连续三次故障触发一分钟的内存冷却，仅暂时绕过决策请求，记忆整理照常进行。成功响应清除连续故障计数，配置或工作空间变化重置冷却，旧请求完成后不能污染新配置代次。这些时长属于实现策略，不是供应商服务保证。缓存只保存配置散列与计数，不保存来源正文或凭据。

任务取消、配置或工作空间变化、来源撤权以及来源修订变化，必须中止过期任务，而不是降级。请求发出前及预筛选返回后均执行既有检查，覆盖跳过与恢复原流程的分支。所选记忆模型仍须有效；模型不可用不能伪装为更新成功。来源复核、待核对状态转换、删除、撤回标记和忘记操作独立于本优化。测试仅使用模拟服务，不代表真实供应商的判断质量或实测节省效果。

### 可见的限制与失败

未找到记忆、尚未完成搜索、来源不可访问、记录损坏、写入冲突和模型服务失败必须区分。文件搜索失败不能解释为没有相关记忆，模型生成失败也不能清空已有记录。必要时继续当前任务并说明缺少可靠记忆，不反复打断用户要求确认低价值信息。

共享 AI 设置在桌面、浏览器和移动端提供同一精简管理入口。内部接口保留计数及完整性字段，管理界面不显示数量。完整数量只统计当前可用的生效记录，不包含候选、待复核、停用记录，也不受概览摘要选取数量限制。计数不完整时不能当作零条。任务完成不等于新增可用记忆；管理器不显示完成、零条记忆或其他行内状态提示，只刷新概览，并将报错放到右上角消息区。既有采纳规则保持不变：模型建议的新生效记录必须有引用来源的逐字依据，不确定或改写的建议不会因为界面简化而自动生效。

## 数据与存储

### 文件布局与归属

以下路径均相对于思源用户工作空间，不是源代码仓库目录。

```text
data/storage/ai/
├── AGENTS.md
└── memos/
    ├── MEMORY.md
    ├── legacy-projections/
    │   ├── USER-<sha256>.md
    │   └── MEMORY-<sha256>.md
    ├── records/
    │   └── <思源ID>.md
    ├── withdrawals/
    │   └── <思源ID>.md
    └── conflicts/
        └── <记录ID>/
            └── <sha256>.md
```

`AGENTS.md` 是现有的人工规则文件，由用户维护，不由记忆整理流程擅自改写。`memos/` 及其中的记忆文件是本设计拟新增的内容。`records/` 是正式记录的唯一来源；文件名使用程序生成的思源 ID，正文或标题变化不改变 ID。

`MEMORY.md` 是唯一生效的系统生成概览，统一归纳稳定的用户背景与偏好、常用上下文、约定及记录线索。它从正式记录派生，按相关性和上下文预算控制长度，不是全部记忆的拼接或完整目录。它持久保存在 `memos/` 下，随正常数据同步，必要时可重建。总体可用记忆数量独立统计有效记录，不受概览摘要范围限制。

正式记录和概览复用现有数据快照与同步机制，仍受用户同步设置及忽略规则影响。首版没有独立数据库或持久检索索引，不预先创建 `temp/ai/memos/`；后续如需缓存，该路径只保存可重建数据，清理缓存不能丢失记忆、纠正或撤回决定。

模型与推理强度选择属于 AI 配置，不写入 `records/` 或概览。应遵循现有配置持久化与导出规则，复用模型引用而不在记忆文件中复制供应商凭证；记忆文件同步不代表接收设备自动拥有同一模型配置或服务访问权限。

### 正式记录

每条记录采用 UTF-8 Markdown、严格校验的 YAML 前置元数据及可读正文。第 1 版元数据包括 `schema`、`id`、`kind`、`subject`、`scope`、`state`、`sources`、`created`、`updated` 和操作身份；确认时间、有效时间及替代关系单独保存。来源包含稳定身份、来源版本及允许保留的依据，不能只有可变标题。使用受限的强类型结构，拒绝重复或未知字段、别名、自定义标签、错误类型与身份以及未知格式版本，不使用任意 YAML 对象或隐式时间转换。具体约束如下：

| 信息 | 约束 |
|---|---|
| 身份与格式版本 | 唯一记录 ID 与显式格式版本；文件名和内部身份必须一致 |
| 主体与范围 | 区分用户、第三人和项目；范围可关联工作空间、笔记本、文档或明确项目，不能仅用标题判断身份 |
| 内容与类型 | 保存背景、偏好、事实或决定及其条件；不能把计划弱化或升级为已发生事实 |
| 来源 | 保留块、文档或会话身份、必要的证据摘录及来源版本线索；记录多个独立依据 |
| 时间 | 区分记录时间、来源创建/更新时间、再次确认时间和事实有效时间；未知的事件时间保持未知 |
| 状态 | 区分候选、可用、待核对、停用、已替代和已撤回等语义；只有满足使用条件的记录可注入 |
| 修订与替代 | 支持陈旧写入校验、修改原因和新旧内容关系；不能以文件修改时间直接判定事实新旧 |

正文应保留对后续判断必要的主体、动作、状态、条件和否定信息。关联来源不等于来源可信；程序能校验引用存在性和访问范围，内容判断仍需模型及必要的用户核对。元数据解析必须拒绝歧义结构，不执行任意标签、表达式或正文中的指令。

记录状态采用 `candidate`、`active`、`review`、`disabled` 和 `superseded`。只有范围和依据当前有效、没有撤回或冲突的 `active` 记录可使用。不确定抽取保留为候选；依据变化或无法验证时转为待核对，不继续断言。重复确认保留 ID 并补充来源；替代关系区分纠错与随时间变化。服务计算完整文件字节的 SHA-256 修订用于比较后交换（CAS），模型不能指定该修订；概览的语义指纹与字节修订分别处理。

撤回信息是 `withdrawals/` 下的正式持久状态，采用带版本的 Markdown 元数据，包含程序生成的 ID、目标记录 ID、来源身份与版本抑制引用、操作 ID 及时间，不包含被忘记的正文或证据摘录。先保存撤回标记，再删除目标记录；清理失败时标记立即阻止使用，并报告物理清理未完成。首版不自动到期清理标记，也不将其当缓存。旧任务、同步版本及自动重新抽取在提交前必须检查这些引用。来源版本变化本身不构成恢复被忘记事实的授权；匹配不明确时继续排除并等待核对，用户之后明确要求重新记住才可建立新的授权关系。跨设备保护仅在撤回状态到达该设备后生效，离线客户端不能承诺立即全局擦除。

撤回格式 2 保存与目标共享来源的其他既有不同记录的 ID 和事实 SHA-256 摘要。摘要覆盖类型、主体、范围和去除首尾空白的正文，不保存这些记录的正文或证据。只有记录 ID 与事实摘要同时匹配时才保留使用资格，不改写其文件；事实变化不能沿用此例外。目标 ID 及完全重复的事实仍被排除，从已撤回来源重新抽取的新记录仍须获得新的明确授权。快照保护连同标记保留这些例外。不需要保留例外时仍写入格式 1。格式 1 标记继续按原有保守来源限制读取，授权摘要保持不变；升级不能重建缺失的例外，也不能自动恢复已排除的事实。处理格式 2 标记的所有设备都必须支持该格式；不支持的读取端必须报告错误，不能忽略撤回。

新撤回标记还保存被忘记记录各次操作身份的 SHA-256 摘要。先前明确记住请求的延迟重试不构成新授权，删除或快照保护后仍须拒绝。没有此可选摘要字段的旧标记继续可读；已有显式用户来源身份仍阻止原创建请求重放，但旧写入端已经丢弃的操作历史不能凭空恢复。

### 概览的一致性

每份概览记录格式版本及与该概览相关的完整可用来源集合指纹，涵盖记录 ID、语义内容、范围、状态、有效期及撤回和冲突适用性。新增、修改与删除都使指纹失效；仅补充来源确认且不改变含义或可用性时才可免于重新生成。使用前核对指纹及当前访问范围，全局生成的概览不能泄漏调用方范围之外的内容。同步带来的旧概览不得覆盖正式记录，也不能因文件时间较新就直接采用。

概览生成基于一个已核对的记录快照。写入时如果相关记录已变化，应丢弃该次过期生成结果并重新安排；只生成并原子替换统一的 `MEMORY.md`，生成失败不改变正式记录。概览暂不可用时，可以按需读取有效正式记录；不能为等待概览而恢复已失效的内容。

## 实现与接口

### 模块职责

| 模块 | 职责 |
|---|---|
| 调用方 | 提供当前任务、允许来源及适用范围，选择是否读取或整理记忆 |
| 模型 | 提取有依据的候选、提出检索词、判断重复/补充/变化及生成概览文字 |
| 统一记忆服务 | 校验身份与权限、检索文件、分配 ID、校验修订、提交记录、维护状态并刷新概览 |
| 文件与同步机制 | 可靠保存文件，复用现有快照和传输机制，保留冲突及恢复所需数据 |

模型输出是待校验的操作建议，不直接获得任意文件写入能力。统一服务必须约束目标目录、校验路径与文件身份、防止符号链接越界，并复用现有只读工作空间与访问控制规则。记忆内容不提高原文指令的权限，也不产生执行其他操作的授权。

使用低依赖的 `kernel/memo` 包负责解析、存储、修订、检索和概览校验，由 `kernel/model/ai_memory.go` 编排来源、配置、模型请求及同步通知。共享 AI 设置和管理界面使用强类型内核契约，不直接访问文件系统。读取和列表、搜索、变更建议、任务取消和状态及概览读取须有明确请求、结果与错误契约，包含修订、操作 ID、搜索未完成标识，以及记录已保存和概览待更新的区别。路由和工具名称属于实现细节；新接口遵守 [API 类型契约](API-CONTRACTS.zh-CN.md) 并维护生成声明。这些是拟实现模块与契约，不是已发布 API。

调用方在业务入口选择接入，当前及未来 AI 功能复用同一服务，不在底层模型协议适配器统一注入。标题生成、会话压缩、模型连接测试及记忆维护模型请求不得递归触发记忆采集。

### 写入与更新时机

| 触发事件 | 正式记录处理 | 概览处理 |
|---|---|---|
| 明确要求记住 | 检索并核对候选后新建、合并来源或更新 | 有效内容变化时安排相关概览刷新 |
| 明确纠正或忘记 | 优先提交纠正、失效或撤回状态 | 立即阻止旧概览继续使用，再刷新受影响部分 |
| 普通任务结束 | 在允许范围内批量整理候选并逐条校验 | 合并有意义的内容变化，批量刷新 |
| 原文修改、删除或权限变化 | 核对受影响记录，标记待核对或失效 | 排除失效或不可访问的内容 |
| 同步、快照恢复或文件变化 | 校验格式、修订、冲突和撤回关系 | 核对依据版本，重建或暂停使用过期概览 |
| 仅新增重复来源 | 保留 ID，更新来源及确认时间 | 内容和有效状态未变时不必重新生成文字 |

来源删除不能机械地删除所有相关记忆，也不能继续把不可验证内容当确定事实。多个来源仍能支持的历史事实与仅由已删除来源支持的偏好，需要分别核对。用户明确忘记某项信息时，其撤回意图优先于再次从同一旧来源抽取的候选；用户之后明确要求重新记住时，可以建立新的有效关系。

记录先可靠提交，再派生概览。刷新失败不回滚已成功的纠正或撤回；调用方得到的状态必须区分记录保存成功与概览仍在刷新。重试需要按来源和操作身份去重，不能因超时或进程中断不断新增相同记忆。

内容不变的反复显式确认保留已有证据，不再次追加完整正文，同时保留操作身份并更新确认时间。已授权来源改版时，维护可以按相同来源身份及当前版本匹配已有记录并保留 ID；来源版本归并仍作为候选，等待确认。其他无法访问的来源仍使该记录退出模型处理。原文不变但来源失效时，拒绝激活且不改变修订或状态；应恢复访问或另建明确确认的记录，不静默移除来源。模型调用后重新核验结果的全部来源及概览来源，不只检查本轮新输入。撤回已持久化但物理清理失败时，返回已保存且清理待完成，并继续通知同步。

首版模型提案可附带 `validFrom`、`validUntil` 和 `supersedes`。有效期仅接受所引来源中明确出现的 RFC3339 时间，并校验起止顺序；自然语言时间仍保留在正文或候选中，不推测日期。替代提案只新建候选并关联当前已核验的同主体、类型和范围记录，提交时复核目标修订，不自动停用旧记录或激活新记录，也不声称完成跨文件原子替代。明确纠正仍可更新原记录 ID。

### 经校验的维护流程

保存提案会收到明确的 `AllowedScopes` 列表，并且只读取这些可写范围内的候选。示例使用有效的枚举字面值，模型须选择一个完全匹配的允许范围，不能将说明文字或主体名称作为范围。手动忘记仍可跨范围检索已核验目标。提交时继续严格检查范围、来源与修订。全部提案被拒绝时，报告实际失败原因，并跳过不必要的概览请求；只有至少一条结果确实已保存时才显示部分保存提示，旧任务没有保存结果时也不能声称部分成功。

全部操作仅因范围检查失败而在写入前被拒绝时，丢弃该批预备提案，供用户明确重试时重新生成，不自动重发。已有保存结果的批次继续保留预备操作和操作身份，避免重复提交成功写入。

1. 捕获操作 ID、来源身份和版本、允许范围及配置代次；来源权限由内核确认，不能信任调用方传入的 ID
2. 使用原始文本及可选的模型关键词组检索相关记录，按需读取候选正文
3. 要求所选模型返回有依据的新建、增强、修订、替代或无操作等结构化建议，而不是文件系统指令
4. 提交前重新校验来源版本、权限、取消状态、配置、撤回及预期记录修订
5. 在短写锁内分配 ID、执行 CAS 与操作去重，逐条原子保存合法记录；模型请求期间不持锁
6. 通知正常数据同步，使受影响概览失效，再基于固定可用快照异步生成；逐条报告失败，不把批次描述为单个事务

当前进程在内存中有界保存任务身份、建议集合及逐条结果。重复请求复用正在运行的任务或已完成结果。建议已生成后，明确重试沿用原建议及稳定的条目身份，仅尝试未提交项，不重新付费生成另一组建议。已完成条目的操作身份随结果记录或撤回标记持久保存，保留先前身份，不能只覆盖为最新操作。来源或记录修订冲突要求重读和重新判断，不能强制覆盖。进程中断不回滚已保存记录，也不承诺跨重启精确续跑整个批次。

### 检索与使用

1. 根据当前任务确定主体、范围、访问权限和可用状态，过滤不能使用的记录
2. 使用当前文本及模型提出的多组关键词、名称或别名搜索文件，按需读取命中的候选，不将全部正文常驻内存
3. 模型结合候选正文与来源判断相关性；写入前额外判断是否为同一事实、补充信息或时序变化
4. 检索结果不足时扩大关键词或范围，但不越过权限边界；记录搜索未完成或未找到的状态
5. 在上下文预算内返回相关记忆和来源，必要时回看原文；无可靠记忆时按当前请求处理，不编造背景

首版使用跨平台文件遍历和文本匹配，不把语义检索当作已有能力。短语变化、别名及中文分词可能造成漏检，「未找到」不能直接成为新建重复记录的充分依据。无法确定是否重复时，可保留待核对候选，不冒险合并不同主体或不同项目。

一次搜索可流式扫描文件，避免全量常驻；这仍有磁盘读取成本。必须对并发、取消、返回大小和模型调用预算作控制，不能通过静默截断记录或扩大外部传输来维持响应速度。摘要、标题等不需要长期背景的请求可以不查询记忆。

### 并发与安全

更新必须携带调用方读取时的修订，并在锁或等效保护下原子保存。过期写入返回冲突，保留当前内容与待处理建议，不强制覆盖。单文件原子写入不保证离线设备间的一致性，概览版本校验与同步冲突处理须分别验证。

模型输出、笔记引用和记忆正文均作为数据处理。当前请求与人工规则继续遵守现有优先级；读取记忆不得绕过权限、扩大工具访问或接受来自收集材料的操作指令。日志与诊断默认记录状态、标识和耗时，不复制完整记忆或敏感原文。

普通全局 Markdown 记录不能保存从加密笔记本提取的明文内容。首版若没有保持原加密边界的记忆存储与生命周期设计，就必须排除此类来源，并在界面说明限制；仅检查笔记本当前解锁不足以允许写入全局文件。加密笔记本的认证读取、锁定清理及恢复要求见 [加密笔记本](ENCRYPTED-NOTEBOOK.zh-CN.md)。

## 兼容与恢复

统一概览使用派生格式版本 2。旧版格式 1 的 `USER.md` 和 `MEMORY.md` 迁移时不能被当作正式记录：先将原始字节保全到按内容寻址的 `legacy-projections/` 备份，仅纳入指纹与当前可用记录匹配的内容，原子写入统一的 `MEMORY.md` 后再停用 `USER.md`。失效、损坏或不支持的内容保留供恢复，但不注入上下文，也不反向重建事实。迁移失败或中断可以重试；旧设备重新带回的文件必须重新验证，不能使失效摘要重新可用或恢复已撤回记忆。只读访问不写入迁移文件，旧格式概览在可以迁移前按失效处理。迁移备份不是第二份生效概览，同步或快照恢复不得静默删除或覆盖这些备份。

`data/storage/ai/AGENTS.md` 已有独立的读取、修订和兼容迁移机制，本功能不迁移或覆盖该文件。旧 `data/ai/AGENTS.md` 的兼容处理继续遵循现有实现。会话压缩与会话历史也保持各自生命周期，不能将删除一个会话等同于已经删除所有派生记忆。

正式记录必须带格式版本。未知格式、损坏元数据或不完整写入不能触发清空、静默重建或全库重新抽取；保留原文件，隔离该条的使用并报告错误，其他合法记录继续可用。重建只针对派生概览和可选缓存，不能用概览反向替换正式记录。

记忆 Markdown 必须显式处理冲突，既有 `.sy` 冲突文档逻辑不能证明已覆盖这些文件。替换前保留双方可恢复版本，未解决记录不参与检索和概览；收到的记录激活前先核对撤回标记，不按设备时间或最后写入决定事实。同步概览是可重建派生数据：比较指纹，跳过已经适用的生成，仅在需要时本地重建。启用跨设备自动维护前必须验证这一集成。

`conflicts/<记录ID>/<sha256>.md` 持久保存未解决冲突的完整版本，不是可清理缓存；存在冲突目录的记录不能用于记忆上下文。恢复或同步若将删除或覆盖未解决冲突证据，会明确报错并阻止该批应用，而不是把删除证据解释为冲突已经解决。撤回标记在替换和删除前保存等价的新身份副本，使当前已知撤回意图不随旧快照回退。

批次去重属于本地任务状态，不作为记忆同步。服务不生成或读取 `operations/<operationSHA>.md`，已有操作文件也不再接受额外的同步覆盖或删除保护。本版本保留这些废弃文件，不自动删除用户数据，也不另建一批备份文件；它们不影响当前任务执行、记忆检索和概览生成。所有同步设备升级并重启内核后，用户可自行清理废弃的 `operations` 目录；旧客户端仍可能生成或依赖这些文件。不要删除 `records` 或 `withdrawals`。

忘记必须使记录、概览和检索结果一致失效，并考虑旧设备、重试、抽取及历史恢复。历史快照可能仍含旧正文，普通忘记不等于擦除所有备份。应用内恢复快照时保留当前已知撤回标记，在暴露恢复的记忆前核对，不能自动重新激活匹配记录。绕过该流程整体恢复旧工作空间可能连较新标记也一并移除，不在此保证范围内；须说明限制，不能承诺无条件防复活。

管理器自动查询当前任务，结束后更新总体结果。临时查询失败只退避重查同一任务，不自动重新提交付费模型请求。关闭管理器释放界面轮询资源，不取消后台任务；任务继续受既有三分钟超时限制。进程重启或内存任务被淘汰后，不自动恢复模型任务。旧任务不可用时如实报告；用户之后明确发起的整理作为新任务，重新核对当前配置、来源、正式记录及撤回状态，不伪造旧批次的恢复结果，也不自动重放旧批次。取消仍是后台生命周期能力：提交前已确认的取消阻止该次提交，成功写入后的取消不能撤销写入。概览更新失败保持正式记录不变。

可调整的产品细节包括批量操作、外部编辑器支持及基于测量的扫描、上下文和调用预算。以上安全默认值、记录语义、撤回保留和失败处理是实现要求，不能交由模型临时决定。

## 验证范围

文档中的行为需要通过实现后的测试验证，不能由文件格式或现有同步能力推断已经成立。至少覆盖以下场景：

| 场景 | 验证要求 |
|---|---|
| 跨会话使用 | 用户不重复偏好时，新任务仍能在正确范围采用，并可追溯来源 |
| 同义重复与补充 | 不同表述保留同一 ID；新增来源不重复建档，不误合并不同主体 |
| 事实与时间 | 计划、已完成、否定及条件不失真；修改时间不冒充事件发生时间 |
| 项目隔离 | 同一用户不同项目的相反要求可共存；临时要求不污染全局 |
| 纠正与忘记 | 下次调用不使用旧概览；重复抽取、失败重试和旧设备同步不静默复活 |
| 来源变化 | 原文修改、删除、权限变化及多来源支持触发正确核对 |
| 并发与恢复 | 多个 AI 请求、离线设备、概览生成中断及文件损坏不造成静默覆盖或丢失 |
| 用户控制与隐私 | 自动整理关闭后不继续提交；只读、加密及受限来源不泄漏 |
| 模型配置 | 使用用户选择的模型和与智能体共用的推理选择策略；切换对话模型不隐式改变记忆配置；不支持参数及失效配置有明确反馈，且保留已有记忆 |
| 跨平台搜索 | 桌面、浏览器及移动端使用同一内核语义，无外部搜索命令依赖 |
| 成本与性能 | 测量不同规模下的搜索耗时、读取量、漏检、模型调用量及取消恢复行为 |

效果评估应比较真实任务中重复解释和人工纠正的次数，同时观察不相关记忆误用、漏检及成本。已有小规模抽取、问答及表示方式对照，只能提供设计线索，不能证明自动形成记忆、长期个性化或同步遗忘已经有效。首版不以记录条数或阅读题满分作为完成标准。

实现按存储和明确管理、文件检索和模型建议、概览校验和调用方接入、可选自动整理及同步恢复验证推进。每阶段在开放依赖行为前通过确定性的失败与并发测试。使用临时工作空间样例覆盖严格解析、路径越界、CAS、操作重试、调用期间来源和配置变化、新增导致概览失效、撤回后清理失败、Markdown 同步冲突及恢复保留。模型驱动的任务评估在这些测试后进行，分别报告准确性、误采用、漏检、延迟和成本；既有基准结果不能替代生命周期验证。
