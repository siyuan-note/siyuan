# 独立 Markdown 编辑器设计

对应 [#21115](https://github.com/siyuan-note/siyuan/issues/21115)。编辑器随思源分发，直接处理用户授权的外部 Markdown 文件，不导入工作空间，不使用 `.sy`、工作空间同步或加密笔记本存储。外部原文件及恢复草稿不因此获得笔记本加密保护。

## 模块与启动

- `app/src/markdown/`：共享编辑页面、Vditor 适配、会话状态机、资源策略与原生传输协议
- `app/electron/markdown/`：桌面启动路由、独立沙箱窗口、授权文件句柄、文件事务及恢复存储
- `app/webpack.markdown.js`、`app/scripts/markdown-assets.js`：独立页面和离线资源清单；产物位于 `stage/build/markdown/`
- Android 的 `MarkdownActivity`、iOS 的 `MarkdownSceneDelegate` 和 HarmonyOS 的 `MarkdownAbility`：原生独立容器，在工作空间启动链之前路由外部 Markdown 请求

主工作空间中的入口只发送“新建独立编辑容器”请求，不向编辑页面传递工作空间权限。轻量入口不启动 Go 内核；已运行的工作空间和内核继续按原有生命周期运行。整个应用退出时须等待所有轻量会话的保存与恢复保护；进入后台只尽力保存已提交输入，不弹出退出确认。

桌面仅有独立 Markdown 窗口时，普通启动请求仍可进入工作空间主界面。该请求到达后才读取工作空间及崩溃记录，复用首次使用、崩溃恢复、目录丢失及正常启动分支，不修改初始启动快照。重复请求复用已有的工作空间选择页或内核启动窗口，Markdown 窗口继续独立编辑。

Android 的编辑容器位于 `:markdown` 进程，使用独立 WebView 数据目录，工作空间的 `Mobile.exit()` 不终止该进程。iOS 和 HarmonyOS 的 Go 内核仍是应用进程内链接，独立 scene 或 UIAbility 不能隔离整个进程的异常终止；正常关闭工作空间会延迟进程退出。HarmonyOS 的延迟请求绑定工作空间代次，重开工作空间后取消旧请求，显式全局退出仍须经过全部会话保护。异常终止只能恢复之前已经确认落盘的草稿。操作系统强制停止整个应用也不能靠退出回调保证最后一次输入被保存。

Vditor 锁定为 `4.0.1`，关闭其自带缓存。离线清单使用仓库内的 Lute 产物，包含引用定义 title 的往返修复，对应 Lute 源码提交 `a824e50c`。解析器更新应保留引用定义 title 在三种编辑模式中的往返语义；产物从 Lute 源码构建，不直接编辑压缩产物，也不改用 Vditor 包内尚未修复的解析器。

## 配置与恢复目录

目录均由宿主决定，桥接不接受配置路径。编辑偏好包括模式、主题和字号；文件树的显示状态、宽度及展开目录使用独立的带版本存储，不调用普通工作空间配置接口。桌面 `tree-view.json` 使用版本 1，默认宽度 240，允许 180–480；每根最多记忆 256 个展开目录、最近 16 个根，未知版本或损坏内容保留并报告错误。

| 平台 | 独立命名空间 | 系统备份策略 |
| --- | --- | --- |
| 桌面 | 应用配置根目录下的 `markdown/`，默认 `~/.config/siyuan/markdown/` | 不接入思源同步；操作系统备份可能包含该目录 |
| Android | `Context.getExternalFilesDir(null)/home/.config/siyuan/markdown/` | 在旧版备份、云备份及设备传输规则中排除此目录 |
| iOS | `Documents/home/.config/siyuan/markdown/` | 设置 `isExcludedFromBackup` |
| HarmonyOS | `Context.filesDir/workspaces/home/.config/siyuan/markdown/` | 在应用备份规则中排除 |

移动端沿用各自现有的模拟 `home`，无需启动内核即可定位配置目录。所有平台的草稿与写入恢复记录位于 `markdown/recovery/`，编辑偏好与文件树状态位于 `markdown/` 根目录，保持各原生平台的存储格式。

偏好和恢复记录都有格式版本。恢复记录校验内容、记录目标代次及编辑版本，安全更新后才确认持久化；未知版本和损坏记录保留原件，不以默认值覆盖。恢复容量为 256 MiB、最多 1,024 条记录；不按时间自动淘汰未保存内容，容量不足时反馈错误。用户可以显式恢复或清理非活跃会话的草稿，不能清理仍被其他编辑容器使用的恢复记录。

## 文件和事务契约

页面只持有不透明授权句柄、展示名称和能力声明。宿主保留真实路径、URI、书签和授权标志。各宿主在整个应用范围登记目标身份；能够确认的路径别名、文件标识或提供方文档标识必须共用占用记录。

另存为依次完成目标选择、原子预留、保存意图持久化、首次写入、结果核验、绑定持久化及内存绑定切换。首次写入使用当前目标代次加一；旧目标直到新绑定确定后才释放。成功写入但尚未完成绑定的目标仍保持占用。结果不确定时只核验原操作，不重复提交，也不释放目标供其他会话使用。

候选目标已经确定失败且不再存在待确认事务时，用户仍可保存或重试原目标；候选错误和基线不能套用到原目标。桌面 POSIX 保存须在替换核验及父目录同步成功后确认本地耐久性；目录同步失败保留不确定事务和恢复正文，核验重试只补充确认，不重新写入正文。Windows 使用既有替换流程。

每次写入绑定不可变的会话、目标代次、编辑版本和操作编号。宿主串行执行文件操作，对重复编号验证请求摘要；完成回执采用有界缓存，已过期操作不得重新执行。更新绑定的持久化结果不确定时，不能把迟到的旧代次草稿确认成已保存；确认已持久化的新绑定后，应将迟到草稿映射到新代次。

外部重载另外绑定编辑版本和请求序号。输入意图立即使在途重载失效，不等到延迟的 Markdown 快照生成；存在待提交输入时不发起自动重载。读取期间发生编辑、切换、关闭或更新的重载请求后，旧结果不能修改正文、基线或已保存版本。程序化重载和未编辑的模式切换都不能触发自动写回。

桌面文件监听对目标的文件系统事件合并通知，由当前会话与已接受的版本比较；宿主打开时的保存基线不能用于过滤外部变化。外部连续保存、恢复到初始内容以及删除操作均进入会话核验，自身写入和内容未变化的通知由会话忽略。

只读文件允许编辑副本及另存为，不能显示为已写回原文件。临时授权有独立提示。成功保存统一显示“已保存到文件”，云端同步由对应网盘管理；未确认云端同步不表示文件保存失败。保存确认和 `durability` 契约保持不变。

## 文件树与同容器切换

打开 `A.md` 时，以它所在目录作为默认导航根，呈现真实文件夹与 `.md`、`.markdown` 文件。目录按需展开，文件夹在前、名称按不区分大小写且识别数字的自然顺序排列。左上角使用独立文件面板按钮显示开关状态与提示，文件名也可切换面板；桌面为可调整宽度的侧栏，移动端为抽屉。空目录不显示占位子行，加载及读取失败提示仍保留。移动平台的单文件授权不足以枚举同目录时，提示用户选择所在目录；取消授权不影响当前正文编辑。

用户展开、折叠目录时采用与文档面板相同的 200 毫秒高度过渡，缓动为 `cubic-bezier(0, 0, .2, 1)`；首次加载、后台刷新及系统要求减少动态效果时不播放。展开先等首批列表就绪，等待期间保持折叠布局；发起后又折叠、切换根或关闭页面时，旧结果不能重新展开目录。动画仅组合已挂载行和虚拟占位空间，退场快照不可交互；快速反向操作、滚动、布局变化及冻结会结束现有过渡，不扩大大目录的渲染范围。

单击树中文件在当前编辑容器中切换。发起候选读取前，页面先取得当前文档已提交输入并等待私有草稿持久化确认；确认失败或仍在组词时不开始读取。共享协议 `tree-prepare-open` 读取并占用候选目标；确认候选可打开后，页面按已有退出保护完成原文件保存、草稿保留、另存为或取消。候选读取期间进入后台，可以在确认草稿水位后应答，并尽力保存原文件，不依赖慢速提供方读取完成。旧会话完成释放后，`tree-commit-open` 只执行幂等的内存绑定切换；取消使用 `tree-cancel-open` 释放候选。提交回执丢失时可重试同一票据或通过 `bootstrap` 确认当前会话。移动桥接的绑定确认等待 5 秒、快照等待 30 秒后报告超时，普通文件写入不因此重试。无法确认新绑定时保持正文冻结，仅允许重试确认，不恢复已经释放的旧编辑会话。候选读取与占用参与退出和容器销毁清理，写入结果未定的旧目标不能释放。

原生容器和页面来源保持固定，文档切换创建新会话，保留旧会话已经确认持久化的恢复内容。旧会话的桥接、状态上报、图片 token 和异步结果不能进入新文档。树内切换保留原根；另存为仍在根内时也保留，保存到根外后跟随新父目录。“更多 - 打开文件夹”只重选导航根，不切换或替换正文，也不因为当前文件位于所选根外而立即改变用户的选择。

树根及节点只向页面提供宿主签发的不透明标识。宿主保存真实路径、URI 或书签，检查授权范围、文件身份、目录链接和循环；树授权不包含图片或任意文件读取权。目录列表与根节点登记均限制为 10,000 项，最大深度为 64，超限明确报告并提示选择较小目录，不返回无提示的截断结果。展开状态使用稳定标识保存；已展开目录通过监听、平台可用的变化通知或重新聚焦时刷新。当前文件删除或撤权时清除其选中状态，可用根目录仍允许导航其他文件。页面按可见范围渲染列表；切换根或目录代次后，旧列表回执不能进入新树。文件树只负责导航，不提供重命名、删除或拖动整理。

## 平台能力与边界

桌面在同目录写临时文件，核验原目标后再替换；新文件使用不覆盖已有目标的创建方式。Windows 使用系统替换接口保留原文件元数据，POSIX 路径保留权限和所有者。摘要、文件身份检查与原子替换都不是跨应用比较并交换，不能宣称排除了所有外部并发写入。

Android 使用 SAF 和实际授权 flags，不申请全盘访问。iOS 使用 UIDocument 和 security-scoped bookmark；只有真实保存 completion 才表示该次保存结束，错误通知本身不是写入完成屏障。HarmonyOS 按 API 18 至目标 API 20 的接口使用文件选择和授权恢复能力。HarmonyOS 桥接传输采用独立的 64 MiB 编码预算，不与原文件的 8 MiB 限额混用；请求指纹基于写入前固定的编码内容。提供方没有条件写入时，使用写前检查、短写循环、截断、关闭结果及写后核验，并保留恢复数据。保存或关闭结果不确定时保留占用。

iOS 和 HarmonyOS 的另存为使用目录选择加文件名，避免导出或保存选择器在应用预留目标之前先写入正文。平台提供方可能改变授权、身份或可用性；失败时需要用户重新选择，不把 URI 或裸 URL 当成长期授权。

## 资源与安全

桌面窗口禁用 Node 集成并启用沙箱和上下文隔离。桥接检查窗口、主 frame、固定页面来源及会话。Android 使用只允许可信主 frame 的 WebMessageListener；iOS 检查 WKScriptMessage 的 frame 和来源；HarmonyOS 向主页面传递专属 WebMessagePort，不注册可被子 frame 直接调用的文件代理。

文件页面直接显示 HTTP、HTTPS 网络图片，协议相对图片地址使用 HTTPS；图片形式的 SVG 徽章也可显示，不执行其中的脚本。网络图片不需要本地目录授权，不转换或下载到工作空间，加载与重定向不修改正文中的原始引用。页面不发送来源地址，网络失败按图片加载失败处理。

文档中的脚本、事件处理器、活动 HTML、iframe、内联 SVG 和动态图表仍不能执行。页面 CSP 仅为图片开放 HTTP、HTTPS；桌面请求过滤和 iOS 内容规则同时按图片类型限制网络访问，Android 与 HarmonyOS 依靠 CSP 限定联网子资源，原生拦截继续保护本地虚拟来源。外部网页及邮件链接必须由用户触发，并由宿主校验协议后打开。必要脚本、样式、字体和图标全部随页面打包。

移动端的单文件授权不推导出所在目录授权。文档及文件树导航授权均不隐式授予图片访问权；相对图片需要独立目录或文件授权，解析结果是会话限定的只读地址。解析和读取均须核验授权范围及身份，失效 token 不能重新解析为另一个文件。正文序列化恢复原引用，临时地址不得写回文件。插入图片先选择并成功保存资源，再插入引用；另存为不隐式复制资源或修改链接。

桌面图片目录授权同时绑定用户选择路径、规范路径和目录身份；解析资源、实际读取及读取完成时复核。目录在同路径被替换、移动或选择路径的符号链接改指后，旧授权及已签发 token 失效，需要重新授权。

## 界面、限额与调度

窗口名称为 SiYuan，标题行显示文件面板按钮、文件名、撤销、重做和“更多”入口。正文不另设格式工具栏，撤销和重做复用 Vditor 当前模式的记录并同步可用状态，输入法组词和会话冻结时禁用。文件、图片、目录授权、恢复及外观操作位于“更多”菜单，各入口使用对应功能图标；编辑模式和外观统一使用侧向展开的二级菜单，外观内收纳主题与字号的勾选子菜单，空间不足时向另一侧展开，并支持逐级键盘导航与关闭。标题的 H1–H6 标识与标题首行共用实际行高，保持垂直对齐。底部显示保存状态；冲突和失败操作只在对应状态出现。桌面窗口复用思源的无边框配置，Windows 使用原生窗口按钮覆盖层，macOS 保留系统交通灯，Linux 提供标题行窗口按钮；标题行空白区域可拖动窗口，关闭操作仍经过保存与草稿保护。样式复用思源控件、菜单及主题变量，不加载工作空间菜单运行时。全新且从未编辑的空白页关闭时不弹保存确认，也不生成空恢复记录；实际编辑后删空、初始非空副本和已恢复草稿仍受退出保护。

Vditor 外壳、正文和代码高亮主题分别配置：初始化和切换时须同步三者，暗色使用 `dark` 正文与 `github-dark` 高亮，浅色使用 `light` 正文与 `github` 高亮。仅设置外壳主题不能覆盖默认浅色正文。三种编辑模式均遵守显式外观设置及跟随系统的规则，主题切换不得触发写回。

桌面标题栏高度为 32 px，底栏常态高度为 24 px；冲突和错误操作可按内容展开。触屏标题栏为 48 px，保留至少 44 px 的按钮点击区域；图标按钮的可见背景内缩至 32 px，图标与背景居中，原生触摸反馈不覆盖外围的透明点击区域。Windows 原生按钮覆盖层随实际标题栏高度与页面缩放同步。开发者工具沿用思源的快捷键与停靠规则：Windows、Linux 使用 `Ctrl+Shift+I`，macOS 使用 `Cmd+Alt+I`；按键重复不触发切换，也不增加界面按钮。快捷键识别与切换能力由启动层注入，独立 Markdown 模块不直接依赖工作空间窗口模块。

文件树失焦和聚焦只更新现有行的焦点样式，不重建鼠标按下的行，避免首击丢失。Electron 文件切换通过视图快照保留旧画面，在新编辑器的首个源码预览及首层目录就绪后交换画面，禁用默认淡入淡出；不支持 View Transition 的 WebView 使用直接替换路径。切换模式时立即建立该模式的撤销基线，紧接着输入的首笔修改也能撤销。

原文件读写上限为 **8 MiB**，按最终 UTF-8 字节计数，包括 BOM 和换行转换；富文本与预览阈值独立为 **256 KiB**。较大文件直接以源码文本框打开并关闭全文预览，继续支持编辑、自动保存、另存为、冲突检测及恢复。源码输入和粘贴在目标事件处理前关闭大内容预览；富文本的大段粘贴先切源码再插入，常规编辑跨过阈值后也转入源码。外部重载先确定模式再设置正文，避免先渲染大内容；删减到阈值以内后可重新选择富文本模式。自动降级只改变当前文档的实际模式，不写入通用编辑偏好；切换到较小文档时采用用户偏好，仅主动选择的模式会被记忆。菜单勾选反映当前实际模式，主题和字号调整不能把降级状态替换为偏好模式。私有恢复正文保留独立 **16 MiB** 预算，超过文件预算的恢复草稿仍可复制或删减，降到文件预算以内后才能写回。超出文件预算时保留原文件并明确报告错误。

Vditor 的 undo/input 快照延迟为 250 ms；适配层在最后一次输入后 300 ms 通知会话，复用 Vditor 已生成的内容，连续输入最多等待 1,000 ms 提交一次已完成的编辑快照。会话通知后的自动保存延迟为 250 ms，进入输入法组词或收到新输入意图时取消待触发保存。关闭、手动保存及另存为直接取得最新已提交内容。输入意图立即使界面离开“已保存”状态，草稿版本仍只在真正落盘后确认。

输入意图结束、超限输入被拒绝或取消文件操作解除冻结后，按当前脏版本和可写状态重新调度自动保存；无可用历史时触发重做快捷键等不改变正文的操作，也不能永久取消已有修改的保存。移动文件抽屉展开时，遮罩后的正文与恢复面板设为 `inert`；收起后按冻结状态恢复。

富文本转换、撤销快照和全文序列化的开销随语法密度增加，因此富文本与预览采用独立于文件大小的阈值。8 MiB 文件预算约束源码、桥接、哈希和持久化的全文副本，恢复预算为其保留余量。256 KiB 阈值兼顾常见教程、说明文档与全文富文本转换开销，密集代码块或表格在阈值以内仍可能停顿，阈值不代表任意语法都流畅。调整富文本范围需同时评估解析、撤销、序列化及草稿写入。
