# 技能管理

[English](SKILL-MANAGER.md)

在设置 - 人工智能的技能分组中打开工作空间技能，即可管理当前工作空间 `data/storage/ai/agent/skills/<目录>/SKILL.md` 中的技能。来自 `~/.agents/skills` 的外部技能保留在相邻的只读列表中，可以逐个启用。

## 管理文件

搜索文件列表，选择 `SKILL.md` 或技能附带的 `.md` 文件，即可编辑 Markdown 源码。可编辑的源码文件必须采用有效的 UTF-8 编码，且不超过 8 MiB。保存时直接写回所选路径，不转换为思源文档，也不重新生成 YAML 前置元数据。编辑器保留统一的 CRLF 换行格式；编辑混合换行的文件后，换行符会统一为 LF。未修改文件或放弃更改时保留原文。放弃未保存的更改前需要确认。

新建技能会创建包含 `SKILL.md` 的目录。在技能内部，可以新建 Markdown 文件和文件夹，在当前父目录内重命名文件或文件夹，以及删除 Markdown 文件或文件夹。技能根目录中的 `SKILL.md` 不能单独重命名或删除；如需移除技能，应删除整个技能目录。重命名技能目录不会修改前置元数据中独立的 `name` 字段。

其他资源文件会显示在列表中，但不能在管理界面内单独编辑、重命名或删除。本地桌面端可以打开文件位置，再使用其他应用管理这些资源。删除文件夹也会删除其中的全部资源，包括管理界面无法编辑的文件，且无法通过技能管理撤销。

移动端通过底部抽屉展示技能管理。选择文件后进入编辑页面，返回列表时保留列表滚动位置。

## 文件标识与并发修改

操作通过相对于工作空间技能目录的路径定位文件。前置元数据中的 `name` 不作为文件标识：名称可以不同于目录名，重名也不会使文件在管理列表中隐藏。现有技能发现和优先级规则保持不变。

读取文件或文件夹会返回修订号。更新、重命名或删除已有项目时必须提交该修订号；如果项目已经变化，操作会被拒绝。发生冲突时，磁盘上的当前内容保持不变；请保留编辑草稿，重新加载项目后再决定如何合并更改。管理界面不提供强制覆盖操作。

管理接口拒绝经过符号链接的路径、技能目录之外的路径以及存在歧义的 Windows 名称。这不会改变智能体现有的链接技能加载能力。

## HTTP API

`POST /api/ai/agent/manageSkills` 使用标准 API 响应结构，要求调用者已通过身份验证、具有管理员权限，且工作空间不处于只读状态。请求包含 `action`，并根据操作提供 `path`、`target`、`content` 和 `revision`。路径使用 `/` 分隔，相对于 `data/storage/ai/agent/skills`。

| 操作 | 行为 |
| --- | --- |
| `list` | 通过 `entries` 返回文件树，每项包含 `path`、`isDir` 和 `editable` |
| `read` | 返回项目的 `revision`，可编辑的 Markdown 文件另返回原始 `content` |
| `create` | 新建顶层技能目录及其 `SKILL.md` |
| `mkdir` | 在技能内部新建文件夹 |
| `write` | 写入技能内部的 Markdown 文件；已有文件必须提供当前 `revision`，新文件使用空修订号 |
| `move` | 在同一父目录内将项目重命名为 `target`，并提供当前 `revision` |
| `remove` | 删除项目，并提供当前 `revision` |

根目录中的 `SKILL.md`、非 Markdown 文件、符号链接以及文件夹删除遵循前述限制。修订号不匹配或操作无效时返回错误，不修改目标项目。现有按名称操作的技能 API 保留兼容，管理客户端应通过此接口使用相对路径。
