# 手动快照接口

这些接口使用 POST，要求管理员权限，并受只读模式限制。请求和响应类型由 `kernel/apicontract` 生成，同时同步到 petal。

## 创建快照

`/api/repo/createSnapshot` 接受 JSON 对象，例如 `{}` 或 `{"memo":"发布前备份"}`。`memo` 可以省略或为空，清理不可见字符和首尾空白后为空时统一使用 `Create manually`。数字、布尔值和 `null` 不作为备注接受。

成功返回 `{"code":0,"msg":"","data":{"id":"快照 ID","created":true}}`。没有数据变化时返回已有快照的 ID，`created` 为 `false`，不改写已有备注。CLI 和 MCP 同样区分新建与无变化。

## 预检查

`/api/repo/checkSnapshot` 不要求请求体，成功返回 `{"code":0,"msg":"","data":{"changed":true}}`。检查前等待编辑事务落盘，然后比较路径、大小和修改时间，遵循快照的忽略规则与尚未下载资源的逻辑存在状态。检查不创建快照、不下载资源、不写入或校验分块，也不进行损坏引用的云端恢复；读取错误返回失败，不作为无变化处理。

预检查不是完整性校验，也不锁定随后创建的结果。用户填写备注期间自动同步可能已保存相同数据，因此提交时仍须处理 `created:false`。界面仅在有变化时打开备注窗口，创建失败或提交时无变化会保留窗口及输入。

## 修改本地备注

`/api/repo/setSnapshotMemo` 接受 `{"id":"完整的 40 位十六进制快照 ID","memo":"新的备注"}`，成功返回 `{"code":0,"msg":"","data":null}`。备注清理和默认值与创建接口一致。

只更新已存在的本地索引备注，保留 ID、创建时间和文件列表，不生成快照、不主动上传，也不保证更新已上传的云端副本或其他设备。后续上传和下载仍沿用原有索引传输行为。该操作不改变快照格式、加密数据或恢复密钥。
